第 1 章 · 共同语言

把前端词汇翻译成 Java

你已经会 HTTP、JSON、Git 与包管理；本章只补 Java 服务端最容易错位的词：构建时依赖、运行时类路径、保留在字节码里的类型、并行请求、浏览器专属的 CORS，以及订单字段怎样安全穿过 JSON。

预计学习一段完整专注时间 前置：无 交互演示 2 个
  • 把 package.json、模块解析、事件循环和 fetch 的经验翻译为 Maven、classpath、线程池和 Java HTTP 客户端；
  • 能为教学订单选择安全的 id、金额和 DTO JSON 表达；
  • 能用四行描述一次从浏览器到数据的请求，并指出超时应在哪一层观察。

1.1 这门课补哪条缺口

问题：前端工程师已会把请求发出去，却常把服务端看成一个黑盒。这里要补的不是另一套 HTTP，而是请求进入 Java 后由谁执行、数据在哪一层变形、错误在哪一层停止。

符号或约定：本课的共同对象叫“教学订单”；字段从 Course.data.order 读取。前端与后端的“对应”用于建立心智模型，不表示两种运行时完全相同。

package.jsonMaven 的 pom.xml 声明依赖；下载后的构件进入本地仓库。
模块解析JVM 在 classpath 上找 class 与 jar。
事件循环服务端常用线程池，让多个请求并行占用工作线程。
fetch浏览器 fetch 受 CORS；Java 作为客户端发 HTTP 不受它约束。

基准算例：教学订单的 userId、库存、金额、超时和线程池参数均由课程数据提供；本章不另造一套业务数字。

易错：把“会发请求”当成“理解服务端”

请求的连接、读取、业务、数据库等待可能发生在不同位置；前端看到的一个超时，未必能说明是哪一层慢。

避坑：先翻译，再背名词

遇到陌生 Java 词，先问它是构建、运行时查找、并发执行、传输，还是数据契约的一部分。

可操作对象：用本章末尾的“四行订单”作为以后读 Controller、Service、Mapper 时的定位卡片。

1.2 pom 与本地仓库

问题：Java 项目怎样声明并取得第三方库？符号或约定：pom.xml 是 Maven 项目描述；坐标通常由组、构件与版本标识，本地仓库缓存下载的 jar。

基准算例：教学订单所在项目的 JDK 版本由 Course.data.order.jdk 给出；构建工具应使用与项目约定一致的 JDK。

易错：把 pom 当成运行时加载器，或把本地仓库误认为应提交进代码仓库的依赖目录。避坑：依赖声明放进 pom，让 Maven 解析传递依赖；具体插件、菜单与版本边界以 Maven 和所用 IDE 的文档原文为准。

可操作对象：打开一个 Maven 工程时，先确认 pom、依赖树和实际执行 Maven 的 JDK，而不是手工复制 jar。

1.3 classpath

问题：编译通过后，JVM 到哪里找订单类和依赖？符号或约定：classpath 是 class 与 jar 的查找集合；PATH 是操作系统寻找 java、javac 等命令的位置，二者不等价。

基准算例：读取教学订单对象前，包含它的 class 必须位于应用运行时可见的 classpath；数据本身不是靠 PATH 找到的。

易错：把 classpath 当 PATH，或在机器上手写长串 classpath。避坑：日常 Maven/IDE 项目让工具组装运行时 classpath；缺类时先检查依赖是否解析、打包物是否包含，而不是随意改系统环境变量。

可操作对象：当出现“类找不到”时，检查依赖坐标、作用域、运行配置和产物内容这条链。

1.4 类型留在字节码里

问题：TypeScript 与 Java 的类型检查分别什么时候发生？符号或约定：TS 类型主要服务于编译期；Java 的类、方法签名和泛型信息的一部分仍参与字节码与运行时机制，反射和框架会读取其中的元数据。

基准算例：教学订单可有明确的 OrderDto 字段：用户标识、雪花标识、金额分与库存，而不是把所有字段塞进无约束的 Map<String, Object>。

易错：以为 Java 类型也会像 TS 一样完全擦掉。避坑：区分“泛型具体实参常被擦除”和“Java 没有运行时类型信息”这两句话；后一句不成立。

可操作对象：读注解、Controller 参数和 DTO 时，观察框架如何按声明的类把 JSON 绑定成对象。

1.5 主线程与线程池

问题：多个浏览器请求抵达 Java 服务时，为什么可能同时修改共享状态？符号或约定：浏览器页面通常围绕主线程与事件循环组织；传统 Java Web 服务通常从线程池分配工作线程，请求在阻塞 JDBC 或远程调用期间会占着线程。

基准算例：教学订单的核心线程数、最大线程数与队列容量来自课程数据；第一个被拒绝的任务序号由 Course.orderMath.rejectTaskNo() 推导，前提是任务涌入时已有任务持续占用线程。

易错：认为两个请求不会同时改同一块内存。避坑：业务代码优先提交给既有线程池；共享可变数据要设计同步、原子性或让状态交给数据库事务，不能靠到处 new Thread。

可操作对象：排查慢接口时，把“线程池排队、线程被 JDBC 占用、数据库连接等待”分开看。

1.6 CORS 只在浏览器侧

问题：为什么浏览器 fetch 报跨域，而 Java 服务调另一个 HTTP 服务通常不会？符号或约定：CORS 是浏览器执行的同源安全规则；服务端 HTTP 客户端不运行浏览器的同源检查。

基准算例：浏览器请求教学订单接口时，可能需要服务端返回允许来源等响应头；Java 服务再请求下游时，关注的是连接与读取超时，取值来自教学订单数据。

易错：以为服务端调 HTTP 也要处理 CORS。避坑：浏览器到网关或 Controller 的跨域问题，在响应链上配置并检查预检；服务间调用应检查地址、鉴权、证书与超时。软件菜单与具体配置键以框架文档原文为准。

可操作对象：先确认发起者是不是浏览器，再决定是否从 CORS 方向排查。

1.7 两种 id 的 JSON

问题：为什么 Java 的 Long 主键给前端时常写成字符串？符号或约定：JSON number 在 JavaScript 中通常进入 Number；超过安全整数范围的整数不能保证逐位保持。雪花标识在课程数据中专门以文本字段保存。

基准算例：userId 位于安全整数范围内，不能拿它演示精度丢失；snowflakeText 与课程提供的“按 JSON number 解析后文本”可用于观察差异。

易错：拿 userId 演示精度丢失

这个 id 在安全范围内；用它得出“大整数一定会丢”的结论是错误实验。

避坑：对外 JSON 中把雪花 id 放在字符串字段，后端内部仍可按长整型处理。下面切换输出方式，观察客户端是否保持原串。

可操作对象：接口契约、DTO 字段类型和前端解析方式必须一起审查。

id 的 JSON 表达对比切换输出方式
观察要点：① userId 在两种方式下都能保持，因为它在安全范围内，不能当反例。② 雪花 id 作为字符串时保持课程原始文本；作为 JSON number 时会变为课程给出的取整后文本。③ 这不是后端 Long 算错，而是浏览器 Number 的表示边界要求接口把此类 id 作为字符串传输。

1.8 金额用分

问题：为什么订单金额不应以 double 元作为账务运算单位？符号或约定：对货币，业务计算采用最小货币单位的整数；展示时才按元格式化。数据库精确小数与 Java 的精确金额类型仍需按业务约束选择。

基准算例：教学订单同时给出元与分字段。该元值单独可被二进制表示，不能用一次换算“没出错”来证明 double 适合做账；业务计算应以课程提供的分字段为准。

易错：看见一次展示正常，就用 double 元累加、比较或入账。避坑：DTO 清楚标注单位，例如 amountFen；前端只在展示层将分格式化为元，避免同一字段在不同层悄悄改变单位。

可操作对象：审查字段名、JSON 契约、数据库列和计算表达式，确认单位始终可追溯。

1.9 DTO

问题：接口为什么不直接返回数据表的一行或 ORM 实体？符号或约定：DTO（Data Transfer Object）是跨边界的数据契约；实体描述持久化结构，DTO 描述某个接口允许暴露和接收的字段。

基准算例：教学订单对外可含字符串形式的 id、金额分和库存；数据库内部字段、密码、审计字段或关联对象不因“表里有”而自动出现在 DTO。

易错：DTO 直接暴露数据表的行。避坑：让 Controller 的输入输出有专用 DTO，Service 处理业务对象，Mapper/实体处理持久化映射；字段变化时明确做转换，而不是让 JSON 序列化意外穿透层边界。

可操作对象：为每个接口写出输入 DTO、输出 DTO 与不允许出现在响应中的字段清单。

1.10 用四行写下这一次教学订单

问题：面对一次失败请求，怎样不被框架名词淹没？符号或约定：用“浏览器、入口、业务、数据”四行记录请求路径；连接超时与读取超时是不同等待阶段，不能混称一个“网络超时”。

基准算例：教学订单的连接、读取与浏览器等待阈值来自课程数据。它们用于学习分层观察，不是生产配置或性能承诺。

易错：只写“接口慢”，不记录请求在哪一跳等待。避坑：从客户端向数据层逐步定位；超时、日志和追踪标识要与这一跳对应。可操作对象：点击步骤，保存你要优先检查的那一行。

教学订单的四行路径切换步骤
观察要点：① 浏览器侧等待阈值不等于服务端连接或读取阈值。② 进入 Controller 后，请求仍可能在 Service、JDBC 或数据库处等待。③ 切换每一行时，先问该层能看到什么证据，再问是否应在该层修改配置。④ 这四行是排查起点，不替代框架和基础设施文档。

本章避坑清单

  1. 不用 userId 演示 JavaScript 整数精度问题；它处于安全范围。
  2. 雪花 id 的 JSON 输出使用字符串字段，避免转成 number 后少一。
  3. 金额计算使用分的整数值；元只用于展示。
  4. 不要把 classpath 与 PATH 混为一谈，也不要手写一长串依赖路径。
  5. 不要把 Java 类型误认为完全像 TS 一样擦除。
  6. 服务端调用 HTTP 不需要“解决 CORS”；CORS 是浏览器访问服务时的规则。
  7. 不要让 DTO 直接透出数据表行和不应公开字段。
