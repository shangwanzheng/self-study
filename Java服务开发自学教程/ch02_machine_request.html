机器、JDK 与一次请求

把一台机器拆成 CPU、内存、硬盘，把一个 Java 进程拆成堆和栈，再把一次 HTTP 请求按层切开。本章不写生产配置，只让你在终端、IDE 和浏览器三处看到的是同一件事。

预计学习 90 分钟 前置：第 1 章 2D 演示 2 个
  • 说清 CPU、内存、硬盘的分工，以及进程与线程在 Java 服务里的对应物；
  • 分清堆上的对象与栈上的引用，知道对象由 GC 回收而不是手动 free；
  • 把 .java 到机器码的链路（javac、字节码、JVM、JIT）连起来，并说清 JDK 17 为什么是底线；
  • 区分 JAVA_HOME、PATH、CLASSPATH，并能在 IDE 与终端两处都确认是 17；
  • 在 WSL 里跑通 java 与 mvn，并说清 Windows 路径与 WSL 路径为什么不能混用；
  • 按层看一次 HTTP，把连接超时 500 ms、读超时 2000 ms、浏览器超时 3000 ms 三个数对到正确的层；
  • 明白 \(-Xms256m\)、\(-Xmx512m\) 是教学值，不是生产容量规划。

2.1 CPU、内存、硬盘

Java 跑在 JVM 上，JVM 向操作系统要内存和线程。集合、GC、IO 的体感都从这三件硬件来。

问题

一个 Java 服务启动以后，CPU、内存、硬盘各自在做什么？分不清这三者，后面讲堆、讲 IO、讲超时都会变成名词背诵。

符号与约定

  • CPU：执行指令。多核可以同时跑多条线程，单核靠时间片轮转也能“看起来同时”。
  • 内存：放正在用的数据。进程退出或断电即丢失，访问速度比硬盘快几个数量级。
  • 硬盘：放持久数据。程序 jar、日志、数据库文件都在这里。

基准算例

教学订单 Course.data.order.listN = 10000 条。把这 10000 条订单放进内存（一个 List），按 userId 查找是内存操作；如果每次请求都从硬盘读这 10000 条再过滤，慢的不是 Java，而是你把内存活干成了硬盘活。

易错：内存和硬盘一样快
“数据反正都在磁盘上，读一遍也快。” 内存访问是纳秒级，硬盘是毫秒级，差六个数量级。热点数据要放进内存（缓存、内存表），别让每次请求都去碰硬盘。
避坑：每次请求都读盘

配置、字典、热点订单这类数据，启动时加载进内存，运行时只读内存。日志写盘是另一回事——写盘走的是 IO 缓冲，不要和读业务数据混在一起。

可操作对象

在任务管理器（Windows）或 top（WSL）里找一个 Java 进程，看它的 CPU 占用、内存占用。让它处理一个请求，观察 CPU 是否有波动、内存是否增长。这就是后面所有性能讨论的最小观察单位。

2.2 进程与线程

这是前端转 Java 最大的认知差。浏览器里 JS 只有一条主线程，await 让出的是这条线程；Java 里两个请求可以同时跑在两条线程上，同时改同一块内存。

问题

一个 Java 服务怎么同时处理多个请求？为什么两个请求会互相把数据改乱？

符号与约定

  • 进程：操作系统分配资源的单位。一个 java -jar 就是一个进程，有自己的内存空间。
  • 线程：CPU 调度的单位。一个进程里有多个线程，它们共享进程的内存。
  • 主线程：每个 Java 进程有一条 main 线程；服务的请求处理线程来自线程池，不是 main。

基准算例

教学订单 Course.data.order.poolCore = 4、poolMax = 8。Tomcat 用线程池接 HTTP：平时开 4 条工作线程，忙时最多涨到 8 条。两条线程同时处理两个请求，如果都读写同一个 HashMap，就可能互相踩坏。线程池四个数的细节在第 4 章，这里只先建立“请求进池而不是事件循环”这张图。

易错：两个请求不会同时改同一块内存
“我写的是顺序代码，两个请求各跑各的，不会撞。” 两条线程共享进程内存。一个普通的 HashMap、一个 int 计数器，被两条线程同时读写都可能出错。共享可变状态要么加锁，要么用并发容器（第 3、4 章）。
避坑：到处 new Thread

业务代码不要 new Thread().start()。请求处理交给 Tomcat 的线程池，自己要异步时也提交给一个受管理的线程池，否则线程数会失控，连接池和数据库一起被拖垮。

可操作对象

启动一个 Boot 应用，用 jstack <pid> 或 IDEA 的线程面板看它的线程列表。你会看到 main、若干 http-nio-8080-exec-*（Tomcat 工作线程）、GC 相关线程。请求打进来时，工作线程才会出现在调用栈里。

2.3 堆上的对象和栈上的引用

new 出来的对象在堆上，局部变量在栈上。栈上的引用指向堆上的对象。引用没了，对象就等着 GC 回收——不是你 free。

问题

Order order = new Order(); 这一行，order 在哪，对象在哪？方法返回以后，对象还在不在？

符号与约定

  • 堆（heap）：所有 new 出来的对象都放在这里，被所有线程共享。
  • 栈（stack）：每个线程有自己的栈，放局部变量和调用栈帧。栈上的内容是引用（指向堆对象的地址）或基本类型。
  • 可达性：从某条线程的栈出发，沿着引用能走到这个对象，它就是“可达”；没有任何引用能走到它，它就是“不可达”，可被 GC 回收。

基准算例

教学订单 userId = 10001、amountFen = 19950、stock = 8。Order order = new Order(10001L, 19950, 8)：引用 order 在当前方法的栈帧上，Order 对象在堆上。如果又把它 put 进一个 Map<Long,Order>，那么从栈上的 Map 变量也能走到这个对象——多一条引用，对象就多一条“活路”。

易错：对象要手动 free
“像 C 一样，用完对象要手动 free，不然内存泄漏。” Java 没有手动 free。对象不可达后由 GC 自动回收。你需要做的是：别让不用的对象一直被引用（例如放进静态 Map 后忘删），而不是去 free 它。
避坑：循环里用 + 拼接大量字符串

String 不可变，s = s + x 每次都会 new 一个新对象。在 10000 次循环里这么写，会在堆上留下一堆临时 String，等 GC 清理。这和前端里反复创建大数组相似：不是错，但量大时是负担。拼接多时用 StringBuilder。

可操作对象

下面的演示把堆和栈画出来。拖动滑块改变指向教学订单对象的引用数量，看对象从“可达”变成“不可达 · 可被 GC 回收”。

堆上的对象与栈上的引用拖动滑块改变引用数量
观察要点：① 左边是线程的栈帧，三格分别是局部变量 order、List<Order> 订单列表、Map<Long,Order> 索引；右边是堆上的 Order 对象，字段取自教学订单。② 引用数为 0 时，没有箭头连到对象，对象变红，标注“不可达 · 可被 GC 回收”。③ 引用数 ≥ 1 时对象变绿，标注“可达”。④ 注意“引用数”不等于“对象被引用的次数”：同一条引用被多次赋值不会让对象更可达，关键是有没有至少一条引用能走到它。

2.4 从 .java 到机器码

你写的 .java 不会直接被 CPU 执行。中间隔着字节码和 JVM，最后才变成机器码。

问题

一个 .java 文件，从你按下保存到 CPU 真正执行它，经过哪些步骤？为什么 Java 的类型“不会像 TS 一样被擦掉”？

符号与约定

  • javac：编译器，把 .java 编译成 .class 字节码。字节码是平台无关的中间格式。
  • JVM：运行时，加载 .class，先解释执行字节码。
  • JIT（即时编译）：JVM 把热点方法的字节码编译成当前 CPU 的机器码，之后直接跑机器码。解释和编译混合进行。

基准算例

教学订单 Course.data.order.jdk = 17。JDK 17 是 Spring Boot 3 的底线（Boot 3 要求 Java 17+）。你写 Long userId = 10001L，javac 把这个 Long 类型信息写进字节码，运行时 JVM 仍能读到它——这就是“类型留在字节码里”，和 TS 编译后类型被擦掉不同。

易错：Java 类型也会被擦掉
“TS 编译成 JS 后类型就没了，Java 应该也一样。” Java 的类型信息留在字节码里，运行时仍可被检查（反射就是靠它）。泛型有擦除，但类、方法签名、字段类型在字节码里都在。所以类型错了过不了编译，也会在运行时被检查。
避坑：把字节码当机器码

字节码不是机器码，它要靠 JVM 解释或 JIT 编译后才能被 CPU 执行。所以“Java 跨平台”靠的是同一份字节码跑在不同平台的 JVM 上，而不是字节码本身能被 CPU 直接读。

可操作对象

写一个 Hello.java，javac Hello.java 得到 Hello.class，再 java Hello 运行。用 javap -c Hello 能看到字节码。这就是 javac 和 JVM 的分工。

2.5 JAVA_HOME、PATH、CLASSPATH

命令行找不到 java、javac，后面所有练习都起不来。这是中级表的第一道门。

问题

装好 JDK 以后，为什么终端里敲 java 提示“不是内部命令”？PATH 和 CLASSPATH 各解决什么问题？

符号与约定

  • JAVA_HOME：指向 JDK 的根目录，例如 C:\Program Files\Java\jdk-17。它本身不直接生效，是给 PATH 和其它工具引用的。
  • PATH：操作系统找可执行文件的目录列表。把 %JAVA_HOME%\bin 加进去，终端才能找到 java.exe、javac.exe。
  • CLASSPATH：JVM 找类（.class、.jar）的路径列表。它告诉 JVM“去哪些目录找类”，不是告诉操作系统找命令。

基准算例

教学订单的运行环境就是 JDK 17。安装后设 JAVA_HOME，再把 %JAVA_HOME%\bin 追加到 Path。用 Maven 工程时，CLASSPATH 由 Maven 根据依赖组装，不要自己手写一长串 -cp。

易错：PATH 和 CLASSPATH 当成一件事
“都是路径，配一个就行，找不到 java 就改 CLASSPATH。” PATH 是操作系统找命令的，CLASSPATH 是 JVM 找类的。找不到 java 是 PATH 的问题；找到 java 但报 NoClassDefFoundError 才是 CLASSPATH 的问题。两者不要混。
避坑：手写长串 CLASSPATH

用 Maven 或 Gradle 时，构建工具负责把依赖拼成 CLASSPATH。自己手写 -cp a.jar:b.jar:c.jar:... 容易漏、容易错，而且换机器就失效。把找类这件事交给构建工具。

可操作对象

新开一个终端，跑 java -version 和 javac -version，两行都要能打印出版本号。再跑 echo %JAVA_HOME%（PowerShell 用 $env:JAVA_HOME）确认它指向 JDK 根目录。

2.6 两处都要是 17

IDE 里用 17、终端里用 8，是最常见也最难察觉的环境坑。编译能过，运行时报各种奇怪的错误。

问题

IDEA 里 java -version 是 17，打开终端跑 mvn 却报版本不对，为什么？

符号与约定

  • IDE 的 JDK：IDEA 在 Project Structure 里选的 JDK，决定编译和运行时用哪个。
  • 终端的 JDK：由 PATH 里的 JAVA_HOME 决定。IDE 自带的终端也读 PATH。
  • Boot 3 底线：Spring Boot 3 要求 Java 17+，包名也从 javax.* 换成 jakarta.*。

基准算例

教学订单 Course.data.order.jdk = 17。两处都要确认是 17：IDEA 的 Project SDK，和终端 java -version。混用时，IDE 编译出 17 的字节码，终端用 8 的 JVM 跑，会报 UnsupportedClassVersionError。

易错：IDE 与终端 JDK 不一致
“IDEA 里能跑就行，终端报错不管它。” CI、部署、同事拉代码都用终端。IDE 用 17、终端用 8，本地能跑、上线就炸。两处都要确认是 17，并且 IDEA 自带终端也要看到同一套 JDK。
避坑：改完环境变量不新开终端

改了 PATH 或 JAVA_HOME 以后，已经开着的终端不会立刻生效。新开一个终端再验证。这是“明明改了却还是旧版本”最常见的原因。

可操作对象

在 IDEA 的 Terminal 里跑 java -version，再去 Settings → Build → Compiler → Java Compiler 看“Project bytecode version”。两个数字都应是 17。

2.7 WSL 里的 java 与 mvn

在 Windows 上，WSL 足够完成后面的 Linux 命令和部署练习。但 Windows 和 WSL 是两套环境，不要把它们当成同一个。

问题

在 Windows 终端里 java 是 17，进 WSL 跑 mvn 又报找不到 java，为什么？项目放哪编译更快？

符号与约定

  • WSL：Windows 上的 Linux 子系统，有独立的文件系统和环境变量。
  • 两套环境：Windows 的 JAVA_HOME 和 WSL 的 JAVA_HOME 互不影响，要分别配置。
  • 路径前缀：Windows 盘在 WSL 里挂载在 /mnt/d/...；WSL 家目录是 ~/。

基准算例

教学订单在 WSL 里跑：管理员 PowerShell 执行 wsl --install 装 Ubuntu，进 Ubuntu 后 sudo apt update && sudo apt install -y openjdk-17-jdk maven，再 java -version、mvn -v 各确认一次是 17。

易错：Windows 路径和 WSL 路径混用
“项目在 D 盘，WSL 里直接 cd D:\proj 就行。” WSL 里 D 盘是 /mnt/d/proj，反斜杠在 Linux 里是转义符。从 Windows 复制路径粘进 WSL 要先换成正斜杠并加 /mnt 前缀。
避坑：项目放 /mnt/d 编译慢

从 WSL 访问 Windows 盘（/mnt/d）可以，但跨文件系统 IO 慢。把项目拷进 Linux 家目录（~/proj）再 mvn，编译明显更快。

可操作对象

在 WSL 里 java -version、mvn -v 各跑一次，确认和 Windows 终端是两套独立的 JDK。再 cd ~ 看家目录路径，和 /mnt/d 对比。

2.8 看进程、文件和端口

服务部署以后，排障基本是：进程在不在、端口谁占着、日志文件里写了什么。服务器上没有任务管理器和 DevTools，命令就是面板。

问题

“线上接口没反应”，第一步该看什么？是先重启，还是先查进程和端口？

符号与约定

  • 进程：ps -ef | grep java、top 看 Java 进程在不在、CPU 占多少。
  • 端口：ss -lntp | grep 8080 看 8080 是哪个进程在听。
  • 日志：tail -f app.log 跟日志，grep -n Exception app.log 找异常。
  • 本机自测：curl -i http://127.0.0.1:8080/api/users/10001 在服务器上打自己的接口。

基准算例

教学订单的查询接口假设监听 8080。8080 是“某个 Java 进程在听”，不是“这台电脑在听”。进程没了，端口就空了；换个进程重启，端口被新进程接走。

易错：以为 8080 是“电脑在听”
“8080 端口开着，所以服务肯定没问题。” 端口是进程在听。进程挂了端口就释放；也可能是另一个进程占了 8080，你的 Java 根本没起来。要先确认是哪个 PID 在听，再确认这个 PID 是不是你的应用。
避坑：先重启再看日志

“没反应就重启”会把现场破坏掉。正确顺序是：进程在不在 → 端口谁占 → 日志最后几十行 → 本机 curl。四步都看过再决定重启。命令菜单和参数名以所用系统/版本文档为准。

可操作对象

在 WSL 里启动一个会占端口的程序，用 ss -lntp 找到 PID，再用 kill 停掉。把一次 curl 的结果用 > resp.txt 2>&1 写入文件。

2.9 按层看这一次 HTTP

一次请求经过 DNS、TCP、TLS、HTTP、Tomcat、Controller、Service、JDBC、数据库。层分清了，“超时”到底是握手失败还是应用没返回，才分得清。

问题

前端请求超时，后端日志里却没有这条请求，停在哪一层了？三个超时数各管哪一段？

符号与约定

  • 四层模型：链路、IP、TCP/UDP、应用协议。DNS 把域名变 IP，TCP 三次握手后才有字节流，HTTP 跑在 TCP 上。
  • 连接超时：建立 TCP 连接（或建数据库连接）最多等多久。
  • 读超时：连接建好后，等对方返回数据最多等多久。
  • 浏览器超时：前端这一侧给整次请求设的总上限。

基准算例

教学订单有三个超时数，不要混：Course.data.order.connectTimeoutMs = 500（连接超时 500 ms）、Course.data.order.readTimeoutMs = 2000（读超时 2000 ms）、Course.data.order.browserTimeoutMs = 3000（浏览器超时 3000 ms）。它们分别属于不同层，数值也不同。

易错：三个超时混成一个
“超时就是超时，设一个 3000 ms 不就行了。” 连接超时管“能不能连上”，读超时管“连上了等多久”，浏览器超时管“前端这一侧总共等多久”。三者发生在不同层、不同时刻。混成一个，就分不清是握手失败还是应用没返回。
避坑：都叫网络错误

“连接被拒绝”“TLS 握手失败”“HTTP 500”分属不同层：前两个在 TCP/TLS，第三个在应用。先问停在哪一层，再决定查 DNS、查证书还是查应用日志。

可操作对象

下面的演示把一次请求切成几层。点选某一层、拖动“本层耗时”滑块，看这一层的超时阈值和是否超时。

观察要点：① 顶部是请求经过的层，点选高亮当前层。② 右侧读出当前层的超时阈值（取自教学订单的三个数）和含义。③ 拖动“本层耗时”滑块：超过该层阈值时，读出“超时 · 由本层先失败”，并标出是哪一种超时；未超过时显示“未超时”。④ 注意连接超时 500 ms、读超时 2000 ms、浏览器超时 3000 ms 三个数分别落在不同层，换一层阈值就变。

2.10 教学堆大小不是容量规划

本章和后续演示里出现的 -Xms256m -Xmx512m 是教学值，让你在本机跑得动、看得见 GC 行为。它不是生产配置。

问题

-Xms、-Xmx 各是什么？为什么不能拿教学堆大小去跑真实数据量？

符号与约定

  • -Xms：JVM 启动时堆的初始大小。
  • -Xmx：堆能涨到的最大值。超过 -Xmx 会抛 OutOfMemoryError。
  • 教学值：本课统一用 -Xms256m -Xmx512m，目的是在小数据量下让 GC 现象可见，不代表任何生产建议。

基准算例

教学订单 Course.data.order.heapXmsMb = 256、Course.data.order.heapXmxMb = 512。本机用 java -Xms256m -Xmx512m -jar app.jar 跑演示，能清楚看到堆从 256 MB 涨到接近 512 MB 时触发 GC。生产环境的堆大小由数据量、并发、压测决定，和这两个数无关。

易错：拿 -Xmx512m 跑真实数据量
“教程里写 512 m，生产也配 512 m 就行。” 512 MB 在真实业务数据量下很快 OOM。教学值是为了让现象可见，生产堆大小要按数据量、并发和压测结果来定，并且和 GC 策略一起看。
避坑：把教学参数写进生产 Deployment

容器编排文件里的 -Xms -Xmx 要单独按生产环境评估，不要从教程复制。教学值出现在本章是为了讲清概念，不是部署清单。

可操作对象

用 java -Xms256m -Xmx512m -XX:+PrintGC -jar app.jar 启动演示程序，压一点数据，观察 GC 日志里堆的涨落。这就是后面所有 GC 讨论的起点。

本章避坑清单

  1. PATH 与 CLASSPATH 混为一谈：找不到 java 是 PATH 的问题，报 NoClassDefFoundError 才是 CLASSPATH 的问题。两者不要互相改。
  2. IDE 与终端 JDK 不一致：IDE 用 17、终端用 8，本地能跑、上线就炸。两处都要确认是 17。
  3. 改完环境变量不新开终端：已开着的终端不读新值，要先关再开。
  4. 手写长串 CLASSPATH：用 Maven/Gradle 时把找类交给构建工具，别自己拼 -cp。
  5. Windows 路径与 WSL 路径混用：WSL 里 D 盘是 /mnt/d，反斜杠要换正斜杠。
  6. 项目放 /mnt/d 编译慢：跨文件系统 IO 慢，项目拷进 WSL 家目录再编译。
  7. 以为对象要手动 free：Java 没有 free，对象不可达后由 GC 回收；要防的是“不用的对象还被引用”。
  8. 循环里用 + 拼接大量字符串：每次 new 一个临时 String，量大时是负担，用 StringBuilder。
  9. 以为两个请求不会同时改同一块内存：线程共享进程内存，共享可变状态要加锁或用并发容器。
  10. 三个超时混成一个：连接超时 500 ms、读超时 2000 ms、浏览器超时 3000 ms 分属不同层，不要合并。
  11. 先重启再看日志：排障顺序是进程→端口→日志→本机 curl，四步都看过再重启。
  12. 拿 -Xmx512m 跑真实数据量：教学堆大小不是生产配置，生产堆大小靠压测。

本章小结与延伸阅读

  • CPU 执行指令、内存放运行中数据、硬盘放持久数据，三者速度差几个数量级；热点数据要进内存，别让每次请求都碰硬盘。
  • 进程是资源单位，线程是调度单位；Java 服务用线程池同时处理多个请求，两条线程共享内存，共享可变状态要加锁或用并发容器。
  • 对象在堆上，引用在栈上；对象不可达后由 GC 回收，不需要手动 free；要防的是“不用的对象还被引用”。
  • .java 经 javac 成字节码，由 JVM 解释或 JIT 编译成机器码；Java 的类型留在字节码里，运行时仍可被检查。
  • JAVA_HOME 指 JDK 根，PATH 让终端找到命令，CLASSPATH 让 JVM 找到类；用构建工具时 CLASSPATH 由它组装，不要手写。
  • JDK 17 是 Boot 3 底线，IDE 与终端两处都要是 17；改完环境变量要新开终端。
  • Windows 与 WSL 是两套环境，路径不能混用；项目放 WSL 家目录编译更快。
  • 排障顺序是进程→端口→日志→本机 curl，四步都看过再重启。
  • 一次 HTTP 按 DNS→TCP→TLS→HTTP→Tomcat→Controller→Service→JDBC→数据库分层；连接超时 500 ms、读超时 2000 ms、浏览器超时 3000 ms 分属不同层，不要混。
  • -Xms256m -Xmx512m 是教学值，不是生产配置；生产堆大小靠压测。
