第 5 章 · 对象与结构

会在库和索引里碰到的数据结构

用数组、链表、哈希、堆和树读懂 Java 容器与数据库索引：先问查什么，再谈结构。

预计学习 100 分钟前置：第 3 章2D 演示 2 个

5.1 为什么这章不为刷题

数据结构组织数据，算法在其上完成操作。本章只看服务里按位置访问、按键查找、按范围扫描三个问题。

问题：查订单为何不能总扫描 10000 条？约定：复杂度说趋势，不是压测结论。基准算例：教学订单 userId=10001、listN=10000、stock=8。易错：把 10000 条说成必须分布式。避坑：也别为 8 条库存上复杂树。可操作对象：先写清是按位置、按 userId，还是按范围查。

先问数据在哪里

ArrayList、HashMap 是进程内对象；B+ 树通常是数据库页上的索引。都帮助查找，但持久化与代价来源不同。

5.2 数组与链表

问题：取第 8000 条时为什么 ArrayList 常合适？约定：数组下标从 0 开始，演示把经过节点算一步。基准算例：10000 条中数组访问位置 8000 近似 1 步，链表约经过 8001 节点。易错：链表按下标不是 \(O(1)\)。避坑：不要仅因“中间插入快”替换普通业务 ArrayList。可操作对象：ArrayList<Order> 适合分页结果和按位置遍历。

数组与链表的访问步数拖动位置滑块
观察要点：位置越靠后，链表经过的节点越多；数组按下标定位不随位置增长。

5.10 和 HashMap 容量那张图对上

问题：第 3 章的容量 16 与第 13 个键，怎样和桶、冲突相连？约定：容量与负载因子决定扩容时机，桶内键分布决定比较次数。基准算例：\(16\times0.75=12\)，第 13 个不同键触发扩容。易错：扩容不表示第 13 个键必然冲突。避坑：不要把 HashMap 多次扩容当作数据库索引工作方式。可操作对象：预计装约 10000 条时预估初始容量，键保持稳定并正确实现 equals/hashCode。

和第 3 章对上

第 3 章讲 Map 怎么用、何时扩容；本章补上桶为何比较多个键，以及何时需要有序结构或数据库索引。

5.9 用 userId 10001 走一遍查找

问题：同一 userId 在线性表、HashMap 与索引中怎么找？约定：列表无序、哈希只比较目标桶、树已平衡且索引可用。基准算例：10000 条线性最坏约比 10000 次；哈希平均接近常数次；树约十几次节点或页决策。易错：\(O(1)\) 不等于永远一步。避坑：\(O(\log n)\) 也不表示没有磁盘页、缓存或回表。可操作对象：接口以 userId 查询，缓存用 Map，持久化交给 SQL、索引和执行计划。

\[T_{list}(n)=O(n),\quad E[T_{hash}(n)]\approx O(1),\quad T_{tree}(n)=O(\log n)\]

5.8 B+ 树和订单表索引

问题：订单表索引为何常用 B+ 树，不用一个 Java HashMap？约定：B+ 树是面向磁盘页的多叉索引：内部页导航，叶子存键和记录定位信息，叶子相连。基准算例：为 userId=10001 建索引后可逐页定位；库存 8 条临时记录不因此需要复杂树。易错：叶节点并非“不存数据”。避坑：索引列被函数包裹可能无法直接走索引。可操作对象：where user_id = ?，并用执行计划验证。

根页→中间页→叶页 10001→相邻叶页范围扫描

5.7 平衡树

问题：BST 如何不变成长链？约定：AVL 严格控高度差，红黑树以颜色规则近似平衡；理解目标即可，不手写删除修复。基准算例：listN=10000 时 \(\log_2 10000\approx13.3\)，平衡查找是十几级比较。易错：平衡不等于每层完全一样。避坑：不要把 HashMap 的平均 \(O(1)\) 和 TreeMap 的有序 \(O(\log n)\) 混成同一承诺。可操作对象：TreeMap、TreeSet 适合排序与区间。

5.6 二叉树、BST

问题：数据可比较大小时怎样按 userId 找 10001？约定：BST 左键更小、右键更大。基准算例：根 10000，右孩子 10002，查 10001 会依次比较这两个键再抵达目标。易错：普通 BST 不保证平衡。避坑：递增插入会退化为链，查找重新变为 \(O(n)\)。可操作对象：TreeMap<Long,Order> 提供进程内有序键与范围视图。

10000→10002→10001

5.5 堆不是堆内存

问题：PriorityQueue 为什么能快速给出最小任务？约定：二叉堆是数组保存的完全二叉树；JVM 堆是对象内存区域。基准算例：将 8 个库存任务放进小顶堆，取堆顶是 \(O(1)\)，插入或弹出约为 \(O(\log8)\)。易错：堆数组从左到右并不有序。避坑：不要从“对象在 JVM 堆上”推断对象会按优先级排列。可操作对象：PriorityQueue<Task> 适合 Top K、最近到期任务。

两个“堆”

JVM 堆回答对象内存分配；二叉堆回答最值获取，名称相同、层次不同。

5.3 栈和队列，对照线程池队列

问题：为什么线程池等待任务是队列，方法调用又是栈？约定：栈后进先出，队列先进先出。基准算例：库存从 8 扣到 7 的调用会入调用栈；多个请求可排进等待队列。易错：队列不等于无限长。避坑：有界队列、最大线程与拒绝策略共同决定第 109 个任务。可操作对象：普通栈/队列优先用 ArrayDeque，并发场景另选线程安全且有界的队列。

请求 A→请求 B→等待队列→工作线程

5.4 哈希函数与冲突

问题：按 userId 10001 取订单为何通常不用扫 10000 条？约定：演示用 \(bucket=userId\bmod capacity\)，不是 JDK 完整扰动实现。基准算例：\(10001\bmod16=1\)，容量 16、负载因子 0.75 的阈值由 Course.orderMath.hashThreshold() 算出 12。易错：冲突不是函数写错。避坑：equals 为真的对象必须同 hashCode，键参与哈希的字段不可变。可操作对象：Map<Long,Order> byUserId 表达“id → 订单”；第 13 个不同键才触发扩容。

userId 的桶与冲突拖动 userId
观察要点：10001 落进一个桶；同桶键增加比较路径。阈值 12 是扩容边界，不保证每桶一键。

本章避坑清单

  1. 二叉堆不是 JVM 堆内存。
  2. 链表按下标不是 \(O(1)\)。
  3. 冲突正常；相等键必须同 hashCode。
  4. 不要为 8 条库存上复杂树。
  5. 索引列被函数包裹可能走不到原索引。
