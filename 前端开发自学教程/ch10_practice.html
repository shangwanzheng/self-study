第 10 章 · 实战

把教学订单页做完并排错

前面各章已经把教学订单页的路由、请求、状态、样式和构建拆开讲过。本章把它们收成一条能交付的闭环，用同一笔基准算例做交付前检查，并按现象决定下一步打开哪一个面板或文件。

预计学习一段完整专注时间 前置：第 6、7、8、9 章 交互演示 2 个
  • 能按路由、请求、状态、样式、构建说出教学订单页的最小闭环；
  • 能用基准算例做交付前检查，五条齐备才读出可交付；
  • 能按现象选出下一步该看的面板或文件。

10.1 路由、请求、状态、样式、构建的最小闭环

问题：路由、请求、状态、样式、构建都写了，怎样算这一页做完？

约定：最小闭环按顺序能指到文件：路由、请求、状态、样式、构建。路由表描述浏览器里哪条路径打开哪一页，它不是后端 Controller。开发时由开发服务器现给文件；生产打开的是构建后的静态产物。一次只改闭环里的一环，现象才能缩到一个文件。

基准算例：页面在 pageOrigin 上打开 route（/orders）。列表请求发往 apiOrigin 的 apiPath（/api/orders），查询参数使用 page 1 与 size 20。Course.orderMath.pageCount() 为 500。首屏脚本体积 Course.orderMath.firstScreenKb() 为 600，即 \(180+420=600\)；懒加载时路由块 bundleRouteKb 40 不进首屏。两个源的端口是 5173 与 8080，端口不同，不同源。

路由路径 /orders 打开订单页。参数 page、size 留在地址上。
请求/api/orders 带页码与金额分。成功之后才写列表。
状态列表、库存和草稿各有一处事实。筛选不写入草稿键。
样式一页 size 行。局部类名，沿用组件库的表格和表单。
构建开发服务器现给文件。生产是静态产物，入口短缓存。
易错：开发服务器能开，就当作生产能打开

开发服务器能打开 /orders，只说明它在按源文件现给这一页。生产要打开的是构建产物里的同一条路由，入口、哈希资源和缓存头都要一起在场。

避坑：同时改样式、请求和构建

三环一起改，失败时无法知道是类名、响应写回还是旧入口。先选定一环，写下文件名，再看现象是否跟着这一环变化。

可操作对象：在自己的订单页上为五环各写一个文件名。写不出文件名的那一环，就是还没接入闭环的部分。

10.2 核对 id 字符串、金额分、page、size

问题：界面上已经是两位小数，为什么还要打开请求再对一遍？

约定：对外 JSON 里的雪花 id 使用字符串。userIdText 在安全整数以内，只用于说明“它不能当精度反例”。金额的运算和请求体使用整数分，展示时才格式化成元。列表请求始终带上 page 与 size。

基准算例：userIdText 为 10001，Course.orderMath.isSafeId 对它为真。snowflakeText 为 9007199254740993；把它当成 JSON number 再走 jsonNumberRoundTrip，得到 snowflakeRoundedText 9007199254740992，少 1。两者都是字符串，脚本里不写成数字字面量。amountFen 为 19950，yuanText() 得到 199.50。amountYuan 为 199.5，单次转换成二进制看不出误差，仍不用于加减、比较或入账。页数为 \( \lceil 10000/20 \rceil = 500 \)。

{ "id": "9007199254740993", "amountFen": 19950, "page": 1, "size": 20 }
易错：只看 199.50，不核对请求里的 19950

展示文本来自 yuanText()。请求、状态和测试断言要出现 amountFen。用 199.5 的偶然相等代替分的断言，会把一次能显示的数当成可以做账。

避坑：雪花 id 当成 JSON number 会少 1；金额用元的小数做账

响应里的雪花 id 保留引号。金额字段名带上分，展示层单独做格式化。拿 userId 10001 做精度实验，会得出错误结论。

可操作对象：在一条订单响应里同时标出四处：id 两侧的引号、amountFen、page、size。缺任何一处，先补契约再谈样式。

10.3 刷新后草稿还在，筛选条件不在

问题：刷新之后，草稿和筛选条件各还在吗？

约定：内存变量在刷新时清除。草稿放在 localStorage，键名是 storageKey。sessionStorage 随标签页关闭清除。Cookie 使用 cookieName，按域和过期时间保留。筛选条件属于这一次查看，放在路由参数或内存，不写入草稿键。已下载的带哈希脚本可能仍是旧文件，那是另一层缓存。

基准算例：storageKey 为 order.draft，cookieName 为 sid。刷新后草稿仍从 order.draft 读出。筛选用的页码使用地址栏上的 page；课程数据里的 page 是 1，不从草稿里恢复成上一次浏览的页码。

易错：刷新后误以为草稿没了

刷新清掉的是内存里的变量。打开 Application 面板，order.draft 还应在。把“刷新后页面回到第一页”理解成“草稿也被清掉”，会让人去改一个本来还在的键。

避坑：筛选条件写进草稿键

筛选和草稿共用 order.draft 时，恢复草稿会把页码一并带回。测试若共用这个键，会互相污染。草稿只保存编辑中的订单内容。

可操作对象：刷新前在 Application 里找到 order.draft。刷新后确认该键仍在，并确认当前 page 来自路由，不来自这个键。

10.4 一次排错看 Console、Elements、Network 和哪一层超时

问题：页面出错了，下一步看 Console、Elements，还是 Network？

约定：Console 看脚本错误和没有接住的 Promise 拒绝。Elements 看盒模型、被盖住的样式和布局。Network 看 HTTP 状态码、响应里的业务 code，以及资源来自内存缓存还是重新下载。超时按层记录：建立连接、等待读取、浏览器侧放弃等待。先选一个现象，只打开与它对应的那一处。

基准算例：连接 connectTimeoutMs 500，读取 readTimeoutMs 2000，浏览器等待 browserTimeoutMs 3000。三数彼此不同。成功是 HTTP 状态 httpOk 200 且业务 code 为 businessCodeOk 0。HTTP 200 且业务 code 为 businessCodeFail 40001 仍是失败。TLS 失败发生在业务请求记入日志之前。

易错：看见 HTTP 200 就更新列表

状态码 200 只说明 HTTP 这一层完成了。业务 code 为 40001 时列表保持原样，并把失败提示交给拦截器。把浏览器等待 3000 当成读取超时 2000，会改错一层的阈值。

避坑：三个超时混用

连接、读取、浏览器等待各记各的字段。TLS 失败时业务日志里还没有这条请求，不把它记成业务 code。断点先停在订单组件，再决定要不要进入框架源码。

可操作对象：下面按现象切换。读出下一步该看的面板或文件，一次只跟一条。

四种现象，下一步看哪里切换现象
观察要点：① 金额变成一长串小数时，下一步看是否用了元而不是分。② 翻页仍是第一页时，下一步看 effect 依赖和请求参数。③ 刷新后草稿丢失时，下一步看 localStorage 键 storageKey。④ 回滚后还是旧按钮时，下一步看入口 html 的缓存，而不是只删 hash 文件。

10.5 旧响应与重复点击

问题：连点翻页之后，列表为什么会闪回上一页？

约定：每次请求带上发出时的 page。响应回来时，若这个 page 已经不是当前页，丢掉这份响应。进行中的重复点击合并成一次请求；超时后取消，避免取消之后响应仍写回状态。乐观更新先改界面，失败时把界面改回服务端仍持有的值。列表和详情读同一份 stock。

基准算例：地址栏已经是 page 1 时，后到达的第 2 页响应不能覆盖列表。stock 为 8。乐观更新把库存从 8 改到 7，失败时界面回到 8。listN 为 10000，渲染路径上不做整表重排。setTimeout(0) 只是把回调排进下一轮宏任务，不是把两次点击变成并行请求。

易错：旧响应覆盖当前列表，乐观失败后停在 7

先发出的第 2 页若后返回，会把已经回到第 1 页的列表盖掉。界面先显示 7，而服务端库存仍是 8 时，失败分支要把界面写回 8。

避坑：旧响应覆盖新列表；乐观更新失败不回滚

写回列表之前比较响应中的页码和当前页码。列表和详情各存一份 stock 时，回滚只会改到其中一处。超时到达后要取消，否则旧响应仍会回来。

可操作对象：给请求标上发出时的 page。在写回前比对；失败分支把界面库存设回 8，并让详情读到同一个数。

10.6 入口 html 与带 hash 的 js

问题：发布记录已经是新包，按钮却还是旧的，先看哪个文件？

约定：入口 html 短缓存。文件名带内容 hash 的 js 与 css 长缓存。回滚更换入口，让入口指向要恢复的那一版哈希文件。接口数据缓存在页面内存里，和浏览器对 html、js 的 HTTP 缓存分成两条失效策略。

基准算例：htmlMaxAgeSec 为 60，assetMaxAgeSec 为 31536000。主包 bundleMainKb 180 与依赖包 bundleVendorKb 420 之和由 firstScreenKb() 给出，为 600。路由块 bundleRouteKb 为 40，懒加载时不进首屏。入口若使用与哈希资源相同的长缓存，回滚后的 60 秒窗口会变成极长的等待。

易错：入口 html 也做长缓存

哈希文件适合长缓存，因为文件名变了就等于新地址。入口的文件名通常不变。把它缓存成 assetMaxAgeSec 那一档，用户会继续下载旧入口里写明的旧脚本。

避坑：回滚只删 hash 文件，不换入口

入口 html 长缓存导致回滚失效。只删除服务器上的哈希文件，已缓存的入口仍引用旧名字。Network 里要先看文档类型的入口是重新下载还是缓存命中，再看它引用的脚本文件名。

可操作对象：在 Network 中点开入口文档，记下 Cache-Control 和脚本地址。入口仍是旧文档时，先缩短入口缓存并更换入口，再处理哈希文件。

10.7 对照基准算例的检查表

问题：页面能打开之后，怎样判断可以交付？

约定：交付前用 Course.data.order 与 Course.orderMath 逐条核对，不另造一套数。检查表五条都核对过，读数才是可交付：id 是字符串，金额用分，超时分开，缓存分开，列表 key 用订单 id。锁文件和密钥是同一轮交付要一起看的相邻项。

基准算例：雪花 id 用 snowflakeText 的字符串形式。金额用 amountFen 19950，展示用 yuanText() 的 199.50。三个超时分别是 500、2000、3000。入口 60 秒，带哈希的资源 31536000 秒。列表 key 用订单 id，不用下标。锁版本是 semverLocked 1.4.2；锁没交会落到 semverUnlocked 1.5.0。secretName ORDER_API_SECRET 只是名字，不进入包。

易错：测试绿了，却没看用户看得见的金额

绿的测试若不断言 199.50 这个展示，也不断言请求里的 19950，就还没覆盖这一页的契约。组件测试替换请求，不打到真实的 apiOrigin 8080。

避坑：lock 没交；密钥打进包

未提交的锁会让本机和 CI 装到 1.5.0。把 ORDER_API_SECRET 写进构建变量，密钥就进了前端包。五条检查里缺一条，读数应保持“还缺”，而不是改口成可交付。

可操作对象：勾选下面的检查表，读出还缺哪一条。五条都勾上时，读出可交付。

交付前检查表勾选已核对的条目
观察要点：① 五条分别对应 id 字符串、金额分、三个超时、两层缓存、列表 key。② 未勾的条目会出现在「还缺」里。③ 全部勾上时，读数是可交付。④ 勾选只表示已经对照过基准算例，不改课程数据。

易错：按清单同时改三环

清单是索引。选中一条之后，只打开它写明的面板或文件。同时改样式、请求和构建，现象会离开这条索引。

避坑：菜单隐藏当成鉴权

菜单和按钮隐藏是这一页的体验。接口鉴权在服务端。灰度开关同样不能代替鉴权。清单里这一条指向接口的拒绝结果，不是再藏一个按钮。

可操作对象：从当前现象选出清单中的一条，写下章号和要打开的面板。写不出面板，就还停在名词上。章末清单是同一张表的完整版。

10.9 高级条目什么时候才展开

问题：为什么不把每种状态库的参数都写下来？

约定：高级条目标成「碰到再展开」。本章只用同一笔教学订单说明交付时会看见什么：禁令写在这一页，参数表留在第 9 章。需要虚拟列表、分包测量或跨端桥时，再打开对应小节。

基准算例：首屏 600KB，其中主包 180KB、依赖包 420KB，路由块 40KB 不进首屏。listN 为 10000 时只画 viewportRows 12 行，visiblePx() 为 \(12\times 48=576\)，整表 fullListPx() 为 \(10000\times 48=480000\)。帧预算 frameBudgetMs 为 16.7，按 \(1000/60\approx 16.7\) 估算，假设 60Hz，不是设备保证。达到 longTaskMs 50 才叫长任务。qpsTeach 为 50，只表示数量级。

易错：把 50、16.7ms、180KB 写成容量承诺

这三个数用来对照教学订单页会看到什么。没测量就给列表加 memo，首屏仍是 600KB。实验室的一次计时和用户侧的分布也不是同一个数。

避坑：备注当 HTML，source map 公开，开关代替鉴权

订单备注不作为 HTML 插入。source map 不放到公网可下。灰度开关不代替服务端鉴权。这三条是交付禁令。微前端、Worker、指标采样的参数表碰到再展开。

可操作对象：交付前确认四条禁令：备注不当 HTML，source map 不公开，菜单隐藏不是鉴权，包内没有 ORDER_API_SECRET。确认完即停，不在这一页展开第 9 章的参数表。

10.10 本章不引入新的示例数字

问题：练习时能把 19950 换成别的金额吗？

约定：全课数字只有 Course.data.order 与 Course.orderMath。可以引用并写明单位换算，不能改字段，不能另造同名参数，不能把雪花 id 写成 JavaScript 数字字面量。本章两个演示只切换现象和勾选检查项。

基准算例：页数调用 pageCount()，展示金额调用 yuanText()，精度调用 jsonNumberRoundTrip 与 isSafeId，首屏调用 firstScreenKb()，可视高度调用 visiblePx()，整表高度调用 fullListPx()。这些结果已经由大纲给定：500、199.50、少 1 的雪花文本、600、576、480000。本章不给出第二套结果。

易错：手写另一套 page、金额或超时

检查表的对照来自同一笔字段。另写一个金额或另一组超时之后，勾选失去了基准，读出的“可交付”不再对应这门课的订单页。

避坑：把雪花 id 写成数字字面量

脚本里一旦把 snowflakeText 写成数字，值就走上 JSON number 那条路径，少 1，对照本身被破坏。演示和测试都从 Course.data.order 读取字符串。

可操作对象：在请求、状态和测试里搜索 amountFen、snowflakeText、storageKey、htmlMaxAgeSec。每个名字只对应课程数据里的那一个值。

本章避坑清单

这是全课清单。前十五条是交付教学订单页时优先检索的条目，后面把前面各章已经单独走过的坑收在同一张表里。用法见 10.8：先现象，再一条，再面板。

  1. 雪花 id 当成 JSON number 会少 1。snowflakeText 经 jsonNumberRoundTrip 得到 snowflakeRoundedText。userIdText 10001 在安全整数内，不能用来演示精度丢失。
  2. 金额用元的小数做账。运算、请求和断言使用 amountFen 19950，展示用 yuanText() 的 199.50。199.5 单次可表示，仍不用于加减和入账。
  3. 三个超时混用。连接 500、读取 2000、浏览器等待 3000 各记各的字段。
  4. 刷新后误以为草稿没了。内存变量会消失，localStorage 键 order.draft 还在。筛选条件不写进这个键。
  5. setTimeout(0) 当并行。它排进下一轮宏任务。微任务在当前宏任务之后、下一轮宏任务之前。
  6. 漏写 await。随后读到的是 Promise，不是 19950。Promise.all 的拒绝要接住，避免整页空白且没有人处理。
  7. 类型当校验。类型在打包后不存在。as、写成 string 的标注和 .d.ts 都不检查运行时 JSON。关 strict 只是消掉编辑器报错。
  8. 列表 key 用下标。翻页后第一行输入会串页。key 使用订单 id 字符串。
  9. 旧响应覆盖新列表。后返回的旧 page 丢掉。超时后取消，避免旧响应仍写回。重复点击合并成一次请求。
  10. HTTP 200 但业务 code 失败仍更新列表。状态码 200 且 code 为 40001 仍是失败。code 为 0 之后才更新列表。
  11. lock 没交。未锁定会装到 1.5.0，锁定版本是 1.4.2。CI 使用同一份锁。
  12. 密钥打进包。ORDER_API_SECRET 只是名字，不写进构建变量、前端包或仓库。
  13. 乐观更新失败不回滚。库存从 8 改到 7，失败时界面回到 8。列表和详情共用这一份 stock。
  14. 入口 html 长缓存导致回滚失效。入口按 60 秒短缓存，带内容 hash 的 js/css 按 31536000 秒长缓存。回滚更换入口；只删 hash 文件，用户仍拿到旧按钮。
  15. 菜单隐藏当成鉴权。隐藏按钮是体验，接口鉴权在服务端。灰度开关不能代替鉴权。
  16. 页面全局对象是 window。浏览器里没有 process，也没有 JVM。
  17. pageOrigin 与 apiOrigin 端口不同，属于不同源。跨域由浏览器执行。服务端允许凭据之后，才随着请求发送 Cookie。
  18. 控件输入 0 被 || 换成 stock 8。0 是这一次输入，默认回退值才是课程库存。缺省合并用 ??。
  19. 直接改 stock 字段不会重画，用新对象替换。effect 依赖包含 page，否则翻页仍请求第 1 页。请求放在副作用里。离开页面时卸下清理函数。
  20. 接口数据的内存缓存，和 html/js 的 HTTP 缓存，分成两条失效策略。
  21. 渲染路径上不对 10000 行整表重算。超过 16.7ms、达到 50ms 才叫长任务。长列表只画 12 行。没测量就 memo，首屏仍是 600KB。
  22. 订单备注不作为 HTML 插入。source map 不放到公网可下。多 Tab 不把旧 token 写回去。
  23. 开发服务器能开，只说明当前在现给文件。生产打开的是静态产物里的 /orders。一次只改闭环中的一环。
  24. qpsTeach 50、frameBudgetMs 16.7、bundleMainKb 180 是教学数量级，不写成容量承诺或压测结论。
  25. 测试核对用户看得见的 199.50，并核对请求中的 19950。组件测试不打到真实的 8080。缺陷记录写上 page 和订单 id。用例之间不污染 order.draft。
  26. DOMContentLoaded 与 load 是两个事件。TLS 失败时业务日志里还没有这条请求。
  27. 模块顶层不发请求。同一边界只保留一套模块事实。JSON.stringify 会丢掉 Map；JSON 往返会丢掉 undefined。
  28. 对象当字典时，键会收成字符串，还可能撞上原型键。循环绑定用每轮自己的绑定。
  29. 路径别名同时写进 tsconfig 和构建配置。Context 不塞进整份 10000 条。渲染期间不读 offsetHeight。业务页沿用组件库控件，不用全局类名盖住它们。
