第 2 章 · 共同语言

结构化输出

档案助理手里有一句教学报销。程序接不住这句散文，要先收成三个整数：上限 200 元、这单 350 元、超出 150 元。缺一个就停。三个都在，并且超出等于申报减上限，才把这张表交给下一章的 lookupClause。

预计学习 80 分钟 前置：第 1 章 交互演示 2 个
  • 能指出教学句是散文，程序从这句话里读不到 limitYuan、claimedYuan、overYuan。
  • 能把同一笔报销写成三个整数：200、350、150，并用 claimedYuan 减 limitYuan 核对超出。
  • 能在缺字段、把 200 写成字符串、把 350 填进上限，或多出一个金额字段时停下来。
  • 能把角色和任务分开写，并只在字段齐且校验通过时把 JSON 交给 lookupClause。

这一章：散文收成三个整数，齐了才交给工具

第 1 章留下档案助理和一句教学报销。原句是「上周报销超了：上限 200 元，这单填了 350 元。」这句话给人读。程序要的是一张只有三个整数的表：limitYuan 200、claimedYuan 350、overYuan 150。150 是 350 减 200，课程里用 Course.agentMath.overYuan() 核对，结果就是 150。

整章按一条链走。先承认散文接不住。再收成三个整数字段。少一个名字，或有一个不是整数，就停在这一章，不进入下一步。角色只介绍档案助理是谁，这一步要抽哪些字段另写成任务。从教学句里把 200 放进上限、把 350 放进申报额，超出写成 150。然后核对超出是否等于申报减上限。核对通过，才把这张表交给下一章的工具 lookupClause。工具名来自 Course.data.agent.toolName。这一章不执行查询，只决定交不交得出去。

这是教学用的一笔报销，用来把全课的数字对齐。它不是某位员工的真实单据。金额只有这三处：200、350、150。后文章节继续用这三个数，本章不另起一笔。

散文接不住

2.1–2.2。整句没有字段表。收成 limitYuan、claimedYuan、overYuan 三个整数。

缺一个就停

2.3–2.5。少字段就停。元写成整数。角色和任务分开，任务不写进角色介绍。

齐了才交工具

2.6–2.8。从这一句抽出 200 和 350，超出核对为 150，再交给 lookupClause。

2.1 程序接不住散文

章首把整条链说完了。这一步先看程序拿到的是不是这句散文。

问题：把教学句原样交给程序时，它能不能读到上限、申报额和超出？

约定：教学句放在 Course.data.agent.sentence。原文是「上周报销超了：上限 200 元，这单填了 350 元。」单位是元。这句话里有汉字、冒号和两处「元」，没有字段名。程序按名字取值。名字不在，取值就无从开始。

基准算例：句子里能看见数字 200 和 350，看不见 150。即便如此，200 和 350 仍是句子里的文字，还不是 limitYuan 和 claimedYuan。三个字段在这一步都算缺席。下一节才给它们名字和整数。

用正则硬挖整句话
写一条正则把整句匹配下来，匹配成功就当作模型已经懂了结构。 匹配成功只说明原句还在。程序手里仍然是散文，limitYuan、claimedYuan、overYuan 一个都没有。句子里也没有 150 这三个数字，挖整句挖不出超出。

可操作对象：下面 2.2 的演示有一档叫「散文」。切过去时，三个字段的读数都是「不在」。这一节先记住：接住散文，不等于已经有结构。

2.2 三个字段 limitYuan、claimedYuan、overYuan

散文已经接不住。这一步把同一笔报销收成 limitYuan、claimedYuan、overYuan。

问题：程序往后传递的时候，这张表上应该有哪三个名字？

符号与单位：三个名字都用整数，单位是元。展示给人看时可以写成「200 元」，字段里只放整数。

字段中文整数单位从教学句的哪一处来
limitYuan上限200元「上限 200 元」里的 200
claimedYuan申报额350元「这单填了 350 元」里的 350
overYuan超出150元句子没写出这个数，由 350 − 200 得到
本课这一笔

教学句：「上周报销超了：上限 200 元，这单填了 350 元。」对应 limitYuan 200、claimedYuan 350、overYuan 150。Course.agentMath.overYuan() 返回 claimedYuan − limitYuan，用来核对 150。Course.data.agent.overYuan 也是 150。两处必须相同。

下面这份示例只构造这三个整数，并检查三个都是整数。控制台打印 true 200 350 150。

var limitYuan = 200;
var claimedYuan = 350;
var overYuan = 150;

function claimFields() {
  return {
    limitYuan: limitYuan,
    claimedYuan: claimedYuan,
    overYuan: overYuan
  };
}

function hasThreeIntegers(claim) {
  var limitOk = typeof claim.limitYuan === 'number' && claim.limitYuan === Math.trunc(claim.limitYuan);
  var claimedOk = typeof claim.claimedYuan === 'number' && claim.claimedYuan === Math.trunc(claim.claimedYuan);
  var overOk = typeof claim.overYuan === 'number' && claim.overYuan === Math.trunc(claim.overYuan);
  return limitOk && claimedOk && overOk;
}

var claim = claimFields();
console.log(hasThreeIntegers(claim), claim.limitYuan, claim.claimedYuan, claim.overYuan);

示例代码：examples/ch02/claim-fields.js

多写一个课程里没有的金额字段
在三字段之外再加一个金额名，例如 bonusYuan，哪怕数字抄了上限 200。 这张表只有 limitYuan、claimedYuan、overYuan。200、350、150 已经落在这三个名字上。多出来的名字不进入下一步。

可操作对象：切换「散文 / JSON」。散文档三个字段都读「不在」。JSON 档三个都读「在」，整数是 200、350、150。JSON 档的超出来自 Course.agentMath.overYuan()。

散文里没有字段，JSON 里三个都在切换散文或 JSON
观察要点：① 「散文」档三个字段都是「不在」，左边仍是教学句原文。② 「JSON」档三个字段都是「在」。③ 这一档的整数是 limitYuan 200、claimedYuan 350、overYuan 150。④ 150 来自 Course.agentMath.overYuan()，与 claimedYuan 减 limitYuan 相同。

2.3 缺字段就不进入下一步

三个字段的名字已经定了。这一步规定：少一个就不进入下一步。

问题：上限和申报额都有了，超出还没写。程序能不能先往下走？

约定：下一步的入口只认三个名字同时在场，并且每个都是数字。少 overYuan，入口关闭。少另外两个里的任意一个，同样关闭。关闭时的标记是「停」，打开时的标记是「字段齐」。这一步先不核对 150 等不等于差，核对放在 2.7。

基准算例：只有 limitYuan 200 和 claimedYuan 350 的对象，nextStep 返回「停」。补上 overYuan 150 之后，返回「字段齐」。控制台两行就是这两个结果。

function nextStep(claim) {
  if (typeof claim.overYuan !== 'number') {
    return '停';
  }
  if (typeof claim.limitYuan !== 'number' || typeof claim.claimedYuan !== 'number') {
    return '停';
  }
  return '字段齐';
}

console.log(nextStep({ limitYuan: 200, claimedYuan: 350 }));
console.log(nextStep({ limitYuan: 200, claimedYuan: 350, overYuan: 150 }));

示例代码：examples/ch02/stop-if-missing.js

漏掉 overYuan 仍继续
看见 200 和 350 已经齐了，就带着缺超出的对象进入 lookupClause。 overYuan 不在，nextStep 返回「停」。150 还没有写进字段，下一步不开始。2.8 的演示里，「缺超出」一档的下一步就是停。

可操作对象：nextStep 的返回值。缺 overYuan 时读到「停」，三个数字都在时读到「字段齐」。

2.4 元用整数，不写成「两百」

缺字段会停。这一步再看齐了的时候，元是不是整数。

问题：上限已经放进 limitYuan。写成 200、写成字符串 "200"、写成「两百」，这三样是不是同一个字段？

约定：字段类型是数字，并且等于它截断小数后的自身。200 通过。字符串 "200" 不通过。「两百」不通过。单位仍是元，汉字「元」不进字段。

基准算例：三个调用的结果依次是 true、false、false。第一行检查整数 200。第二行检查字符串 "200"。第三行检查「两百」。350 和 150 用同一条规则，这里只用 200 把类型说清楚。

function yuanIsInteger(value) {
  return typeof value === 'number' && value === Math.trunc(value);
}

console.log('整数 200', yuanIsInteger(200));
console.log('字符串 200', yuanIsInteger('200'));
console.log('汉字两百', yuanIsInteger('两百'));

示例代码：examples/ch02/yuan-integer.js

把 200 写成字符串
limitYuan 写成 "200"。在 JavaScript 里 "350" - "200" 会先被转成数字，看起来像 150，字段类型却仍是字符串。 limitYuan 写成整数 200，claimedYuan 写成整数 350，overYuan 写成整数 150。yuanIsInteger 对字符串 "200" 和「两百」都返回 false，这种表停在类型这一步。

可操作对象：yuanIsInteger。它只接受本课这种整数。字符串和汉字数目都留在字段外面。

2.5 角色和任务分开写，不把任务写进角色介绍

整数已经和「两百」、字符串分开。这一步把角色介绍和这一步的任务拆开。

问题：档案助理是谁，和这一步要抽出哪三个字段，要不要写在同一段介绍里？

约定：角色只写身份。本课的身份是 Course.data.agent.name，也就是档案助理，按规章回答。任务另写这一步要做的事：从教学句抽出 limitYuan、claimedYuan、overYuan 三个整数，缺一个就停。换一句报销时，改任务里的原句，角色介绍保持不动。

基准算例：下面两段是分开的。角色里没有 200、350、150，也没有「抽出」。任务里引用教学句原文，并点名三个字段。控制台先打印角色，再打印任务。

var role = '档案助理。按规章回答。';
var task = '从「上周报销超了：上限 200 元，这单填了 350 元。」抽出 limitYuan、claimedYuan、overYuan 三个整数。缺一个就停。';

function promptParts() {
  return { role: role, task: task };
}

console.log(promptParts().role);
console.log(promptParts().task);

把任务写进角色介绍
角色写成「你是负责把这句报销拆成 limitYuan 200、claimedYuan 350、overYuan 150 的档案助理」。 角色停在「档案助理。按规章回答。」任务另起一段，写明从教学句抽出三个整数。任务里的「200 元」「350 元」是在引用原句，整数仍要写进字段。

可操作对象：promptParts() 返回的两个属性 role 和 task。读的时候分两行，不把任务接在身份后面。

2.6 从这一句教学句抽字段

角色和任务已经分开。这一步只从教学句里把 200 和 350 放进对应字段，超出写成 150。

问题：对着「上周报销超了：上限 200 元，这单填了 350 元。」这三个整数各从哪里落下？

约定：抽字段是按意思把数放进已经定好的名字，再写成整数。整句匹配、把整句交回去，都还停在 2.1 的散文上。句子没有出现字段名，也没有出现 150。超出要在这一步写上，数值用下一节的减法核对。

教学句里的说法写入的字段写入的整数
上限 200 元limitYuan200
这单填了 350 元claimedYuan350
原句没有超出的数字overYuan150

基准算例：抽完的对象就是 2.2 的 claimFields()。limitYuan 是 200，claimedYuan 是 350，overYuan 是 150。同一份示例在 examples/ch02/claim-fields.js。

把 350 填进上限
看见句中较大的 350，就把它写入 limitYuan，200 被写进 claimedYuan。 「上限」对应 limitYuan 200，「这单填了」对应 claimedYuan 350。两个数对调之后，150 不再等于申报减上限，2.7 的校验失败。
把展示文本「200 元」再当一份事实
整数 200 已经放进 limitYuan，再存一份字符串「200 元」，当作另一个上限。 事实只有整数 200。「200 元」是给人看的展示，带着汉字「元」。程序读 limitYuan 这一处。

可操作对象：上表三行。读教学句时，先对上「上限」和「这单填了」，再单独补上超出 150。展示句子留在原处，不进字段表。

2.7 校验：overYuan 必须等于 claimed 减 limit

三个整数已经抽出来。这一步核对 overYuan 是不是 claimedYuan 减 limitYuan。

问题：三个字段都在，就可以交给工具了吗？

符号与单位：三个量都是元的整数。减法在同一单位下进行，差的单位仍是元。这里不换算成分，也不把元写成小数。

本课的等式是：

\[ \text{overYuan} = \text{claimedYuan} - \text{limitYuan} = 350 - 200 = 150 \]

Course.agentMath.overYuan() 的实现就是 claimedYuan - limitYuan。它读 Course.data.agent 上的 350 和 200，返回 150。这个返回值要和字段 overYuan 相等，也要和 Course.data.agent.overYuan 相等。

基准算例：第一行用 200、350、150，校验为 true。第二行把 350 填进上限、把 200 填进申报额，超出仍写 150，校验为 false。false 的那一张停在这里，不因为三个名字都在就继续。

var limitYuan = 200;
var claimedYuan = 350;
var overYuan = 150;

function overMatches(claim) {
  return claim.overYuan === claim.claimedYuan - claim.limitYuan;
}

console.log(overMatches({
  limitYuan: limitYuan,
  claimedYuan: claimedYuan,
  overYuan: overYuan
}));
console.log(overMatches({
  limitYuan: 350,
  claimedYuan: 200,
  overYuan: 150
}));

示例代码：examples/ch02/check-over.js

控制台两行是 true 然后 false。页面演示不抄第二套差：切到「三字段齐」时，overYuan 的读数直接取 Course.agentMath.overYuan()，本课显示 150。

可操作对象：overMatches。相等才留下这张表。不相等就停，等待字段改回 200、350、150。

2.8 字段齐了才交给 lookupClause

超出已经核对为 150。这一步才决定能不能把这张表交给 lookupClause。

问题：校验通过之后，下一章的工具接到的是什么？

约定：工具名是 lookupClause，与 Course.data.agent.toolName 相同。交给它的是只含三个整数的对象。缺字段、类型不是整数、多出一个金额名、或者超出不等于申报减上限，返回的工具名都是空，原因是「停」。这一章不查询规章，查询留在第 3 章。这里只做交接口。

基准算例：三行控制台依次是 null、lookupClause、null。第一行缺 overYuan。第二行是 200、350、150，并且 150 等于 350 减 200。第三行在第二行之外加了 bonusYuan，数字抄了上限 200。这个名字不在课程的三个字段里，工具名仍是空。

function handOff(claim) {
  var allowed = ['limitYuan', 'claimedYuan', 'overYuan'];
  var seen = {};
  var key;
  var i;
  for (key in claim) {
    if (Object.prototype.hasOwnProperty.call(claim, key)) seen[key] = true;
  }
  for (i = 0; i < allowed.length; i++) {
    key = allowed[i];
    if (typeof claim[key] !== 'number' || claim[key] !== Math.trunc(claim[key])) {
      return { tool: null, reason: '停' };
    }
  }
  for (key in seen) {
    if (allowed.indexOf(key) < 0) {
      return { tool: null, reason: '停' };
    }
  }
  if (claim.overYuan !== claim.claimedYuan - claim.limitYuan) {
    return { tool: null, reason: '停' };
  }
  return { tool: 'lookupClause', reason: '字段齐' };
}

console.log(handOff({ limitYuan: 200, claimedYuan: 350 }).tool);
console.log(handOff({ limitYuan: 200, claimedYuan: 350, overYuan: 150 }).tool);
console.log(handOff({ limitYuan: 200, claimedYuan: 350, overYuan: 150, bonusYuan: 200 }).tool);

示例代码：examples/ch02/hand-to-lookup.js

校验失败仍把散文送给工具
overYuan 对不上，或字段缺失时，把「上周报销超了：上限 200 元，这单填了 350 元。」整句送给 lookupClause。 停的时候工具名是空。lookupClause 只在 handOff 返回「字段齐」时出现，参数是三个整数，不是这句散文。
JSON 外再附一段解释
JSON 右花括号后面再写「请按报销规章继续查」，把 JSON 和这段话一起当作程序输入。 程序输入停在三个整数字段。括号外的解释不进入 limitYuan、claimedYuan、overYuan，也不送给 lookupClause。

可操作对象：切换「缺超出 / 三字段齐」。缺超出时下一步是停，overYuan 读作「缺」。三字段齐时，overYuan 读数是 Course.agentMath.overYuan()，本课为 150，下一步是 lookupClause。

缺超出就停，三字段齐才读 150切换缺超出或三字段齐
观察要点：① 「缺超出」档 overYuan 是「缺」，下一步是停，不把教学句送给 lookupClause。② 「三字段齐」档 overYuan 的读数是 Course.agentMath.overYuan()，本课为 150。③ 这一档的核对行是 150 = 350 - 200。④ 缺的那一档不要把 150 填回去再继续。

本章避坑清单

  1. 用正则硬挖整句话，匹配成功就当成模型已经懂了结构。原句还在，只说明散文还在；200 和 350 若被抠成两个数字，overYuan 的 150 仍然没有。
  2. 校验失败仍把散文送给工具。超出对不上 150，或少了字段，lookupClause 的工具名保持为空，参数不能是教学句原文。
  3. 把展示文本「200 元」再当一份事实。整数 200 是 limitYuan。带「元」的那一串是给人看的。
  4. JSON 外再附一段解释，把解释和 JSON 一起当成程序输入。输入停在三个整数字段。
  5. 把 200 写成字符串 "200"，或写成「两百」。字段要能通过整数检查。字符串相减看起来像 150，类型仍然不对。
  6. 漏掉 overYuan 仍继续。只有 200 和 350 时，下一步是停。
  7. 把 350 填进上限。上限是 200，申报额是 350。对调之后，150 不再等于申报减上限。
  8. 多写一个课程里没有的金额字段。bonusYuan 即使抄了 200，也不和 limitYuan、claimedYuan、overYuan 并列。
