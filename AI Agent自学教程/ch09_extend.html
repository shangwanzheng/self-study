第 9 章 · 现象与判断

技能、图谱与接口差异

第 8 章在超出 150 元时停下来等人确认。这一章接着判断三件事：两个技能先读哪一个，关系沿哪一条走到规章，换一家模型接口之后三个字段还是不是原来的数。

预计学习 90 分钟 前置：第 2、3、6、7、8 章 交互演示 2 个
  • 能读出技能文件数是 2、这次装入数是 1，先读报销，差旅留在外面。
  • 能区分按词「上周」会摸到第 1 条考勤，沿「超了」走到第 3 条报销并读出上限 200 元。
  • 能说明换一家模型接口之后，limitYuan、claimedYuan、overYuan 仍是 200、350、150。

这一章：先读 1 个技能，再沿关系，最后核对三个字段

教学句仍是「上周报销超了：上限 200 元，这单填了 350 元。」磁盘上有两个技能文件：报销、差旅。skillCount 是 2。第一次提示不把两份正文都装进去，装入数 skillLoaded 是 1，先读报销。差旅文件还在，只是这次留在外面。

技能只决定读哪一份说明。规章仍是四条：考勤、请假、报销、差旅。只按词「上周」重叠，会摸到第 1 条考勤。图谱上的边从「超了」接到第 3 条报销，再经 lookupClause 读出上限 200 元。这一个 200 就是 第 2 章 的 limitYuan，不在技能文件里再写一份，也不因为多一条边就再造一个上限。

最后换一家模型接口。外层的路径、鉴权和初始化以各家文档原文为准。程序仍读这三个字段：limitYuan 200、claimedYuan 350、overYuan 150。差是 \(350-200=150\) 元，和第 8 章停下来等人确认的那一笔是同一个数。

先读 1 个技能

9.1–9.3。文件数是 2。第一次只读报销。差旅留在外面。正文里不写 200。

沿着关系找

9.4–9.6。「上周」摸到考勤。「超了」连到第 3 条报销，上限仍是 200。

字段不改

9.7–9.8。换接口后三个字段名还在。150 这个差不改，也不删掉 overYuan。

9.1 两个技能不是一开始都装进提示词

章首把装入、关系和字段串成一条。先决定第一次提示里读进几个技能。

问题：磁盘上已经有报销和差旅两个技能，第一次发给模型的提示词要不要把两份正文都放进去？

约定：技能文件数记作 skillCount，数的是磁盘上的文件，单位是个。装入数记作 skillLoaded，数的是这一次读进工作上下文的文件，单位也是个。两个数可以不同。第一次提示只写下这次的决定：文件有几个、装入几个、名字是哪一个。技能正文在决定之后再读。四条规章的正文也不在这一步贴进来。第 7 章 的上下文预算 contextChars 是 120 字，第一次提示还要留给教学句和后面三个金额字段。

量符号基准这一步放进第一次提示的内容
技能文件数skillCount2名字：报销、差旅。两份都还在磁盘上
装入数skillLoaded1决定先读报销。差旅这一份先不读
上下文预算contextChars120 字留给教学句和随后要读的三个字段

基准算例：问的是报销超了没有。文件数是 2，装入数是 1。第一次提示里看得到这组决定，看不得到两份技能正文叠在一起。上限 200 元、这单 350 元、超出 150 元都还不在技能正文里，它们留到沿关系找到第 3 条之后再读。

把技能正文整份贴进第一次提示

第一次提示如果已经贴着报销正文，再贴着差旅正文，装入数就从 1 变成 2。120 字的预算里，教学句和后面的 limitYuan、claimedYuan、overYuan 没有位置。正文是决定读哪一个之后才读的那一份。

用文件数代替装入数

skillCount 是 2，只说明报销和差旅两个文件都在。第一次装入数仍是 skillLoaded 1。把 2 填进装入数，差旅会和报销一起进入这次提示。

可操作对象：在纸上写两行。第一行「文件」下面写报销、差旅，个数 2。第二行「这次装入」下面只写报销，个数 1。两行的个数不要抄成同一个数。下一节用分段把装入数在 2 和 1 之间切换。

9.2 先读报销这 1 个

两个技能都还在磁盘上，第一次提示并没有把两份正文都装进去。这一节决定先读报销这 1 个。

问题：装入数已经定为 1，读的是哪一个文件？

约定：教学句在问报销有没有超了，所以这 1 个是报销技能。读进来的是步骤：调用工具 lookupClause，再读取它返回的 limitYuan、claimedYuan、overYuan。工具名是本课的 toolName。步骤里不出现 200、350、150 这三个数。数在第 3 条规章上，由工具带回，见 第 3 章。

报销技能里有的

名称是报销。何时读：这句在问报销有没有超了。步骤：调用 lookupClause，读取三个字段。

报销技能里不写的

不写上限 200，不写这单 350，不写超出 150。这些数只留在第 3 条。

基准算例：下面的函数把两种读法收成文件数和装入数。先读 1 个时，装入数是 skillLoaded 1，名字只有报销。两个都读时，装入数等于文件数 2。页面上的分段改读 Course.data.agent 的 skillCount 与 skillLoaded，不另抄一套个数。

var skillCount = 2;
var skillLoaded = 1;
var skillNames = ['报销', '差旅'];

function loadSkills(mode) {
  if (mode === '两个都读') {
    return {
      found: skillCount,
      loaded: skillCount,
      names: skillNames.slice()
    };
  }
  return {
    found: skillCount,
    loaded: skillLoaded,
    names: skillNames.slice(0, skillLoaded)
  };
}

console.log(loadSkills('先读 1 个').loaded, loadSkills('先读 1 个').names.join('、'));
console.log(loadSkills('两个都读').loaded, loadSkills('两个都读').names.join('、'));

示例代码：examples/ch09/load-skill.js

控制台两行是 1 报销 与 2 报销、差旅。第一行是本章的装入。第二行是一次把两个都装进去。函数里没有 200。

一次装进 2 个技能

分段切到「两个都读」时，装入数是 2，差旅和报销一起进入这次提示。基准装入数是 1。这句还没问差旅，差旅正文不该占掉那 120 字。

技能文件里再写一份 200

报销技能若把上限写成 200，磁盘上就有了第二份上限：一份在第 3 条，一份在技能文件。以后只改规章，技能里的 200 仍会跟着步骤被读出来。技能文件只写 lookupClause 和三个字段名。

可操作对象：切换下面的分段。读「技能文件」和「装入数」两栏。文件数保持 2。装入数在 2 和 1 之间变。先读 1 个时，差旅卡片写着「留在外面」。

两个技能读进几个切换「两个都读 / 先读 1 个」
观察要点：① 先读 1 个：技能文件数是 2，装入数是 1，名字只有报销，差旅留在外面。② 两个都读：装入数变成 2，报销和差旅都进了这次提示。③ 两种分段都不出现 200。上限不写在技能装入这一步。

9.3 差旅技能先留在外面

装入数已经是 1，读的是报销。差旅这一份先留在外面，文件还在，技能文件数仍是 2。

问题：这次没读差旅，磁盘上的差旅技能还算不算在 skillCount 里？

约定：留在外面指这次不装入，不是把文件删掉，也不是把 skillCount 改成 1。差旅技能只保留名字和何时再读的条件：问的是差旅时再读。它和第 4 条差旅规章不是同一件东西。第 4 条仍在四条规章里，余弦是 0，本章不改这个余弦，也不从第 4 条读上限。

对象这次在哪个数或条号上面有没有 200
报销技能已读入装入数 1没有。步骤只点三个字段名
差旅技能留在磁盘上仍计入文件数 2没有。不另写一份上限
第 4 条差旅规章四条之一条号 4，余弦 0没有。这句的上限不在这一条

基准算例：文件数 \(2\) 减装入数 \(1\)，留在外面的是 \(2-1=1\) 个，就是差旅技能。第 3 条报销规章上的上限仍是 200 元，不因为外面还放着一个差旅技能就再出现一个上限。

没装入就把文件数改成 1

演示里差旅卡片写「留在外面」时，技能文件栏仍是 2。若把文件数改成 1，磁盘上的差旅技能就从基准里消失，下次真问差旅时没有文件可读。

在差旅技能里新造第二个上限

差旅文件若写上另一个上限，或者把报销的 200 抄进去，上限就有了两处。本章的上限只有 limitYuan 200，在第 3 条。差旅技能留在外面，里面也不放这个数。

可操作对象：回到上一节的分段，停在「先读 1 个」。核对三格：文件数 2、装入数 1、差旅是「留在外面」。不要在差旅那一格填 200。

9.4 词重叠找到「上周」会摸到考勤

报销技能已经读入，步骤是去查规章。若只按词重叠找，教学句里的「上周」会摸到考勤。

问题：只拿「上周」这个词去和四条规章重叠，落在哪一条？

约定：这一节的找法只使用这一个词，不使用图谱，也不使用 第 6 章 的余弦。本章约定：考勤条文里有「上周」，所以重叠落在第 1 条，名字是考勤。报销条文的命中不靠这个词。落点条号是 1，不是 clauseNo 3。这一条上不读 limitYuan。读数用「未读」，不用 0。0 会像另一个上限。

词落点条号报销上限
上周考勤1未读

基准算例：教学句是「上周报销超了：上限 200 元，这单填了 350 元。」句中有「上周」，也有「报销」和「超了」。这一节故意只用「上周」。四条名字仍是考勤、请假、报销、差旅。摸到的是第一条。200 元还在第 3 条上，这一步碰不到它。

用「上周」命中考勤就回答考勤时间

落点变成考勤之后，若接着写到岗或工时，回答就离开了这句。这句问的是报销有没有超了。考勤条上没有 limitYuan 200，也没有这单 350 和超出 150。考勤时间不进入这句的回答。

把考勤落点改记成第 3 条

为了和后面的基准条号看起来一样，把词重叠的落点改成第 3 条，两条找法就混成一条。按词「上周」的落点就是第 1 条考勤。第 3 条要等下一节的那条边。

可操作对象：盖住「报销」「超了」，只留「上周」，在四条名字上点重叠。点到的是考勤。纸上的上限栏写「未读」。下一节改用关系词「超了」。

9.5 图谱把「超了」连到报销

按词「上周」已经摸到第 1 条考勤，上限仍是未读。这一节改沿关系：图谱把「超了」连到报销。

问题：「超了」这条边接到四条里的哪一条？

约定：图谱这一步只记边，不记第二套金额。节点是关系词和四条规章。边只有一条：从「超了」到第 3 条，名字是报销。第 1 条考勤不在这条边上。边的条数是 1。沿边读到的上限，就是第 3 条已有的 limitYuan 200 元，不是边上新标的一个数。

起点终点条号边上写的数
超了报销3不写。上限仍去第 3 条读

基准算例：下面的 edges 只有一条。按图谱走时，条号取这条边的 clauseNo 3，名字是报销，上限是 200。按词「上周」走时，名字是考勤，上限是 null，表示未读。页面演示改读 Course.data.agent 的规章名、clauseNo 和 limitYuan。

var clauseNames = ['考勤', '请假', '报销', '差旅'];
var limitYuan = 200;
var edges = [{ from: '超了', clauseNo: 3 }];

function follow(mode) {
  if (mode === '按词「上周」') {
    return {
      clauseNo: 1,
      name: clauseNames[0],
      limitYuan: null
    };
  }
  var edge = edges[0];
  return {
    clauseNo: edge.clauseNo,
    name: clauseNames[edge.clauseNo - 1],
    limitYuan: limitYuan
  };
}

console.log(follow('按词「上周」').name);
console.log(follow('按图谱').name, follow('按图谱').limitYuan);

示例代码：examples/ch09/follow-edge.js

控制台两行是 考勤 与 报销 200。edges.length 是 1。200 来自 limitYuan 这一个变量。

把「超了」连到第 1 条考勤

边若从「超了」接到考勤，落点就和按词「上周」相同，上限会到考勤条上去找。考勤条没有报销上限。关系词「超了」的终点是第 3 条报销。

图谱多一条边就多一个上限

在现有这一条之外，再添「超了」到考勤，边就变成 2 条。读的时候会再找一个上限。本章只有 limitYuan 200，在第 3 条。示例里的 edges 保持一条。

可操作对象：画出四个规章节点，只画一条从「超了」出发的箭头，箭头落在报销上。数一数箭头：是 1。不要把「上周」也画成从「超了」出发的第二条箭头。

9.6 命中仍是第 3 条，上限仍是 200

「超了」已经接到报销。这一节核对：命中仍是第 3 条，上限仍是 200。

问题：沿图谱走完之后，条号和上限有没有变成另一套数？

约定：命中条号用 clauseNo，基准是 3，名字是报销。上限用 limitYuan，基准是 200 元。第 6 章按余弦取前 topK 2 片时，第 3 条在里面，第 3 条与问句的余弦是 1。本章的图谱边和那个条号一致，不另起第 5 条，也不把上限改成 350 或 150。350 是 claimedYuan，150 是 overYuan。按词「上周」的落点仍是第 1 条，那一条的上限保持未读。

找法落点条号上限
按词「上周」考勤1未读
按图谱报销3200 元

基准算例：按图谱的落点等于 clauseNames[clauseNo - 1]，也就是报销。读出的上限等于 limitYuan 200。这单 350 元和超出 150 元这一步不改写。切换分段时，四条名字的顺序保持考勤、请假、报销、差旅。

命中第 3 条后把上限读成 350 或 150

三个数都在第 3 条附近出现。上限是 200 元。350 元是这单填的，150 元是超出。把后两个填进上限栏，第 8 章要等人确认的那一笔就对不上。

沿图谱又按「上周」补读考勤

图谱已经落到第 3 条并读出 200。再因为句中有「上周」去读第 1 条，等于把两条找法接成两条边。考勤条上没有第二个上限。补读这一步不做。

可操作对象：切换「按词「上周」 / 按图谱」。前一档落在考勤，上限是未读。后一档落在报销，上限是 200 元。

按词还是按图谱切换「按词「上周」 / 按图谱」
观察要点：① 按词「上周」：落点是第 1 条考勤，上限是未读。不要据此回答考勤时间。② 按图谱：落点是第 3 条报销，上限是 200 元。③ 四条名字的顺序不变。「超了」没有连到考勤。

9.7 换一家接口，字段名仍是这三个

条号已经是 3，上限已经是 200。这一节换一家模型接口，核对字段名仍是这三个。

问题：换一家模型之后，程序读的字段名要不要跟着那家的示例改掉？

约定：本章用「甲家」「乙家」称呼两套外层，只为了在同一页上对比。它们不是产品真名，也不代表某一套初始化代码。外层的路径、鉴权、流式事件和 SDK 初始化参数，以各家文档原文为准。程序要读的字段名固定为 limitYuan、claimedYuan、overYuan。单位都是元。不新造第二个上限，也不把差旅技能里的空位填成另一个数。

limitYuan200 元
claimedYuan350 元
overYuan150 元
甲家乙家
外层见甲家文档原文见乙家文档原文
limitYuan200200
claimedYuan350350
overYuan150150

基准算例：两家各调用一次 readFields。返回值里的 envelope 只是教学标签，提醒外层去看那家文档。三个金额字段在两家之间同名同数。overYuan 由 \(350-200\) 得到，仍是 150。演示和自测读 Course.data.agent 与 Course.agentMath.overYuan()。

var limitYuan = 200;
var claimedYuan = 350;
var overYuan = claimedYuan - limitYuan;

function readFields(vendor) {
  return {
    vendor: vendor,
    envelope: '见' + vendor + '文档原文',
    limitYuan: limitYuan,
    claimedYuan: claimedYuan,
    overYuan: overYuan
  };
}

var jia = readFields('甲家');
var yi = readFields('乙家');

console.log(jia.limitYuan, jia.claimedYuan, jia.overYuan);
console.log(yi.limitYuan, yi.claimedYuan, yi.overYuan);
console.log(jia.envelope === yi.envelope);

前两行都是 200 350 150。第三行是 false，因为外层标签一个是甲家、一个是乙家。金额三列没有跟着变成两套。

换模型后把上限改成别的数

换的是调用哪一家。上限仍是 200 元，这单仍是 350 元。若把 200 改成那家示例里的别的数，第 3 条和技能步骤就不再指向同一个 limitYuan。

把某个 SDK 的初始化菜单写成唯一做法

某一页快速开始可能只演示了该 SDK 的客户端构造。那一页的参数以该 SDK 当时的文档原文为准。本章不把那一页菜单写成唯一做法，也不据此增删 limitYuan、claimedYuan、overYuan。

可操作对象：把上表甲家、乙家两列盖住外层，只留三行字段。两列应都是 200、350、150。字段名不要改成那家文档里的别名后再算一遍。

9.8 接口差异不改变 150 这个差

三家字段名已经对齐成同一组。最后确认：接口外层可以不同，150 这个差不变。

问题：甲家和乙家的外层标签不同，超出还是不是 150 元？

约定：超出记作 overYuan，单位元。它由这单减去上限得到，两项都用元，都来自第 3 条经 lookupClause 带回的那一组。不在技能文件里另写，不随外层标签改写。某一家的示例若只展示两个金额字段，那是那一页示例的取舍；本章的返回值仍保留 overYuan。

基准算例：代入第 3 条的两个数。

\[ \mathrm{overYuan}=\mathrm{claimedYuan}-\mathrm{limitYuan}=350-200=150 \]

甲家一行是 200、350、150。乙家一行也是 200、350、150。两行的差都是 150 元。这就是 第 8 章 停下来等人确认的那一笔，也是 第 10 章 要走到确认后回答时用的那一笔。

换了外层就把 150 重估成别的差

外层标签不同，只说明要去看的文档不同。\(350-200\) 仍是 150。让模型按新接口重新估计一个差，确认时的 150 元就不再是这单减上限。

为兼容某家接口而删掉 overYuan

若某家示例里没有超出字段，就从返回值删掉 overYuan，程序就读不到 150，虽然 \(350-200\) 还是 150。字段留着。外层怎么包，回到那家文档原文，不反过来改这三个字段。

可操作对象：用上一节的函数对甲家、乙家各读一次。比较 overYuan。两个都是 150，envelope 的字符串不相同。三条链到这里合上：装入数是 1，命中是第 3 条，差是 150 元。

  1. 一次装进 2 个技能。文件数 skillCount 是 2，第一次装入数是 skillLoaded 1，只读报销。

  4. 图谱多一条边就多一个上限。「超了」只连第 3 条报销。再连到考勤，就会去找另一个上限。本章的上限只有 limitYuan 200。
  5. 技能文件里再写一份 200。上限只在第 3 条，经 lookupClause 读出。差旅技能留在外面，也不抄这个数。
  6. 换模型后把上限改成别的数。换的是外层调用。limitYuan 仍是 200，claimedYuan 仍是 350。
  7. 为兼容某家接口而删掉 overYuan。差是 \(350-200=150\)，这个字段留着。
  8. 把某个 SDK 的初始化菜单写成唯一做法。初始化、路径和鉴权以各家文档原文为准。
