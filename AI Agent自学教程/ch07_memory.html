这一章：先承认没有记忆，再留下 3 条，再压进 120 字

教学句是「上周报销超了：上限 200 元，这单填了 350 元。」模型下一次调用不会自动记得这句话。记忆是外面再送进去的文本。本课留下 memoryKeep 3 条，预算 contextChars 120 字。320 字规章放不进这个预算。情景摘要要有重要度、前因、下一步；下一步是等人确认，确认本身在第 8 章。

7.1 每次调用都不记得上一次

检索已经能取到第 3 条。这一节先承认模型自己不保留上一次的观察。

问题：上一轮看见过上限 200 元，下一轮如果不再送进这段文本，模型读到的上一轮上限是空的。

约定：previousLimit 固定为 null。这一次能不能读到 200，只看这次文本里有没有「上限 200」。

基准算例：跟进句「超了多少」本身不带 200。不另送记忆时，reads200 为假。

function seesOnlyThisTurn(currentText) {
  return {
    previousLimit: null,
    reads200: currentText.indexOf('上限 200') >= 0
  };
}

示例代码：examples/ch07/no-memory.js

以为模型自己记得上次的 200

窗口还停在上一轮，不表示下一次请求还带着那个 200。没送进这次输入的数，这次就没有。

可操作对象：用「超了多少」调用 seesOnlyThisTurn，reads200 应为假，previousLimit 应为 null。

7.2 记忆是外面送进去的文本

上一次不会自动留下。这一节把要留的句子和当前句接在同一次输入里。

问题：记忆不是模型内部的一块存储，而是这次请求正文的一部分。

约定：先放记忆各行，再放当前句。当前句仍可以是「超了多少」，200 写在记忆行里。

基准算例：记忆行含「上限 200 元」。接上当前句之后，整段里能找到这五个字。

function withMemory(memories, currentText) {
  return memories.join('\n') + '\n' + currentText;
}

示例代码：examples/ch07/send-memory.js

只看当前句 / 带上 3 条记忆切换分段
观察要点：① 「只看当前句」时，当前句是「超了多少」，读不到上限 200。② 「带上 3 条记忆」时，三条里有上限 200 元和超出 150 元。③ 条数读数是 0 或 3，3 等于 memoryKeep。④ 两种模式都不改写档案里的 200 和 150。
用聊天窗口的滚动记录冒充记忆

屏幕上还看得到上一轮，只说明浏览器留着显示。下一次调用的输入里没有这段文字，模型就看不见 200。

可操作对象：把三条记忆和当前句交给 withMemory，结果字符串里应同时有「上限 200」和「超了多少」。

7.3 提取：从过程里挑出上限和超出

文本可以送进去了。这一节只留下写着上限和超出的行。

问题：过程里还有考勤、请假、差旅。全留下就会超过 3 条，也会挤占 120 字。

约定：一行里出现「上限 200」或「超出 150」才保留。

基准算例：「上限 200 元」和「超出 150 元」留下。「差旅不是这一问」丢掉。

function extractLimitAndOver(lines) {
  return lines.filter(function (line) {
    return line.indexOf('上限 200') >= 0 || line.indexOf('超出 150') >= 0;
  });
}

示例代码：examples/ch07/extract-facts.js

摘要里只有下一步、没有上限

只写「等人确认」，200 和 150 都没了。下一轮就答不出超了多少。

可操作对象：过滤后的数组应含上限行和超出行，不含差旅行。

7.4 只留 3 条

值得留的句子已经挑出。这一节按重要度只留 3 条。

问题：memoryKeep 是 3。留下 4 条还说成 3 条，预算就不是这一课的预算。

约定：按 importance 从高到低排序，再取前 memoryKeep 条。重要度最高的不被先删掉。

基准算例：上限那条重要度最高，超出其次，前因再次。第 4 条及以后不进入记忆。

function keepThree(notes, memoryKeep) {
  var ranked = notes.slice().sort(function (a, b) {
    return b.importance - a.importance;
  });
  return ranked.slice(0, memoryKeep);
}

示例代码：examples/ch07/keep-three.js

重要度最高的条被先删掉

排序是重要度高的在前。slice(0, memoryKeep) 留下的是前 3 条，不是丢掉前 3 条。

可操作对象：传入 4 条笔记和 memoryKeep 3，返回长度应为 3，第一条仍是重要度最高的那条。

7.5 压缩到 120 字以内

3 条已经选定。这一节把它们压进 120 字，并仍保留 200 和 150。

问题：过程草稿比预算长。原样送进去，fitsContext 不成立。

约定：压缩文必须同时含「上限 200」和「超出 150」，并且长度不超过 contextChars。压缩时不把 150 写成 0。

基准算例：压缩文三行：上限 200 元；超出 150 元；情景摘要里写明重要度、前因和下一步。草稿本身更长，不作为送进模型的文本。

var draft = '过程记录：用户说上周报销超了，上限 200 元，这单填了 350 元。lookupClause 命中第 3 条，名称是报销。超出金额是 150 元。考勤、请假、差旅不是这一问。情景摘要要写全三格。重要度：高。前因：上限 200 元，这单 350 元，超出 150 元。下一步：等人确认。确认放到第 8 章，这一章停在等人。规章全文 320 字不写进这条草稿。';

function compressMemory(draft, contextChars) {
  var keptFacts = draft.indexOf('上限 200') >= 0 && draft.indexOf('超出 150') >= 0;
  var text = [
    '上限 200 元',
    '超出 150 元',
    '情景摘要：重要度高；前因上限 200 元、这单 350 元、超出 150 元；下一步等人确认'
  ].join('\n');
  if (!keptFacts) {
    return {
      text: '',
      length: 0,
      fits: false,
      keeps200: false,
      keeps150: false,
      draftLength: draft.length
    };
  }
  return {
    text: text,
    length: text.length,
    fits: text.length <= contextChars,
    keeps200: text.indexOf('上限 200') >= 0,
    keeps150: text.indexOf('超出 150') >= 0 && text.indexOf('超出 0') < 0,
    draftLength: draft.length
  };
}

观察要点：① 「塞进 320 字」时，fitsContext(handbookChars) 为假。② 「压成不超过 120 字」时，压缩文长度不超过 120，读数为真。③ 压缩文仍含上限 200 元和超出 150 元。④ 两个读数都调用 Course.agentMath.fitsContext。

为了变短而改数字，超出就没了。压缩删的是考勤、请假、差旅这些旁支，不改 200 和 150。

可操作对象：compressMemory(draft, 120) 的 fits、keeps200、keeps150 都应为真，length 不大于 120。

7.6 情景摘要的三格

字数已经压进预算。这一节把留下的内容收成三格，而不是一段没有结构的话。

问题：只有下一步时，读的人不知道为什么等人。

约定：三格是重要度、前因、下一步。前因要同时写出上限 200 元、这单 350 元、超出 150 元。下一步固定为「等人确认」。

基准算例：重要度是「高」。确认动作本身不在本章执行。

function sceneSummary(lines) {
  var hasLimit = false;
  var hasOver = false;
  var i;
  for (i = 0; i < lines.length; i++) {
    if (lines[i].indexOf('上限 200') >= 0) hasLimit = true;
    if (lines[i].indexOf('超出 150') >= 0) hasOver = true;
  }
  return {
    importance: '高',
    cause: hasLimit && hasOver ? '上限 200 元，这单 350 元，超出 150 元' : '',
    next: '等人确认'
  };
}

function summaryComplete(summary) {
  return summary.importance.length > 0
    && summary.cause.indexOf('上限 200') >= 0
    && summary.cause.indexOf('超出 150') >= 0
    && summary.next === '等人确认';
}

示例代码：examples/ch07/scene-summary.js

摘要里只有下一步

summaryComplete 要求前因里同时有上限 200 和超出 150。缺一格，摘要就不完整。

可操作对象：用含这两句的行调用 sceneSummary，再交给 summaryComplete，结果应为真。

7.7 丢掉上限 200 的那一条就答不出来

三格都在时才能回答。这一节看删掉上限那一行之后发生什么。

问题：当前问句若不再重复 200，记忆里又没有这一条，这次输入里就没有上限。

约定：dropLimitLines 去掉含「上限 200」的行。canAnswerLimit 只在剩下的文本里找这几个字。

基准算例：问句用「超了多少」。删掉上限行之后，canAnswerLimit 为假。

function dropLimitLines(lines) {
  return lines.filter(function (line) {
    return line.indexOf('上限 200') < 0;
  });
}

function canAnswerLimit(lines, ask) {
  var packet = lines.concat([ask]).join('\n');
  return packet.indexOf('上限 200') >= 0;
}

示例代码：examples/ch07/drop-limit.js

为了塞进去而新造一个上下文长度

预算就是 contextChars 120。放不下就压缩，不把 120 改成 320 来迁就全文。

可操作对象：先 dropLimitLines，再 canAnswerLimit(lines, '超了多少')，结果应为假。

7.8 全文 320 字不能当记忆原样塞进去

上限那一条必须留着。这一节再核对全文本身不能充当记忆。

问题：规章全文 320 字，预算 120 字。原样塞进去一定超出预算。

约定：是否放得下看字数是否小于等于 120。页面演示调用 Course.agentMath.fitsContext，与下面这个同规则的函数对照。

基准算例：fitsContext(320) 为假，fitsContext(120) 为真。不新造超时或另一档上下文长度。

function fitsContext(chars) {
  var contextChars = 120;
  return chars <= contextChars;
}

示例代码：examples/ch07/fit-handbook.js

把 320 字整段算进 120 字预算

两个数都在档案里。320 大于 120，fitsContext 不会因为「这是规章」而放行。

可操作对象：对 320 和 120 各调用一次，读数应分别为假和真。页面上的读数以 Course.agentMath.fitsContext 为准。

本章小结与延伸阅读

模型无状态。记忆是这次送进去的文本。从过程里抽出上限 200 元和超出 150 元，按重要度只留 3 条，再压进 120 字。情景摘要写出重要度、前因和下一步「等人确认」。全文 320 字放不进这个预算。确认动作留给第 8 章。

  • 本课第 6 章：320 字先切片，检索只取前 2 片。第 8 章：超出 150 元时等人确认，并把观察写入检查点。
  • 所用模型的上下文长度以该模型文档原文为准。本课教学预算是 120 字。
