Agent 是什么

先分清聊天和干活，再把 Agent 收成大脑、规划、记忆、工具，然后用同一笔报销把四块各安一处。全课只认档案里的上限 200 元、这单 350 元、超出 150 元。

预计学习 80 分钟 前置：无（全课起点） 分段演示 2 个
  • 分清「只聊天」和「能干活」：回复里出现 200 元，仍然可能一次工具都没调用；
  • 把 Agent 收成大脑、规划、记忆、工具，并说清规划只负责先查再答；

  • 把页面上的分段演示和本机安装分开，安装以当前文档为准。

本章这条链

这一章在「共同语言」里，把「Agent 是什么」收成一条链。它不跑循环，也不切规章全文。三块按这个顺序接上：先分清聊天和干活，再把 Agent 收成大脑、规划、记忆、工具，然后用这笔报销把四块各安一处。下面八节是这条链上的八步，每节开头写明它接住的上一步结果。

1. 聊天和干活

聊天只留下建议。建议可以复述教学句里的 200 元，工具调用次数仍是 0。干活要改到结果：lookupClause 返回第 3 条。

2. 四块

同一个档案助理内部只有大脑、规划、记忆、工具。规划负责先查再答。四块不并进一句提示词，本章也不拆成多个角色。

3. 一笔规章

上限 200 元放在工具读到的第 3 条。这单 350 元是填写额。超出 150 元由 Course.agentMath.overYuan() 相减得到。

数字只来自 Course.data.agent 与 Course.agentMath。教学句是「上周报销超了：上限 200 元，这单填了 350 元。」Agent 的名字是「档案助理」。

1.1 聊天只给建议，干活要改到结果

承接章首：这条链从这里起。先把「只给建议」和「改到结果」分成两档，后面的四块才有地方可放。

聊天是一次生成：模型读到你的句子，写出一段建议。干活要多一次运行时动作：调用工具 lookupClause，把返回值当成结果。两档都可以在文字里写出「200 元」。能对上号的，是读数「是否调用工具」。

两档各留下什么

符号先定死。工具名是字段 toolName，值为 lookupClause。金额单位是元。这一节的调用次数只取 0 或 1：只聊天是 0，能干活是 1。规章上限是 limitYuan，等于 200。这单填写是 claimedYuan，等于 350。

提问用档案里的 ask：「报销上限是多少」。旁边放上教学句 sentence。只聊天时，模型可以回答：「建议你核对规章。这句话里写着上限 200 元。」200 来自句子本身，调用次数是 0。能干活时，运行时执行 lookupClause，命中 clauseNo 为 3 的「报销」，上限仍是 200 元；再与 350 元相减，超出 150 元。上限没有因为「能干了」就改成别的数。

结果看返回，不看口气

干活的标志是读数「是否调用工具」为「是」，工具名为 lookupClause。回复里出现 200 元，只说明教学句里写过这个数。

把只给建议当成已经查过规章
回复写着「上限 200 元，超出 150 元」，就当作第 3 条已经查过。 同时看「是否调用工具」。它为「否」时，200 元是教学句的复述。查过的凭据是 lookupClause 的返回：第 3 条报销，上限 200 元。两个 200 元相差 0 元，差别在有没有这一次返回。
只聊天，还是能干活切换分段

报销上限是多少。上周报销超了：上限 200 元，这单填了 350 元。

建议你核对规章。这句话里写着上限 200 元，这一次没有调用工具。

规章上限这格读的是档案里的 limitYuan。分段切换时它停在 200 元。

分段与读数
观察要点：① 切到「只聊天」，「是否调用工具」为否，回复只是建议。② 切到「能干活」，工具名变为 lookupClause，命中第 3 条报销。③ 两种分段下，规章上限都是 200 元。

可核对的对象就是这块读数，以及字段 toolName、limitYuan、clauseNo。分段按钮只切换档位，不改档案。

1.2 四块

承接上一节：能干活之后，还要知道是谁在查、谁在答。这一节把 Agent 收成四块，并用这笔报销各安一处。

本章的 Agent 是一个，名字是「档案助理」。它内部四块的英文和职责如下。金额单位仍是元，记忆的单位是「条」和「字」。

规划planner先查再答。本章只排这一次maxSteps 记为 4，留给第 4 章

用这一单把四块放好

大脑读入「上周报销超了：上限 200 元，这单填了 350 元。」它知道要回答 ask。规章上限不放在大脑里保管。

规划只写顺序：先查再答。先让工具查，再让大脑根据返回来答。字段 maxSteps 是 4，表示以后的循环最多 4 步。本章不开始循环。

记忆留下 memoryKeep = 3 条，一次能装的字数是 contextChars = 120。规章全文 handbookChars = 320 字。\(320 > 120\)，Course.agentMath.fitsContext(320) 不成立。教学句本身很短，放得进 120 字；全文放不进。所以记忆里留短记录，全文仍由工具去查。

工具执行 lookupClause，打开第 3 条「报销」，交回 limitYuan = 200。这单的 350 元留在填写额 claimedYuan 上。超出 150 元是两者相减，由规划安排「先查再减」，减法使用 Course.agentMath.overYuan()。

把四块并进一句提示词
写一句「你同时是大脑、规划、记忆和工具，上限是 200 元」，希望一次回复把四块都做完。 四块分开记账。上限只出现在工具返回里。规划栏始终是「先查再答」。并成一句之后，读数「是否调用工具」没有从「否」变成「是」，200 元又变成了句子里的文字。
第 1 章就拆成多个角色
再设一个报销专员、一个审核专员，各自记一个上限。 本章只有档案助理这一个 Agent，四块在它内部。两个角色各写一个上限时，常见情形是一个写 200 元、一个写 350 元，两边相差 150 元。角色拆分留到整门课走完之后再考虑。

点亮四块
观察要点：① 点亮大脑、规划或记忆时，「上限从哪块来」仍是工具。② 只有点亮工具，「这一块给出上限」才为是。③ 任意一块被点亮，规划职责都是先查再答，规章上限都是 200 元。

下面这个函数和演示用同一条规则：from 恒为「工具」，givesLimit 仅当点亮的名字是「工具」时为真，plan 恒为「先查再答」，limitYuan 恒为档案里的值。页面摘录与文件逐字相同，教程页不把该文件嵌进来执行。

/* 第 1 章 · 上限从哪块来。点亮哪一块都可以问；给出上限的只有工具，规划只负责先查再答。 */
function whereLimit(part) {
  var A = Course.data.agent;
  return {
    asked: '上限从哪块来',
    lit: part,
    from: '工具',
    givesLimit: part === '工具',
    plan: '先查再答',
    toolName: A.toolName,
    limitYuan: A.limitYuan,
    clauseNo: A.clauseNo
  };
}

示例代码：examples/ch01/where-limit.js

在已经载入本课运行时的环境里调用 whereLimit('规划') 与 whereLimit('工具')，比较 givesLimit。安装方式见 1.7 节，以你当前的文档为准。

1.4 把教学句拆成 200、350、150

承接上一节：档案已经整本列出。这一节只拆教学句里的三个金额，让「超了」对应到 150 元。

教学句是一整句：上周报销超了：上限 200 元，这单填了 350 元。冒号后面两截。单位都是元。

  • 「上限 200 元」对应 limitYuan = 200。这是规章允许的数。
  • 「这单填了 350 元」对应 claimedYuan = 350。这是单据上填写的数。
  • 超出是填写额减去上限。字段 overYuan 与函数 Course.agentMath.overYuan() 都是这个差。
\[\text{超出}=\text{claimedYuan}-\text{limitYuan}=350-200=150\]1.1

假设：两个金额都以元入库，且上限取规章、被减数取这单。页面上由函数填入的超出是 150 元，与字段 overYuan 相同。

350 元若按「分」入库，就变成 3.5 元，比这单少 100 倍。那时再减 200 元，得到的不是 150 元。校核量就是这个超出：它应当等于 150 元。

这一句怎么对上「超了」

350 比 200 多 150，所以「超了」成立。多出来的 150 元就是 overYuan。句子前半的「上限」两个字标的是 200，后半的「填了」标的是 350。

把 350 当成规章上限
看到句子里较大的 350，就把 limitYuan 记成 350。超出变成 350 − 350 = 0。 规章上限是 200 元，来自第 3 条。350 元是 claimedYuan。记反之后，超出少了 150 元，「超了」在账上消失。用式 (1.1) 回减：被减数是填写额，减数是规章上限。

1.5 四条规章各管一件事，上限只在第 3 条

承接上一节：150 元已经由 350 − 200 得到。这一节说明减数 200 只写在四条规章的第 3 条。

四条的名字在 clauseNames：考勤、请假、报销、差旅。clauseCount 是 4。每条只管一件事。报销上限不写进考勤，也不写进请假或差旅。命中条号 clauseNo 是 3，名称是报销。

问句「报销上限是多少」的向量是 query = \([3,1,0,0]\)。四条向量按条号依次是 \([0,1,0,0]\)、\([1,0,1,0]\)、\([3,1,0,0]\)、\([0,0,1,1]\)。维数 embedDim 是 4，问句和规章共用这 4 个分量。本章直接使用档案里的这些数，不另做一套编码。

相近程度用余弦。设问句为 \(\mathbf q\)，第 \(i\) 条为 \(\mathbf c_i\)。假设两者都是本课的 4 维向量，对应分量相乘再相加得到点积；分母是两个长度的乘积。长度为零时余弦记 0，本课四条的长度都不为零。

\[\cos(\mathbf q,\mathbf c_i)=\frac{\mathbf q\cdot\mathbf c_i}{\lVert\mathbf q\rVert\,\lVert\mathbf c_i\rVert}\]1.2

\(\lVert\mathbf q\rVert=\sqrt{3^2+1^2}=\sqrt{10}\)。四条分别是：

  • 第 1 条考勤：点积 \(1\)，长度为 \(1\)，余弦 \(1/\sqrt{10}\)；
  • 第 2 条请假：点积 \(3\times 1=3\)，长度为 \(\sqrt{2}\)，分母 \(\sqrt{10}\cdot\sqrt{2}=\sqrt{20}\)，余弦 \(3/\sqrt{20}\)；
  • 第 3 条报销：与问句相同，点积 \(10\)，长度 \(\sqrt{10}\)，余弦 \(1\)；
  • 第 4 条差旅：点积 \(0\)，余弦 \(0\)。
\[\cos_1=\frac{1}{\sqrt{10}},\quad \cos_2=\frac{3}{\sqrt{20}},\quad \cos_3=1,\quad \cos_4=0\]1.3

下标是条号。这四个数就是 Course.agentMath.scores() 返回的 score，顺序与 clauseNames 一致。右列小数由同一次调用填入，用来对照闭式。

条号名称向量闭式scores() 读数
1考勤\([0,1,0,0]\)\(1/\sqrt{10}\)—
2请假\([1,0,1,0]\)\(3/\sqrt{20}\)—
3报销\([3,1,0,0]\)\(1\)—
4差旅\([0,0,1,1]\)\(0\)—

topK 是 2，按余弦从高到低取两条。Course.agentMath.topK() 取到的是 第 3 条报销、第 2 条请假。因为 \(1 > 3/\sqrt{20} > 1/\sqrt{10} > 0\)。第 2 条进入前两名，只说明它比考勤更近；请假条文里仍然没有 200 元。上限只在第 3 条。

把向量维数写成某家模型广告里的维数
把 embedDim 写成广告里的 1536，觉得维数越大越能表示这句报销。 本课维数是 4，和 query、clauses 的长度一致。1536 维和 \([3,1,0,0]\) 无法按分量相乘，式 (1.2) 的点积做不成。维数以档案字段为准，不以广告文案为准。

分数只向 scores() 与 topK() 要，示例里不再手写第二套向量。

/* 第 1 章 · 四条规章的余弦与 topK。分数只来自 Course.agentMath，不另写一套向量。 */
function clauseScores() {
  return {
    scores: Course.agentMath.scores(),
    picked: Course.agentMath.topK()
  };
}

示例代码：examples/ch01/clause-scores.js

调用 clauseScores() 后，scores[2].score 为 1（第 3 条，下标从 0 计），picked 的前两条是第 3 条和第 2 条。

1.6 一次提问还不会自己循环，循环留给第 4 章

承接上一节：第 3 条已经能被查中，余弦是 1。这一节说明「查一次」还不是循环。

本章这一次提问的顺序是三拍：规划写下「先查再答」；工具 lookupClause 执行一次，返回第 3 条报销和上限 200 元；大脑用填写额 350 元减去该上限，写出超出 150 元。工具调用次数是 1。

档案里的 maxSteps 等于 4。它是第 4 章循环的步数上限：循环最多走 4 步，第 5 步不再发起。本章不把这一次提问拆成 4 轮，也不在提示词里要求模型「自己循环」。提示词里写上「请循环」，得到的仍是一次生成，读数「是否调用工具」不会因此变成多次。

单位：步。本章用掉的是 1 次工具调用，离 4 步上限还空着 3 步。这 3 步留在第 4 章，不在这里预支。

用聊天记录代替工具结果
把上一轮回复「建议你核对规章，上限好像是 200 元」贴到下一步，当作 lookupClause 的返回。 观察文本应是工具返回：条号 3，名称报销，上限 200 元。聊天记录里的 200 元没有条号。若模型改口说成 350 元，用聊天记录当观察就会把上限带偏 150 元。
这一章停在一次返回

循环、把观察写回下一步、走到第 4 步就停，都在第 4 章。这里只要能指出：本次结果是一次 lookupClause 返回，加上由它参与的那次减法。

本章避坑清单

  1. 用聊天记录代替工具结果。观察应是 lookupClause 的返回：第 3 条报销，上限 200 元。聊天里的「好像是 200 元」没有条号，改口后会把上限带偏。
  2. 另写一套金额。把上限写成 500 元、这单写成 800 元、超出写成 300 元，和档案相差 300 元、450 元、150 元。只读 limitYuan、claimedYuan 和 overYuan()。
  3. 第 1 章就拆成多个角色。报销专员和审核专员各记一个上限时，容易一个 200 元、一个 350 元。本章只有档案助理，四块在它内部。
  4. 把向量维数写成某家模型广告里的维数。embedDim 是 4。写成 1536 后，无法与 \([3,1,0,0]\) 做点积。
  5. 把只给建议当成已经查过规章。回复里出现 200 元时，先看「是否调用工具」。为「否」就是复述教学句。
  6. 把 350 当成规章上限。350 元是填写额。把它当上限，超出变成 0，比档案少 150 元。
  7. 把四块并进一句提示词。一句里同时声称自己是大脑、规划、记忆和工具，读数不会出现 lookupClause 的返回。
  8. 把某个编辑器菜单写成唯一安装法。本章不记录菜单路径。安装以你正在看的那份文档的当前步骤为准。

本章小结与延伸阅读

  • 聊天只给建议。回复里出现 200 元时，工具调用次数仍可以是 0。
  • 干活调用 lookupClause，命中第 3 条报销，规章上限 200 元。
  • Agent 在本章收成大脑、规划、记忆、工具。规划只负责先查再答。四块属于同一个档案助理。
  • 教学句拆成上限 200 元、这单 350 元、超出 150 元。超出由 overYuan() 计算。
  • 四条规章各管一件事。余弦依次为 \(1/\sqrt{10}\)、\(3/\sqrt{20}\)、\(1\)、\(0\)。topK 取第 3 条和第 2 条，上限仍只在第 3 条。
  • 向量是 4 维。全文 320 字、每片 80 字、共 4 片。记忆留 3 条，上下文 120 字。一次提问不循环，4 步留给第 4 章。
  • 页面演示与本机安装分开。语言和安装以当前文档为准。
