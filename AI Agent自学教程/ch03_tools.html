3.1 为什么聊天给不了档案里的上限

章首把链排成说明书、模型选择、运行时执行、观察。先停在聊天这一侧：问句到了，档案还没被查。

问题：用户问「报销上限是多少」。只靠模型的下一句回答，为什么还是没有档案里的上限？

符号与单位：问句读 agent.ask，全文是「报销上限是多少」。教学句读 agent.sentence。上限 limitYuan、填报 claimedYuan、超出 overYuan 的单位都是元，依次是 200、350、150。条目序号 clauseNo 从 1 数到 clauseCount 4。四条名字在 clauseNames：考勤、请假、报销、差旅。工具名 toolName 是 lookupClause。运行时全局名只用 Course。

用档案助理走一遍：教学句是「上周报销超了：上限 200 元，这单填了 350 元。」超出是 \(350-200=150\)，单位元，与 Course.agentMath.overYuan() 相同。这句话里已经出现「上限 200 元」这几个字，那是用户在叙述这单。档案里的上限是另一处：第 3 条「报销」的 limitYuan，数值也是 200。两个 200 相差 0 元，出处差一整条观察。聊天直接把叙述里的 200 写进回答时，工具结果还是空的，条目来源对不上第 3 条。

3.2 工具说明书写名字、参数和返回

聊天给不出条目来源。这一节把能查档案的那一个工具写成说明书，模型才知道可以选它。

问题：模型和运行时要对齐的说明书，最少写哪三栏？

符号与单位：名字 name 取 agent.toolName，字符串 lookupClause。参数只有 ask，类型是字符串，基准值是「报销上限是多少」。返回三格：clauseNo（序号）、name（条目名）、limitYuan（元）。该条没有报销上限时，limitYuan 为空。200 是查中第 3 条之后的返回值，不写进参数的默认值。

用档案助理走一遍：说明书准备好之后，问句仍是 agent.ask。名字栏对上 lookupClause。参数栏只留 ask 这一格，不把 200、350 或 150 预填进去。返回栏声明会交回序号、条目名和上限。真正的 200 要等 3.4 节执行之后才出现。考勤、请假、差旅在这张说明书里没有各自的金额；差旅被查到时，返回的是第 4 条，上限那一格为空。

const agent = Course.data.agent; const toolSpec = { name: agent.toolName, parameters: { ask: '要查的问句，字符串' }, returns: { clauseNo: '命中条目的序号', name: '条目名', limitYuan: '这一条的报销上限，单位是元；该条没有上限时为空' } }; // name 来自 agent.toolName，就是 lookupClause。 // 说明书只写名字、参数和返回。某一家接口的私有字段以该家文档原文为准。

可操作对象：打开 examples/ch03/tool-spec.js，核对 toolSpec.name 与 agent.toolName 是同一个字符串 lookupClause。parameters 里只有 ask。返回说明里有序号、条目名和上限，没有 350。

3.3 模型只决定调谁

说明书已经有了 lookupClause。模型这一步从说明书里选它，并填上 ask。

问题：模型这一步的输出里，允许出现哪些字段？

符号与单位：选择对象记为 choice。它有 name 和 parameters.ask。这一步没有 observation，因此没有 clauseNo，也没有以元为单位的 limitYuan。问句仍用 agent.ask。

用档案助理走一遍：输入是「报销上限是多少」。模型对照说明书，选出名字 lookupClause，参数 ask 原样填这句。输出到这里就停。四条规章还在运行时一侧。第 3 条的 200 元还没有被读出来。若选择对象里已经出现 limitYuan: 200，那是把下一步的观察提前写进了选择，条目来源仍然空着。

const agent = Course.data.agent; function modelSelects(question) { return { name: agent.toolName, parameters: { ask: question } }; } const choice = modelSelects(agent.ask); // choice.name 是 lookupClause。 // choice.parameters.ask 是「报销上限是多少」。 // 这里还没有 clauseNo，也没有 limitYuan。模型不读取规章文件。

示例代码：examples/ch03/model-select.js

选择里已经写上 limitYuan 200

可操作对象：对 agent.ask 做一次 modelSelects。检查返回对象的键是 name 和 parameters。name 为 lookupClause，ask 为「报销上限是多少」。对象里没有 limitYuan，也没有 clauseNo。

3.4 运行时才执行

模型已经交出 lookupClause 和 ask。数字要等运行时执行之后才出现。

问题：谁调用 lookupClause，返回写到哪里？

符号与单位：观察记为 observation。三格是 clauseNo、name、limitYuan（元）。执行者是运行时。模型停留在上一节的选择。answerOnce 里的 callCount 单位是次，本章为 1。

用档案助理走一遍：ask 为「报销上限是多少」时，运行时在四条里命中 agent.clauseNo，也就是 3。条目名是 clauseNames[2]，即「报销」。limitYuan 取 agent.limitYuan，即 200 元。claimedYuan 350 留在教学句，不写入观察。overYuan 150 也不写入。函数按整句相等来对：ask 既不是「差旅」，也不是这句全文时，clauseNo 为空，不能顺手写成第 3 条。

const agent = Course.data.agent; function lookupClause(ask) { if (ask === '差旅') { return { clauseNo: agent.clauseCount, name: agent.clauseNames[agent.clauseCount - 1], limitYuan: null }; } if (ask === agent.ask) { return { clauseNo: agent.clauseNo, name: agent.clauseNames[agent.clauseNo - 1], limitYuan: agent.limitYuan }; } return { clauseNo: null, name: null, limitYuan: null }; } function answerOnce(question) { const choice = { name: agent.toolName, parameters: { ask: question } }; const observation = lookupClause(choice.parameters.ask); return { callCount: 1, choice: choice, observation: observation }; } const once = answerOnce(agent.ask); // once.callCount 是 1。同一问句不再调用第二次。 // ask 为「报销上限是多少」时，clauseNo 是 3，name 是报销，limitYuan 是 200。 // ask 为「差旅」时，clauseNo 是 4，name 是差旅，limitYuan 为空。 // agent.claimedYuan 是 350，不在 observation 里。 // agent.overYuan 是 150，这次工具不计算它。 // 循环留到第 4 章。这里不按 maxSteps 继续发起。

示例代码：examples/ch03/lookup-once.js

把工具当成模型自己去读硬盘

用教学句里的 200 填进观察
跳过函数返回，把叙述中的 200 直接写成 observation.limitYuan，clauseNo 仍是空的。 观察三格一起从 lookupClause 的返回抄：序号 3、条目名报销、上限 200 元。少一格就不算查到第 3 条。

可操作对象：在加载了 Course 的环境里跑 examples/ch03/lookup-once.js。读 once.observation.clauseNo、once.observation.name、once.observation.limitYuan，应为 3、报销、200。再读 once.callCount，应为 1。

3.5 参数写成差旅就查错条

运行时会执行。它按 ask 的文字查，按你心里想问的那一条对不上号。

问题：参数写成「差旅」时，命中的是哪一条？

符号与单位：写错的 ask 是字符串「差旅」。写对的 ask 是 agent.ask 全文「报销上限是多少」。第 4 条的序号等于 agent.clauseCount，名字是 clauseNames[3]，即差旅。这一条的 limitYuan 为空，单位上没有「元」可以读。写对时上限是 200 元。

用档案助理走一遍：lookupClause('差旅') 得到 clauseNo 4、name 差旅、limitYuan 空。lookupClause(agent.ask) 得到 clauseNo 3、name 报销、limitYuan 200。两条结果的序号相差 1。报销上限一侧是 200 元，另一侧没有这个金额。只写条目名「报销」两个字，也不等于基准问句，函数落到最后一档，clauseNo 为空。

ask 写错仍当命中报销
ask 已经是「差旅」，返回的序号是 4，仍把条目名改成报销，并把上限写成 200 元。 先读观察里的 clauseNo 和 name。4 和差旅就停在差旅。报销上限只在序号为 3、条目名为报销时读取，数值是 200 元。
工具返回了第 4 条差旅仍拿来当上限
观察明确是第 4 条，回答仍写「报销上限 200 元」。 第 4 条不提供报销上限。limitYuan 为空时，回答里不出现 200 元。要改问句，把 ask 写成「报销上限是多少」，再执行一次，才会得到第 3 条和 200 元。

可操作对象：下面的分段每次只执行一次 lookupClause。读「命中条目」。差旅一侧是第 4 条，写对报销一侧是第 3 条。

ask 写成差旅 / 写对报销切换分段，读命中条目
观察要点：① ask 写成差旅时，命中条目是第 4 条，条目名是差旅。② ask 写对「报销上限是多少」时，命中条目是第 3 条，条目名是报销，报销上限是 200 元。③ 第 4 条没有报销上限，这一侧不能读出 200。④ 每一侧只执行一次 lookupClause。切换分段是在比较两个 ask，不是把同一问句再打一次。

3.6 结果送回后才能说 200

条目已经能查到。回答里的 200 元要等这份观察送回模型。

问题：观察还没送回时，回答里能不能写上限 200 元？

符号与单位：送回的对象就是 observation。回答中的上限要等于 observation.limitYuan，单位元，并且 clauseNo 为 3、条目名为报销。350 元是 claimedYuan。150 元是超出，算式 \(350-200=150\)。本章观察里没有这两个字段。

用档案助理走一遍：第一拍，模型交出 lookupClause 和 ask「报销上限是多少」，选择里没有金额。第二拍，运行时得到第 3 条、报销、limitYuan 200。第三拍，这份观察送回模型，回答才可以写上限 200 元，并注明来源是第 3 条。若在第二拍之前就把 200 写进回答，数字可以和档案相同，来源仍然是空的。若把 350 写进上限，比 limitYuan 多 150 元，用的是这单填报。

拍谁手上有什么能否说上限 200 元
1模型名字 lookupClause，ask「报销上限是多少」不能。还没有观察
2运行时第 3 条，报销，limitYuan 200观察已经产生，尚未送回
3模型看见观察上一拍的三格可以。来源写第 3 条
来源还是空的就宣布上限
第一拍结束就输出「上限 200 元」。调用次数是 0，和模型直接回答 200 却没有工具结果是同一种记录。 把观察三格送回之后再写 200 元。来源栏写第 3 条报销。3.1 节的空格子到这一拍才填上。
把 350 当成工具结果
观察送回之后，上限写成 350 元。这是教学句里的填报 claimedYuan。 工具结果里的金额只读 limitYuan，是 200 元。350 与 200 相差 150 元，那个差是超出，留在第 4 章计算，不装进这次观察。

可操作对象：切换「模型编造 / 调用工具」。两侧回答里都能看见 200 元。只读「上限来源」：后一侧才是第 3 条。

模型编造 / 调用工具切换分段，读上限来源
观察要点：① 两侧回答里都能看见 200 元。② 只有「调用工具」的上限来源是第 3 条报销，limitYuan 来自观察。③ 「模型编造」的 lookupClause 次数是 0，没有工具结果。④ 工具结果里没有 350。⑤ 超出 150 元不在这次观察里。

3.7 一次提问只发一次 lookupClause

观察可以送回了。同一次提问上，lookupClause 只出现一次。

问题：同一句「报销上限是多少」发两次，档案会不会更准？

符号与单位：callCount 的单位是次。本章基准是 1。同一问句再执行一次，次数变成 2，比基准多 1 次。观察内容仍是第 3 条和 200 元，多出来的那一次没有新条目，也没有把 200 改成别的数。

用档案助理走一遍：answerOnce(agent.ask) 内部只调用一次 lookupClause，callCount 写成 1。观察是第 3 条、报销、200 元。若把同一 ask 再送进函数一次，两次观察的 limitYuan 都是 200，序号都是 3，次数却是 2。档案没有因为多打一次而多出一条新规章。本章停在 1 次。示例在 examples/ch03/lookup-once.js 的 answerOnce。

同一问句连打两次
日志里 ask 都是「报销上限是多少」，lookupClause 出现 2 次。两次都返回第 3 条和 200 元。 一次提问保留第一次观察，callCount 记 1。200 元的来源已经是第 3 条，不需要第二份相同观察来确认。
用第二次相同结果覆盖第一次
两次都是 200 元，就把 callCount 改成 2，并说上限被核对过两遍。 次数和金额分开记。金额仍是 200 元，次数保持 1。多出来的 1 次不改变第 3 条。

可操作对象：在 answerOnce 里数 lookupClause 的调用，路径上是 1 次。再看返回的 callCount，也是 1。若你在外面用同一个 ask 再调一次，把两次的次数相加会得到 2，那已经超出本章这一问的基准。

3.8 这一次还不算循环

这一次提问的工具次数已经定为 1。它还没有进入想一步、做一步的循环。

问题：选择、执行、观察送回，这三拍算不算循环？

符号与单位：maxSteps 是 4，单位是步，留给第 4 章。本章这条轨迹的工具执行次数是 1，没有第二步去算超出。超出仍是 \(350-200=150\)，单位元，不在这次观察里。第 4 章才会先查规章，再算这 150 元，并且第 5 步不再发起。

用档案助理走一遍：三拍走完，回答可以引用第 3 条的 200 元。工具名只有 lookupClause，次数是 1。不把 callCount 改成 maxSteps 的 4，也不再发起下一次工具去计算 150。4 步是后面那一章的上界，和这一次观察的次数相差 3 步。把 150 说成 lookupClause 的返回，会比真实观察多出一个字段，金额也从 200 元换成了 150 元。

  1. 模型交出选择：lookupClause，ask「报销上限是多少」。
  2. 运行时执行一次，观察是第 3 条、报销、limitYuan 200。
  3. 观察送回。回答可以写上限 200 元。轨迹在这里停止。
把 callCount 写成 maxSteps 4
