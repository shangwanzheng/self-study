切片、落库与查询

规章全文 320 字切成 4 片，每片 80 字、重叠 0。查询和索引用同一个问句向量，只取前 2 片：第 3 条报销，然后是第 2 条请假。上限仍是 200 元。

这一章：切成 4 片，存上向量，只取前 2 片

第 5 章已经有问句 \([3,1,0,0]\) 和四条规章的余弦。本章把 320 字规章切成 4 片，每片 80 字，重叠 0，每片存上那一条的向量。查询用同一个问句向量，topK 取 2，顺序是第 3 条、第 2 条。回答里的上限来自第 3 条的 200 元。

先切开

320 ÷ 80 = 4。片与片之间不重叠。

再落库

每片记下编号和 4 维向量。索引用的问句向量就是查询用的那一个。

只取前 2

第 3 条必须在结果里。第 4 条余弦为 0，不进前 2 片。

6.1 为什么不把 320 字整段塞进一次提示

第 5 章把整句收成一个向量。这一节先看规章全文为什么不能整段送进一次上下文。

问题：档案里的规章有 handbookChars 320 字。一次上下文预算 contextChars 是 120 字。整段塞进去，后面的记忆和回答没有地方。

约定：放不放得下只调用 Course.agentMath.fitsContext。320 大于 120，结果为假。

基准算例：教学句仍是「上周报销超了：上限 200 元，这单填了 350 元。」全文 320 字对不上 120 字预算，所以要先切片，而不是把四条规章连同考勤、请假、差旅一起贴进这一次提示。

var agent = Course.data.agent;
var wholeFits = Course.agentMath.fitsContext(agent.handbookChars);

示例代码：examples/ch06/whole-prompt.js

把 4 片都送进回答

切完仍把 4 片原文全部贴回提示，和整段 320 字是同一件事。topK 是 2，回答只带前 2 片。

可操作对象：对 handbookChars 调用 fitsContext，读数应为假。

6.2 按 80 字切，重叠为 0

整段放不下。这一节按固定长度切开，片与片之间不重叠。

问题：切多长、重不重叠，决定片数。片数变了，后面「四条各一片」就对不上。

约定：每片 chunkChars 是 80 字。重叠是 0，不另造 20 字重叠。片数只调用 chunkCount()。

基准算例：\[320 / 80 = 4\] 片数是 4，不是 3.2。若把片长改成 100，320 除不尽 4，四条规章就不再是一片一条。

var agent = Course.data.agent;
var overlap = 0;
var count = Course.agentMath.chunkCount();

示例代码：examples/ch06/slice-80.js

切片长度改成 100，片数不再是 4

本课片长是 80。改成 100 以后，chunkCount() 不再是 4，第 3 条也不再稳稳落在第 3 片。

可操作对象：读 count，它应等于 4；读 overlap，它应等于 0。

6.3 四片各对一条规章

4 片已经数出来。这一节让每一片对应一条规章，不多也不少。

问题：片是存储单位，条是规章单位。两者若错位，查到的片就不是那一条的上限。

约定：片号从 1 计到 4，名称依次是考勤、请假、报销、差旅。每片长度都是 80 字。

基准算例：第 3 片名称是报销，上限 200 元写在这一片。第 1 片考勤、第 2 片请假、第 4 片差旅都不写这个上限。

var agent = Course.data.agent;
var pieces = agent.clauseNames.map(function (name, i) {
  return { chunk: i + 1, name: name, chars: agent.chunkChars };
});

示例代码：examples/ch06/four-pieces.js

只因关键词「上周」命中考勤

教学句里有「上周」。按词面会摸到第 1 片考勤。本课检索看的是第 5 章的余弦，不是这个词。

可操作对象：pieces[2].name 应为「报销」，pieces.length 应为 4。

6.4 落库存的是向量加片编号

四片已经对上四条。这一节把每一片的向量和片号存下去。

问题：查询时要比的是向量。库里如果只有原文、没有向量，查询就无法沿用第 5 章的余弦。

约定：每一行有片号 chunk、维数 dim、向量 vector。维数是 embedDim 4，向量就是档案里的 clauses，不换成广告里的维数。

基准算例：第 3 行向量是 \([3,1,0,0]\)，与问句相同。第 4 行是 \([0,0,1,1]\)。

var agent = Course.data.agent;
var rows = agent.clauses.map(function (vector, i) {
  return { chunk: i + 1, dim: vector.length, vector: vector.slice() };
});

示例代码：examples/ch06/store-row.js

落库后改了原文却不重算向量

原文改了，库里的向量还是旧的，查询仍按旧余弦排序。要更新，就按现在这一套 4 维句向量重算后再写入。

可操作对象：rows[2].dim 应为 4，rows.length 应为 4。

6.5 查询向量必须就是索引那一个

向量已经落库。这一节规定查询时用的问句向量，就是索引时用的那一个。

问题：索引用一套、查询用另一套，余弦比的不是同一件事，第 3 条不必再是第一名。

约定：索引和查询都用 query \([3,1,0,0]\)。sameSet 为真，表示两边分量相同。

基准算例：同一套时，topK() 第一名是第 3 条。教学对照若改用 \([0,0,1,1]\)，第一名变成第 4 条。这个对照向量不是档案里的新字段。

var agent = Course.data.agent;
var indexQuery = agent.query.slice();
var askQuery = agent.query.slice();
var sameSet = indexQuery.join(',') === askQuery.join(',');

示例代码：examples/ch06/same-vector.js

换一套查询向量 / 用同一套切换分段
观察要点：① 「用同一套」时，问句向量是 \([3,1,0,0]\)，第一名是第 3 条报销。② 「换一套查询向量」时，对照向量是 \([0,0,1,1]\)，第一名变成第 4 条。③ 两种读数都调用 Course.agentMath.cosine，不另写一套小数。④ 只有同一套时，上限仍跟第 3 条走。
用另一个模型算问句向量

索引是这套 4 维句向量，查询却换成另一家模型的向量，分量对不上。sameSet 必须为真，才沿用第 5 章的四个余弦。

可操作对象：读 sameSet，它应为真。再在演示里切到对照向量，看第一名从 3 变成 4。

6.6 取前 2 片

同一套向量已经对齐。这一节只取余弦最高的 2 片。

问题：topK 是 2。取 4 片等于把切片白做了。

约定：排序和截取只调用 Course.agentMath.topK()。不把 topK 改成 4 还说成取前 2。

基准算例：返回顺序是第 3 条，然后第 2 条。因为余弦 \(1 > 3/\sqrt{20} > 1/\sqrt{10} > 0\)。

var picked = Course.agentMath.topK();

示例代码：examples/ch06/top-two.js

取前 2 片 / 取全部 4 片切换分段
观察要点：① 「取前 2 片」的编号是 3 和 2，片数读数是 2。② 「取全部 4 片」会把第 1 条和第 4 条也带上，片数读数是 4，这是要避开的做法。③ 两种模式的排序都来自 scores()。④ 前 2 片里的第一名仍是第 3 条。
把 topK 改成 4 还说是取前 2

档案里的 topK 是 2。topK() 的长度就是这个数。改成 4 之后，差旅那一片也会进回答。

可操作对象：picked[0].clause 应为 3，picked[1].clause 应为 2，picked.length 应为 2。

6.7 第 3 条必须在结果里，第 4 条不在

前 2 片已经取到。这一节核对第 3 条在、第 4 条不在。

问题：第 4 条余弦是 0。把它放进结果，回答就会掺进差旅。

约定：hasClause3 为真，hasClause4 为假。0 表示不相关，不是查询失败。

基准算例：第 4 条向量 \([0,0,1,1]\) 与问句点积为 0，所以进不了前 2 名。第 3 条余弦为 1，排第一。

var picked = Course.agentMath.topK();
var hasClause3 = picked.some(function (row) { return row.clause === 3; });
var hasClause4 = picked.some(function (row) { return row.clause === 4; });

示例代码：examples/ch06/keep-clause3.js

检索不到就编一个 200

前 2 片里若没有第 3 条，不能凭教学句里出现过的 200 直接回答。本课同一套向量下第 3 条一定在；不在就重新核对向量，而不是编上限。

可操作对象：读 hasClause3 与 hasClause4，应分别为真和假。

6.8 拿到的上限仍是 200，不是第 2 条请假的内容

第 2 条也在前 2 片里。这一节把上限从第一名读出来，不从第二名读。

问题：第 2 条请假比考勤更近，所以进了前 2。请假条文里没有 200 元。

约定：只有第一名的片号等于 clauseNo 3 时，limitYuan 才取档案里的 200。

基准算例：第一名是第 3 条报销，上限是 200 元。第 2 条留在结果里供对照，不提供上限。超出仍是 \(350-200=150\)，这一步还不写进检索结果。

var agent = Course.data.agent;
var picked = Course.agentMath.topK();
var limitYuan = picked[0].clause === agent.clauseNo ? agent.limitYuan : null;

示例代码：examples/ch06/limit-stays.js

把第 2 条当成上限条款

前 2 片的第二名是请假。用它回答「报销上限是多少」，上限就离开了第 3 条。上限只在片号等于 3 的那一行。

可操作对象：limitYuan 应为 200。若第一名不是第 3 条，这个值是 null，不能改填 200。

本章避坑清单

  1. 把 320 字整段或切完的 4 片全部送进一次回答。
  2. 把片长改成 100，或把重叠写成 20，使片数不再是 4。
  3. 只因「上周」命中考勤，而不看余弦。
  4. 索引用一套向量、查询用另一套，或落库后改了原文却不重算向量。
  5. 把 topK 改成 4 还说是取前 2；第 4 条余弦为 0，不进结果。
  6. 检索里没有第 3 条时编一个 200，或把第 2 条请假当成上限条款。
