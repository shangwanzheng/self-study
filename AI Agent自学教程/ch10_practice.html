10.1 从教学句抽出三个整数

全课用的仍是这一句。这一节先把它收成三个整数字段。

问题：散文接不住后续的减法和工具。缺一个字段就停。

约定：字段名是 limitYuan、claimedYuan、overYuan。超出等于填写额减上限。

基准算例：200、350、150。三个都是整数。缺任何一个，ok 为假。

function threeFields(agent) {
  const found = String(agent.sentence).match(/\d+/g);
  const limitYuan = found && found.length > 0 ? Number(found[0]) : undefined;
  const claimedYuan = found && found.length > 1 ? Number(found[1]) : undefined;
  const overYuan = limitYuan !== undefined && claimedYuan !== undefined ? claimedYuan - limitYuan : undefined;
  const fields = { limitYuan: limitYuan, claimedYuan: claimedYuan, overYuan: overYuan };
  const missing = ['limitYuan', 'claimedYuan', 'overYuan'].filter(function (key) {
    return fields[key] === undefined;
  });
  if (missing.length) return { ok: false, missing: missing };
  return { ok: true, fields: fields };
}

示例代码：examples/ch10/three-fields.js

缺字段仍继续

missing 非空时不要调用工具。下一节的 lookupOnce 只接已经齐了的这三个数。

可操作对象：对 Course.data.agent 调用 threeFields，ok 应为真，overYuan 应为 150。

10.2 调一次 lookupClause，拿到 200

三个字段已经齐了。这一节只调用一次工具。

问题：模型自己说出的 200 不是观察。上限来自工具返回的第 3 条。

约定：calls 是 1。工具名是 lookupClause。条号是 3，名称是报销。

基准算例：返回的 limitYuan 是 200，不是 350。

function lookupOnce(agent) {
  return {
    tool: agent.toolName,
    calls: 1,
    clauseNo: agent.clauseNo,
    name: agent.clauseNames[agent.clauseNo - 1],
    limitYuan: agent.limitYuan
  };
}

示例代码：examples/ch10/lookup-once.js

没有工具结果就回答 200

教学句里写着 200，仍要等 lookupClause 的返回。没有这次观察，回答就停住。

可操作对象：calls 应为 1，clauseNo 应为 3，limitYuan 应为 200。

10.3 取前 2 片，上限来自第 3 条

工具已经交回第 3 条。这一节按同一套问句向量取前 2 片。

问题：第 2 片也会进来。上限不能改从请假那一条读。

约定：片号顺序与 Course.agentMath.topK() 一致：第 3 条，然后第 2 条。limitFrom 是 clauseNo。

基准算例：打开本章时，页面先用 Course.agentMath.topK() 核对前两片。下面的函数用同一套点积和范数，结果仍是第 3 条和第 2 条，上限 200。

function firstTwo(agent) {
  function dot(u, v) {
    let s = 0;
    for (let i = 0; i < u.length; i++) s += u[i] * v[i];
    return s;
  }
  function norm(u) {
    return Math.sqrt(dot(u, u));
  }
  const qn = norm(agent.query);
  const ranked = agent.clauses.map(function (v, i) {
    const n = qn * norm(v);
    return { clause: i + 1, score: n ? dot(agent.query, v) / n : 0 };
  }).sort(function (a, b) { return b.score - a.score; });
  const picked = ranked.slice(0, agent.topK);
  return {
    clauses: [picked[0].clause, picked[1].clause],
    limitFrom: agent.clauseNo,
    limitYuan: agent.limitYuan
  };
}

示例代码：examples/ch10/first-two.js

索引和查询不是同一套向量

这里的排序用的是档案里的 query。换一套向量，第一名可以不再是第 3 条，上限就没有着落。

可操作对象：调用 Course.agentMath.topK()，前两片应是第 3 条和第 2 条，并与 firstTwo 的 clauses 相同。

10.4 记忆压成 3 条并放进 120 字

前 2 片已经取到。这一节留下 3 条，并确认它们放得进 120 字。

问题：规章全文 320 字放不进预算。记忆只留上限、超出和前 2 片的编号。

约定：keep 等于 memoryKeep 3。chars 不超过 contextChars 120 时 fits 为真。

基准算例：三条写的是第 3 条上限 200 元、这单 350 元超出 150 元、前 2 片为第 3 条与第 2 条。

function memoryThree(agent) {
  function dot(u, v) {
    let s = 0;
    for (let i = 0; i < u.length; i++) s += u[i] * v[i];
    return s;
  }
  function norm(u) {
    return Math.sqrt(dot(u, u));
  }
  const qn = norm(agent.query);
  const ranked = agent.clauses.map(function (v, i) {
    const n = qn * norm(v);
    return { clause: i + 1, score: n ? dot(agent.query, v) / n : 0 };
  }).sort(function (a, b) { return b.score - a.score; });
  const items = [
    '第' + agent.clauseNo + '条' + agent.clauseNames[agent.clauseNo - 1] + '上限' + agent.limitYuan + '元',
    '这单' + agent.claimedYuan + '元超出' + agent.overYuan + '元',
    '前' + agent.topK + '片为第' + ranked[0].clause + '条与第' + ranked[1].clause + '条'
  ];
  const text = items.join('。') + '。';
  return {
    keep: items.length,
    chars: text.length,
    fits: items.length === agent.memoryKeep && text.length <= agent.contextChars,
    text: text
  };
}

示例代码：examples/ch10/memory-three.js

把 320 字塞进 120 字

fits 看的是这 3 条拼出来的长度，不是 handbookChars。全文不进这一次记忆。

可操作对象：keep 应为 3，fits 应为真，文本里应有 200 和 150。

10.5 走到第 4 步前先看超出

记忆已经压好。这一节在写出回答之前先看超出。

问题：第 4 步是回答。超出大于 0 时，回答不能抢在确认前面。

约定：四步仍是规划、行动并观察、算出超出并等待、确认后回答。maxSteps 是 4。第 5 步不发起。

基准算例：超出是 \(350-200=150\)，hold 为真。startFifth 为假。

function beforeStepFour(agent) {
  const overYuan = agent.claimedYuan - agent.limitYuan;
  return {
    aboutTo: agent.maxSteps,
    maxSteps: agent.maxSteps,
    overYuan: overYuan,
    hold: overYuan > 0,
    fifthStep: agent.maxSteps + 1,
    startFifth: false
  };
}

示例代码：examples/ch10/before-step-four.js

超过 4 步

fifthStep 是 5，只用来标出不再发起的那一步。startFifth 保持假，不把 maxSteps 改成 5。

可操作对象：overYuan 应为 150，hold 应为真，maxSteps 应为 4。

10.6 未确认不出最终回答

超出已经算出来。这一节在人确认之前把最终回答留空。

问题：150 已经知道了，仍不能先给一句草稿答案。

约定：confirmed 不是真时，answered 为假，text 是空字符串。

基准算例：未确认的返回是 { answered: false, text: '' }。

function gateAnswer(agent, confirmed) {
  if (!confirmed) return { answered: false, text: '' };
  return {
    answered: true,
    text: '上限' + agent.limitYuan + '元，超出' + agent.overYuan + '元。'
  };
}

示例代码：examples/ch10/gate-answer.js

跳过确认 / 先确认切换分段
观察要点：① 「跳过确认」时最终回答已经出现，读数标红。② 「先确认」且尚未确认时，最终回答为空。③ 点「人工确认」之后，回答才同时写出 200 和 150。④ 两种模式下上限仍是档案里的 200，不新造金额。
超出 150 却不等人

hold 为真时必须先走本节的门槛。跳过确认得到的句子不能当作最终回答。

可操作对象：gateAnswer(agent, false).text 应为空字符串。

10.7 确认后回答写出 200 与 150

人已经确认。这一节才把两个数写进同一句。

问题：只写上限，读者看不到超了多少；只写超出，读者看不到规章边界。

约定：回答同时含 limitYuan 和 overYuan。wroteLimit 和 wroteOver 都为真。

基准算例：句子是「上限200元，超出150元。」不把 350 写进上限的位置。

function answerAfterConfirm(agent) {
  const text = '上限' + agent.limitYuan + '元，超出' + agent.overYuan + '元。';
  return {
    text: text,
    wroteLimit: text.indexOf(String(agent.limitYuan)) !== -1,
    wroteOver: text.indexOf(String(agent.overYuan)) !== -1
  };
}

示例代码：examples/ch10/answer-after.js

把 350 当成上限

350 是这单填写额。回答里的上限仍是工具交回的 200，超出仍是 150。

可操作对象：wroteLimit 与 wroteOver 都应为真。

10.8 两个角色仍读同一个上限

回答已经能写出两个数。这一节让查档的和核对的读同一份规章。

问题：两个角色若各写一个上限，课程里就出现了第二份 200。

约定：角色是「查档的」和「核对的」。上限只在规章里有 1 份时，copies 是 1，limitYuan 仍是 200。

基准算例：各写一份时 copies 是 2，这是要避开的做法。数值即使都写成 200，份数也不该是 2。

function sharedLimit(agent, eachWrites) {
  const roles = ['查档的', '核对的'];
  return {
    roles: roles,
    copies: eachWrites ? roles.length : 1,
    limitYuan: agent.limitYuan
  };
}

示例代码：examples/ch10/shared-limit.js

两个角色各写上限 / 上限只在规章切换分段
观察要点：① 「各写上限」时份数是 2，读数标红。② 「上限只在规章」时份数是 1。③ 两种模式显示的金额都是 200，不新造第二个数。④ 查档的和核对的名字不变。
两个角色各写一个上限

核对的再抄一份 200，就和规章里的那一份分成了两处。以后一处改了，另一处仍是旧的。

可操作对象：sharedLimit(agent, false).copies 应为 1，limitYuan 应为 200。

10.9 先读报销技能，不把差旅技能装进这一次

上限只有一处。这一节决定这一次提示词里装进几个技能。

问题：技能有 2 个：报销和差旅。一次都装进去，差旅会挤进这句报销。

约定：skillLoaded 是 1。先读的名字是报销，留在外面的是差旅。

基准算例：loaded 是 ['报销']，leftOut 是 ['差旅']。

function loadSkills(agent) {
  const names = [agent.clauseNames[agent.clauseNo - 1], agent.clauseNames[agent.clauseCount - 1]];
  const loaded = names.slice(0, agent.skillLoaded);
  return {
    skillCount: agent.skillCount,
    skillLoaded: loaded.length,
    loaded: loaded,
    leftOut: names.slice(loaded.length)
  };
}

示例代码：examples/ch10/one-skill.js

两个技能一次装进

skillCount 是 2，表示一共有两个文件。skillLoaded 是 1，表示这一次只读报销。不要把差旅正文贴进这次提示。

可操作对象：skillLoaded 应为 1，leftOut[0] 应为「差旅」。

10.10 对着清单核对，不再新造数

技能也只装了 1 个。这一节把全课用过的数对一遍，不引入新的金额或步数。

问题：走到最后若再写一个上限或再加一步，前面九章的读数就对不上。

约定：核对函数只读档案和 Course.agentMath.overYuan()。不在函数里写死第二套数。

基准算例：上限 200，填写 350，超出 150，条号 3，前 2 片，最多 4 步，记忆 3 条，120 字，技能 2 个先读 1 个，全文 320 字，工具名 lookupClause。

function practiceCheck(agent, math) {
  return {
    limitYuan: agent.limitYuan,
    claimedYuan: agent.claimedYuan,
    overYuan: math.overYuan(),
    clauseNo: agent.clauseNo,
    topK: agent.topK,
    maxSteps: agent.maxSteps,
    memoryKeep: agent.memoryKeep,
    contextChars: agent.contextChars,
    skillCount: agent.skillCount,
    skillLoaded: agent.skillLoaded,
    handbookChars: agent.handbookChars,
    toolName: agent.toolName
  };
}
