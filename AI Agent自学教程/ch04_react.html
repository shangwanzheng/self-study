第 4 章 · 对象与结构

思考与行动的循环

档案助理回答「上周报销超了多少」时，一次查规章只交出上限。先想到要查，再调用工具看见 200 元，然后用填报的 350 元减去它，第 4 步写下超出 150 元，循环停在这里。

预计学习 90 分钟 前置：第 2、3 章 分步演示 2 个
  • 说清一次 lookupClause 交出的是上限 200 元，超出 150 元要等后面的减法。
  • 会把一步记进思考、行动、观察三格，观察格只接受工具返回。
  • 用 maxSteps = 4 走完教学句：想到要查、调用后看到 200、350 减 200 得 150、写出回答。
  • 第 5 步读到停止；问句「报销上限是多少」只调用一次。
  • 回答同时留下上限 200 元和超出 150 元。

这一章：想、做、看观察、再想，到第 4 步停

档案助理面对的是同一笔报销。教学句是「上周报销超了：上限 200 元，这单填了 350 元。」送给工具的问句 ask 是「报销上限是多少」。工具名是 lookupClause。步数上限 maxSteps 是 4。这一章只把这一笔走成一条链：先想，再做，看见观察，再想一次，第 4 步写出回答后停。

1 想

第 1 步写下「想到要查规章」。这一步还没有上限，也不调用工具。

2 做

第 2 步调用 lookupClause，问句用这一次的 ask。

3 看观察

观察格写下上限 200 元。这个 200 才是后面的减数。

4 再想并停

第 3 步用 350 减 200，得到超出 150 元。第 4 步写出回答。第 5 步不再发起。

金额单位都是元。填报金额 claimedYuan 是 350，观察里的上限 limitYuan 是 200，超出 overYuan 是 150。三个数都在 Course.data.agent 里，超出也可以用 Course.agentMath.overYuan() 现算。同一句 ask 不要再查第二次。

4.1 一次工具调用解决不了「超了多少」

章首把这条链定成四步。这一节先看第 2 步那一次调用交回了什么，以及它为什么还答不出「超了多少」。

问题：工具已经返回之后，超出还缺哪一步？

符号与单位：工具名 toolName 是 lookupClause。问句 ask 是「报销上限是多少」。上限 limitYuan、填报 claimedYuan、超出 overYuan 的单位都是元。maxSteps 计步，本课是 4，没有元这个单位。教学句 sentence 整句给人读；送进工具的是 ask，两句各留各的。

用基准算例走一遍：档案助理听到「上周报销超了：上限 200 元，这单填了 350 元。」一次 lookupClause 的返回是 { limitYuan: 200 }。200 元回答的是上限。问句要的超出是填报减去上限。这次返回里没有 150。所以第 2 步结束时，循环还留着第 3 步的减法和第 4 步的回答。maxSteps 给出 4 步，用来装下想、调用、相减、回答，用来把同一次查询重复四遍则对不上这四步的分工。

把返回的 200 元填进超出

观察格里的 200 元是上限。把它抄到超出，读者会以为这单超了 200 元。基准里的超出是 150 元，要等 350 减 200。一次调用结束时，超出还没写出来。

在同一次返回里另编 150

lookupClause 这次只交 limitYuan。超出由第 3 步的思考格计算，计算用的减数来自观察格。返回对象里再塞一个 150，工具契约和减法就各写了一套超出。

可操作对象：在页面脚本里读 Course.data.agent 的 toolName、ask、limitYuan、claimedYuan、maxSteps。超出调用 Course.agentMath.overYuan()，结果应等于 agent.overYuan，都是 150。

4.2 思考、行动、观察三格

一次调用只留下上限 200 元。这一节规定这一步要记进哪三格，观察格只接受工具返回。

问题：同一步里，准备做什么、调用了什么、工具交回了什么，各写在哪里？

符号与单位：思考格记这一步的打算，行动格记工具名，观察格记返回值。思考和行动没有单位。观察里的 limitYuan 单位是元。三格是记录的形状；maxSteps 另计已经走了几步。第 2 步同时占行动格和观察格：调用写进行动格，返回写进观察格。

用基准算例走一遍：第 1 步只填思考格，内容是「想到要查规章」。第 2 步填行动格 lookupClause，问句仍是「报销上限是多少」。运行时执行后，观察格写成上限 200 元。调用之前，观察格是空的。

思考第 1 步：想到要查规章。第 3 步才会写下减法。
行动第 2 步：调用 lookupClause。工具名来自 agent.toolName。
观察第 2 步返回之后：上限 200 元。这一格在返回前保持空白。
思考和观察写成同一句

思考格可以写「要去查上限」。把「上限 200 元」同时抄进观察格，两格就分不开来源。观察格在 lookupClause 返回前应保持空白。

观察写成模型自己的猜测

模型可以在思考格里估计一个上限。那个估计不能当作 limitYuan。观察格只填写这次工具返回的 200 元。各家运行时把返回放进哪一个日志字段，以该运行时文档原文为准；本课的观察格就是返回里的 limitYuan。

可操作对象：记一步时准备三个字段：thought、action、observation。第 1 步只有 thought。第 2 步的 action 等于 lookupClause，observation.limitYuan 等于 200。

4.3 用这四步走完教学句

三格的写法已经固定。这一节按第 1 步到第 4 步把教学句走完，并读出当前步能不能回答。

问题：从「想到要查规章」到写出回答，四步各自留下什么？

符号与单位：步号从 1 计到 4，与 maxSteps 对齐。金额仍是元。可以回答的读数只有两个字面：第 4 步是「可以」，第 1 步到第 3 步是「还不能」。第 3 步虽然已经算出 150，回答这句话留到第 4 步才落笔。

用基准算例走一遍：教学句不变。四步连起来是一条链。

步格写下的内容是否已经可以回答
1思考想到要查规章还不能
2行动、观察调用 lookupClause，观察上限 200 元还不能
3思考350 − 200 = 超出 150 元还不能
4回答上限 200 元，超出 150 元可以
四步之后的标志

steps.length 与 maxSteps 都是 4 时，finished 为 true。数组里没有第 5 步。第 5 步为何读成停止，留到 4.6 节；这里先把四步走满。

第 1 步就调用工具

第 1 步的记录是思考「想到要查规章」。这一步把 lookupClause 写进行动格，查询就提前发生，后面的第 2 步会变成第二次调用。同一句 ask 只应出现在第 2 步。

四步挤进同一次调用

一次返回同时带上思考、200、150 和回答，maxSteps 的 4 步就没有逐步可对的记录。先有第 1 步的思考，再有第 2 步的观察，然后才有第 3 步的 150 和第 4 步的回答。

可操作对象：下面这份脚本按基准数字走完四步。overYuan 由 claimedYuan - limitYuan 得到，结果是 150。finished 在长度等于 4 时为 true。

const maxSteps = 4;
const claimedYuan = 350;
const ask = '报销上限是多少';
const toolName = 'lookupClause';

function lookupClause(askText) {
  if (askText === ask) return { limitYuan: 200 };
  return null;
}

const steps = [];
steps.push({ step: 1, thought: '想到要查规章' });
const observation = lookupClause(ask);
steps.push({ step: 2, action: toolName, observation: observation });
const limitYuan = observation.limitYuan;
const overYuan = claimedYuan - limitYuan;
steps.push({ step: 3, claimedYuan: claimedYuan, limitYuan: limitYuan, overYuan: overYuan });
steps.push({ step: 4, answer: '上限 ' + limitYuan + ' 元，超出 ' + overYuan + ' 元' });
const finished = steps.length === maxSteps;

示例代码：examples/ch04/four-steps.js

走到第 1 至第 4 步切换分段
观察要点：① 读数有两格：当前步，以及是否已经可以回答。② 第 1 步只有「想到要查规章」，回答读数是还不能。③ 第 2 步出现观察上限 200 元，仍然还不能；第 3 步出现超出 150 元，回答仍留在下一步。④ 切到第 4 步，读数变为可以，回答同时写出上限 200 元和超出 150 元。

4.4 观察里的 200 才能拿来相减

第 2 步的观察格已经写下上限 200 元。这一节只用这个 200 做减法，得到超出 150 元。

问题：350 应该减去哪一个 200？

符号与单位：被减数 claimedYuan 是这单填报的 350 元。减数 limitYuan 取观察格，是 200 元。差 overYuan 的单位仍是元。教学句里也写着上限 200 元，它和工具返回是同一个基准数。减法读取的是观察格里的那一个；教学句用来核对两边都是 200。

用基准算例走一遍：观察格为 { limitYuan: 200 } 之后，第 3 步计算

\[ \mathrm{overYuan}=\mathrm{claimedYuan}-\mathrm{limitYuan}=350-200=150 \]

假设写在式子旁边：limitYuan 已经放在观察格里，claimedYuan 是教学句里的填报金额。两边单位都是元，所以可以直接相减。Course.agentMath.overYuan() 做的就是这道减法，结果与 agent.overYuan 同为 150。

减法差本课是否采用
350 − 观察里的 200150 元采用，记为 overYuan
350 − 3500 元不采用，减数没有用观察
观察格仍空白时写下 150150 元不采用，差没有观察来源
没有观察就写出 150

350 减 200 的差确实是 150，但减数要先出现在观察格。观察还空着就写出 150，这个 150 是提前写下的结果。正确顺序是第 2 步先得到 200，第 3 步再减。

用 350 减 350 得到 0

claimedYuan - claimedYuan 的差是 0 元。两个 350 都是填报金额，上限没有参加运算。超出应是 150 元。脚本里这个错误差叫 sameOnSame，它不写入回答。

可操作对象：overYuan 来自 observation.limitYuan。sameOnSame 是 0，留在一旁对照。

const claimedYuan = 350;
const observation = { limitYuan: 200 };
const overYuan = claimedYuan - observation.limitYuan;
const sameOnSame = claimedYuan - claimedYuan;

示例代码：examples/ch04/from-observation.js

4.5 第 4 步是回答，不是再查一次

第 3 步已经得到超出 150 元。这一节把第 4 步用来写回答，步号仍然是 4，工具不再调用。

问题：150 已经算出来之后，第 4 步的记录里应该有什么？

符号与单位：第 4 步的字段是 answer，内容是一句中文，里面带两个金额：上限 200 元、超出 150 元。这一步没有 action。步号 4 等于 maxSteps，所以这一步允许开始；它开始之后做的事是回答。

用基准算例走一遍：第 3 步的记录是 { step: 3, claimedYuan: 350, limitYuan: 200, overYuan: 150 }。第 4 步接上这一个 150，写成「上限 200 元，超出 150 元」。问句「报销上限是多少」已在第 2 步送出。第 4 步再送一次，调用次数会变成 2，回答句也让给了第二次查询。

把第 4 步再用来查一次

第 4 步若写成 { step: 4, action: 'lookupClause' }，回答没有地方落笔，同一句 ask 也被查了第二次。上限在第 2 步的观察里已经是 200 元，第 4 步用它和 150 元组成回答。

回答步再放一个行动格

四步脚本里，第 4 步只有 answer。再加 action 就会和「这一步是回答」抢同一条记录。150 元留在第 3 步，第 4 步只负责把上限和超出写进同一句。

可操作对象：对照 examples/ch04/four-steps.js 的最后一次 push。那一条的 step 是 4，字段名是 answer。读数「是否已经可以回答」在这一步变成可以。

4.6 第 5 步停止

第 4 步的回答已经写下，finished 为 true。这一节看第 5 步为什么不再发起。

问题：还想再查一次时，第 5 步的读数是什么？

符号与单位：maxSteps 保持 4。步号 n 大于 4 时，这一步的 started 为 false，读数 reading 为「停止」。步号 4 不大于 4，started 为 true，读数是「进行」，因为第 4 步就是允许写下的回答。停止不改变 200 和 150，也不把超出改成 0。

用基准算例走一遍：beginStep(4) 得到 { step: 4, started: true, reading: '进行' }。beginStep(5) 得到 { step: 5, started: false, reading: '停止' }。第 5 步没有调用 lookupClause，ask 仍是第 2 步那一次。若把 maxSteps 改成 5，beginStep(5) 的读数会变成「进行」，第 5 步就发起了。本课不改这个数。

超过 4 步还继续

第 4 步已经可以回答。再发起第 5 步，循环就多出一次本课没有安排的行动。正确读数是停止，已写下的回答仍是上限 200 元、超出 150 元。

循环不停，或把 maxSteps 改成别的数

停不下来时，第 5 步仍去调用工具。把 maxSteps 改成 5、3 或 200，都会让「第 5 步停止」这句读数失效。200 是上限的元，不是步数。本课 Course.data.agent.maxSteps 保持 4。运行时若用别的参数名表示步数上限，以该文档原文为准；本课只认 maxSteps。

可操作对象：at5.reading 为「停止」，at5.started 为 false。at4 仍允许进行。

const maxSteps = 4;

function beginStep(n) {
  if (n > maxSteps) return { step: n, started: false, reading: '停止' };
  return { step: n, started: true, reading: '进行' };
}

const at4 = beginStep(4);
const at5 = beginStep(5);

示例代码：examples/ch04/stop-at-max.js

还想查第 5 步，或停在 4切换分段
观察要点：① 选「停在 4」：当前停在第 4 步，第 5 步读数是未发起，回答已经可以。② 选「还想查第 5 步」：第 5 步读数是停止，这一步没有调用工具。③ 两种选择下 maxSteps 都是 4，同一句 ask 的调用次数都是 1。④ 停止之后，上限仍是 200 元，超出仍是 150 元。

4.7 同一 ask 不重复调用

第 5 步已经停住。这一节再看同一句 ask：就算有人把它再送一次，lookupClause 也不再交一个新的上限。

问题：「报销上限是多少」在这条链里出现几次调用？

符号与单位：ask 是字符串「报销上限是多少」，按字面比较。第一次返回 limitYuan 200 元，calledAgain 为 false。同一字符串第二次进入时，calledAgain 为 true，返回里不再带新的上限。调用次数是 1，单位是次，和元、步都分开计。

用基准算例走一遍：第 2 步的那一次就是 first。first.limitYuan 是 200，first.calledAgain 是 false。若第 4 步或第 5 步把同一句再送进去，得到的是 second：calledAgain 为 true。观察格仍保留第一次的 200 元，不会被第二次的空返回改写。第 5 步本身已经由 maxSteps 停住；这一节的重复检查是另一道闸，专门挡住同一个 ask。

同一 ask 的调用次数变成 2

第 2 步已经查过「报销上限是多少」。第 4 步再查，次数变成 2，而且占用了回答步。第二次返回没有新的 limitYuan，上限仍然只能用第一次观察到的 200 元。

再确认一次同一句问话

上限已经在观察格里。再把同一句 ask 送进 lookupClause，不会得到第二个 200，也不会算出 150。150 来自第 3 步的减法。问句字面不同的另一次查询不在本课这条链里；本课只规定这一句不重复。

可操作对象：连续调用两次同一个 ask，看 first 与 second。

const ask = '报销上限是多少';
const called = {};

function lookupClause(askText) {
  if (called[askText]) return { calledAgain: true };
  called[askText] = true;
  if (askText === ask) return { calledAgain: false, limitYuan: 200 };
  return { calledAgain: false, limitYuan: null };
}

const first = lookupClause(ask);
const second = lookupClause(ask);

示例代码：examples/ch04/lookup-once.js

4.8 回答里同时有上限 200 和超出 150

调用只发生了一次，第 4 步也已经允许写回答。这一节核对这句回答里同时有上限 200 元和超出 150 元。

问题：怎样才算把「超了多少」答完？

符号与单位：回答是字符串。reply(limitYuan, overYuan) 把 200 和 150 放进同一句，单位写「元」。只含上限的那一句记为 capOnly，它有 200，没有 150。第 4 步采用的是同时含两个数的 answer。

用基准算例走一遍：answer 为「上限 200 元，超出 150 元」。它接得上第 2 步的观察和第 3 步的差。capOnly 为「上限 200 元」。读者拿这句去对「超了多少」，对不上 150。两个数都在时，上限说明规章边界，超出说明这单越过边界的金额。第 5 步停止之后，这句回答保持不变。

只写超出 150 元

150 元是差。回答里若不出现上限 200 元，读者看不到这个差是相对哪一条规章边界算出来的。第 4 步的句子两个数都写。

回答只报上限、不报超出

capOnly 只有上限 200 元。教学句问的是超了多少，150 元还停在第 3 步的记录里，没有进入回答。第 4 步用 answer，同时带上 200 和 150。

可操作对象：比较 answer 和 capOnly。交给读者的是 answer。

const limitYuan = 200;
const overYuan = 150;

function reply(limit, over) {
  return '上限 ' + limit + ' 元，超出 ' + over + ' 元';
}

const answer = reply(limitYuan, overYuan);
const capOnly = '上限 ' + limitYuan + ' 元';

示例代码：examples/ch04/answer-both.js

本章避坑清单

  1. 循环停不下来：第 4 步已经写出回答后，第 5 步仍去调用 lookupClause。第 5 步的读数应是停止。
  2. 观察格写成模型自己的猜测。观察只填写 lookupClause 返回的上限 200 元；猜测不能拿去相减。
  3. 把 maxSteps 改成 5 或其他数来给第 5 步腾位置。本课这个数保持 4。
  4. 回答只报上限 200 元，不报超出 150 元。第 4 步的句子两个数都要有。
  5. 没有观察就写出 150。观察格还空时，超出还没有来源。
  6. 把第 4 步再用来查一次「报销上限是多少」。第 4 步的字段是 answer。
  7. 用 350 减 350 得到 0，并把 0 当作超出。减数应是观察里的 200，差是 150。
  8. 同一句 ask 调用第二次，次数变成 2。第二次不再交新的上限。
