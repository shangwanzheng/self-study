# 编程边学边练教程

把编程入门做成**断网能打开、每一节都能跑**的分章课。页面和运行时见 [course-contract.md](course-contract.md)。语言入口见 [tracks.md](tracks.md)。并行章节任务书见 [subagent-brief.md](subagent-brief.md)。

数学、工程、自然科学、车辆等多体理论课走 [self-study-course](../self-study-course/SKILL.md)。

## 何时使用 / 何时不用

**使用：** 用户要从零学一门编程语言，要边学边练的交互课，或要把一个小痛点做成整门练习。

**不用：** 只问一个语法点；修改现有业务代码；跑测试、做缺陷分析；理论学科的自学课。

## 学员路径

生成的课照下面教。编程自学的核心逻辑是目标驱动、边学边练、AI 共生，避开只收藏不跑通。

1. 先按目标定语言，不要比较哪门语言最厉害。三门默认入口在 [tracks.md](tracks.md)。用户点名其他语言时，仍用本技能的章节结构和动手比例。
2. 一周扫完变量、循环、条件判断、函数。只让学员知道工具箱里有什么。冷门语法不进这四章。
3. 每一节先写短概念，紧接着一份能跑的复刻，再做一个只改一处的动手。复刻也要跑出输出。概念块短于这一节的复刻加动手。章节页眉写上「概念约 10 分钟」和「预计动手 30 分钟」。
4. 整门课只做一个痛点项目。写代码前先写中文伪代码。出现分支或循环时画流程图：矩形是动作，菱形是判断。
5. AI 共生的顺序固定：学员定业务逻辑，模型可以出初稿，学员逐行拆解并自己重写核心部分。报错时保留错误原文和对应代码；能跑通的改法放在参考解里，底层原因放在自测解析里，不放在报错旁边的第一屏。
6. 首页写明时间感：3–6 个月从零到能独立做完这门课的小项目。延伸只留 freeCodeCamp、Exercism、roadmap.sh 这三处名字，不放远程链接。不写编辑器主题、插件清单，也不堆第二套课程。

## 产出放哪里

- 课程正文只写入用户指定目录。
- 未指定时：当前工作区就是在备这门课，则放到工作区下的 `<课程名>/`。当前工作区是别的软件项目时，先问输出目录。
- 不要写进本技能的 `template/`。
- 大纲放 `<课程目录>/_draft/outline.md`。
- 续写时在原目录改，不复制第二套 `assets/`。

## 作者署名

用户指定作者时照用。未指定则不要编造人名，不写 `meta author`，不放作者 chip。

指定了作者时，每个 HTML 只保留一处可见署名「作者：名字」和一条 `meta author`。

## 工作流

```text
任务进度：
- [ ] 1. 锁定语言、痛点项目、做完的标志、输出目录、作者
- [ ] 2. 写下大纲并落盘
- [ ] 3. 复制运行时，改注册表，复制 exercises/check.py
- [ ] 4. 按 subagent-brief 并行写各章和练习文件
- [ ] 5. 父任务合并首页、注册表、项目里那段真实报错
- [ ] 6. 运行 validate_course.py，再运行 exercises/check.py 与 --solution
- [ ] 7. 抽查首页、一节复刻能跑、一道自测能提交
```

### 1. 锁定范围

请求里已经有目标和痛点时直接开工。缺的只问两件：学完拿它做什么、手头那个真实痛点是什么。语言按 [tracks.md](tracks.md) 定。

痛点仍然没有时，用课程自带的几行虚构 csv 做批量整理。不要改成爬虫，也不要用真实个人信息。

一门课只锁一门语言、一个痛点项目、一组基准输入。做完的标志写成一条能观察的结果：命令行印出什么，或页面上出现什么。

### 2. 大纲

默认五篇，顺序是依赖，不要打乱：

1. 目标（语言已锁定、痛点项目、做完的标志、只够跑起来的环境）
2. 四件套（变量、循环、条件判断、函数，各一章）
3. 先写清楚（中文伪代码、流程图）
4. 项目（痛点拆成几章，每章结束时程序比上一章多做一件能观察的事）
5. 协作与收束（一段来自本课项目的真实报错、AI 共生、自己重写核心、按做完的标志验收）

用户要短课或「7 天入门」：保留目标、四件套、至少一个能运行的项目切片。伪代码、流程图、AI 共生和这段真实报错仍然要出现，可以并进项目章。

每章写死：`id`、文件名、篇号、跑通标准、复刻与动手各做什么、预期输出、练习文件名。项目章写清这一章新跑通了什么。

大纲同时写死 `language`：`python`、`javascript` 或 `java`。用户点名其他语言时，用该语言的小写英文名，并在校验时走默认结构校验；四件套和项目切片仍然要有。

### 3. 运行时

从本技能 `template/assets/` 复制到课程目录。把 `course.js` 顶部的 `language` 和里面的 `CHAPTERS`、`STAGES` 改成这门课的。复制后全文搜索「先跑通一行」和「结构骨架」，正式课里应当为零。

把 `template/exercises/check.py` 复制到课程的 `exercises/check.py`。比较逻辑保持不动，只增加练习文件。

`course.js` 只由父任务改。子任务只写自己的 HTML 和 `exercises/chNN/`。

JavaScript 的复刻和四件套用页面里的运行器跑，并和 `node` 看到同一份纯输出。Python、Java 在页面写清从课程根目录执行的命令。不要嵌入 Pyodide、在线编译器或 CDN。

### 4. 并行写章

大纲和 `CHAPTERS` 落盘后，一章一个子任务，提示词用 [subagent-brief.md](subagent-brief.md)。结构对标 `template/ch01_run.html`。不要把骨架项目「先跑通一行」抄进新课。

### 5. 一节里写什么

练习节按这个顺序写：

1. **本节要跑通：** 一条能观察的结果。
2. **概念：** 只讲这一步用到的语法。
3. **伪代码：** 中文步骤。
4. 有分支或循环时调用 `Course.ui.flow`。矩形是动作，菱形是判断。
5. **复刻：** 一份已经能跑的短代码，和 `exercises/` 里以 `demo` 开头的文件是同一份。
6. **动手：** 在复刻上改一处。页面上的代码和练习文件是同一份，里面留出待补的那一处。
7. **预期输出：** 复刻和动手各写一条，文字与对应的 `.expect.txt` 一致。

项目章和收束章加 **AI 共生**：学员先有伪代码；允许模型起草的范围；必须自己重写的核心。四件套章节不放这块。

参考解只放 `exercises/chNN/solution/`，不要链到页面上，也不要出现在 HTML 里。

章末四块：本章避坑清单、自测题（不少于 6 题，含一道多选，提交后给解析）、术语表（中文 / 英文 / 符号 / 含义）、本章小结。解析要写出误区。

收束章的报错练习：动手区是会打出那段错误的代码，第一屏用 `pre.error-log` 只放错误原文。底层原因放进自测解析。能跑通的版本只在 `solution/`。

### 6. 校验

在本技能目录执行（`python` 不可用时改用 `py -3`）：

```bash
python scripts/validate_course.py "<课程目录>" --full
python "<课程目录>/exercises/check.py"
python "<课程目录>/exercises/check.py" --solution
```

短课把 `--full` 换成 `--short`。指定了作者才加 `--author "名字"`。退出码非 0 就按报告改，再跑，直到通过。

`check.py` 退出码 2 表示本机没有 `node`、`javac` 或对应解释器。写明缺什么，不要改成跳过就算通过。

### 7. 抽查

需要看页面时，在课程目录临时启动静态服务，看完即关。课程仍用相对路径，运行时保持经典脚本。

抽查首页的痛点项目和三处延伸、一节复刻的运行结果、一道自测的解析。JavaScript 课按「运行」后，输出应与预期一致。

## 不要做的事

- 不要一门课塞两门语言，也不要中途换基准输入。
- 不要把参考解放进页面或动手区前面。
- 不要用空讲概念充一节。概念块不短于这一节的复刻加动手，就把概念删短。
- 不要在四件套里讲内存管理、算法复杂度、编辑器主题或插件。
- 不要默认写成爬虫。
- 不要从 CDN 加载脚本或样式，不要把教程运行时写成 `type="module"`。
- 不要给 freeCodeCamp、Exercism、roadmap.sh 加远程链接；只写名字。
- 不要编造作者，不要在一页上重复作者标签。
- 不要把教学示例写成真实个人信息。
- 页面运行器只服务这门本地课，不要拿去嵌不受信任的网站。
