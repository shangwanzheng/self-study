注入、凭据与供应链

沿着一条订单备注、一次会话和一次安装走：不可信字符串只当文本，凭据与秘密留在应在的位置，依赖树由 lockfile 固定。

前置：第 1–5 章交互演示 2 个离线可打开
  • 能把订单备注与 HTML 解释边界分开，避免 XSS。
  • 能说明 Cookie、HttpOnly、CSRF 与内存 token 的取舍。
  • 能检查秘密、SemVer、lockfile 与构建机的安装边界。

这一章：一条备注从输入到构建机

订单备注是不可信字符串，不要当 HTML 插入。它进入页面时以文本节点呈现；CSP 与开放重定向以各自文档的原文和当前部署配置为准，不把某个菜单点击路径写死。

备注

数据可以不可信；呈现 API 决定它是文本还是被解释的 HTML。

会话

sid 只是 cookieName。HttpOnly 的 Cookie 脚本读不到；内存 token 刷新就没了。

秘密

ORDER_API_SECRET 只是 secretName，不能进前端包和仓库。

安装

lock 锁在 1.4.2；不锁可能装到 1.5.0。构建机不执行未锁定的安装结果。

6.1 不要把备注当 HTML

先守住输入到 DOM 的边界。订单备注来自用户、接口或历史数据时，都先按不可信字符串处理。

约定：展示备注时使用 textContent 或框架默认的文本插值。它会创建文本，不会把字符串中的标记解释成页面结构。把同一字符串交给 innerHTML，浏览器会把它当 HTML 解析；如果字符串来自不可信来源，就形成 XSS 风险。需要富文本是另一条受控流程：定义允许的格式、在服务端或可靠组件中净化，并把净化规则和版本当作安全边界；本章不提供攻击载荷或绕过方法。

const remark = order.remark; // 不可信字符串
remarkNode.textContent = remark; // 当文本显示

// 不要这样做：remarkNode.innerHTML = remark;

示例代码：examples/ch06/render-remark.js

备注用 innerHTML 插入

“接口已经返回字符串”不等于它可信。innerHTML 是解释入口；备注只是业务数据，不应获得 HTML 的表达能力。

用 userId 10001 当密钥

10001 是教学订单的用户标识，不是秘密，也不能把可预测的业务 id 当作密钥、签名材料或权限证明。

当文本 / 当 HTML切换分段
观察要点：① 两种模式读取的是同一段教学字符串。② “当文本”会显示尖括号，说明备注没有被当作结构。③ “当 HTML”会出现教学标记，读数显示字符串被浏览器解释；这是风险模型演示，不含真实攻击载荷。④ 真实订单备注选择文本呈现。

6.2 CSP

文本呈现先缩小了注入面。CSP 再规定文档可以从哪些来源加载、执行或连接资源。

约定：CSP（Content Security Policy）的指令、继承关系、报告行为与浏览器支持，以 CSP 规范和所用浏览器文档的原文为准。它是降低脚本注入影响的一层策略，不是把不可信字符串交给 HTML 解释器的许可。策略应由应用实际使用的资源、脚本加载方式和部署响应头推导；上线后用浏览器控制台与报告端点核对违反项，不用某个固定菜单路径当作唯一操作步骤。

先修注入点，再配置策略

备注继续用 textContent。CSP 是纵深防御：即使未来出现遗漏，也限制可执行资源的来源；它不替代输出编码、审查和测试。

可操作对象：为订单页列出三份清单：实际脚本来源、实际接口来源、实际图片来源。把每一项与部署响应中的 CSP 对照；缺项先确认业务需要，宽泛来源先确认是否真的必须存在。

6.3 开放重定向

资源来源之外，还有导航去向。登录后的 returnTo、订单详情的跳转地址都不能把外部输入直接交给重定向。

约定：开放重定向是应用接受一个目的地址并把用户带到未验证目标的缺陷。验证规则应以路由、身份提供方或框架的官方文档原文为准，并与当前业务允许的站内路径一致。常见的稳妥边界是：服务端只接受已登记的站内相对路径或服务器保存的状态值，拒绝不符合规则的输入，再以安全的默认页兜底。不要依赖前端隐藏链接或某个固定菜单路径来保证安全。

把 returnTo 原样拼回 Location

“来自查询参数”不等于“站内地址”。先按允许规则解析与比较，再决定是否跳转；解析失败和不允许时回到明确的默认路径。

6.4 token 放 Cookie 还是内存

导航边界之后是会话边界。这里比较的是脚本能否读取与刷新后的存续，不把存储位置误写成万能安全结论。

HttpOnly 的 Cookie

浏览器会随满足作用域的请求带上 Cookie；脚本读不到 HttpOnly 值。教学 cookieName 是 sid，它只是名字，不表示凭据类型或安全属性。

内存 token

当前页面运行期间可由脚本持有；刷新、关闭或重新加载后内存状态就没了。它避免持久化读取面，但需要明确续期与恢复流程。

选择要从威胁模型、同站/跨站请求、续期体验、服务端验证和失效机制一起判断。无论放在哪里，服务端仍要验证会话与权限；前端菜单是否显示不构成鉴权。

// 浏览器脚本不能读取 HttpOnly Cookie 的值。
// 内存变量只在当前页面生命周期内存在。
let accessTokenInMemory = null;

示例代码：examples/ch06/session-boundary.txt

6.5 HttpOnly 与 CSRF

HttpOnly 保护的是“脚本不能读取值”的边界，不等于请求不会携带凭据。

当 Cookie 会随请求带上凭据时，要处理 CSRF：攻击者诱导浏览器发起跨站状态变更请求，服务端若只看自动携带的 Cookie，可能把它当成用户意图。组合使用同站策略、服务端校验不可伪造的请求证明、校验 Origin/Referer（按部署场景选择）和关键操作再次确认等措施；具体属性与浏览器行为按当前 Cookie、Fetch 与框架文档原文核对。不要把 HttpOnly 误解为 CSRF 防护，也不要把“前端没有显示按钮”当作接口防护。

Cookie 带凭据时忽略 CSRF

脚本读不到 sid，并不会阻止浏览器在符合规则的请求中携带它。状态变更接口要有服务端可验证的抗 CSRF 设计。

6.6 前端包和仓库里没有秘密

会话凭据之外，构建输入也有边界。前端包会交付给浏览器，仓库可能被克隆、镜像和日志收集。

ORDER_API_SECRET 是 secretName，只是名称，不能出现在前端包和仓库中；它的值更不能进入其中。把密钥值写进 REACT_APP_ 前缀变量、公共构建变量、源码、示例配置或日志，都会把它交给能取得构建产物或仓库的人。本章不展开 source 的公网下载流程，但秘密不进包是不可省略的边界。需要秘密的请求由服务端进程持有并执行，前端只获得完成业务所需的公开结果。

把密钥值写进 REACT_APP_ 或构建变量

“构建时读取”不等于“运行时保密”。只要变量被替换进浏览器产物，用户就能下载该产物。公开接口地址和服务端秘密是两类配置。

可操作对象：检查源码、历史提交、构建日志、产物和示例文件。发现疑似泄漏时，先撤销并轮换该秘密，再删除暴露位置；只删除当前行不能让已下载的值失效。

6.7 lockfile 锁住依赖树

秘密不进入构建产物后，构建输入还要可复现。SemVer 范围不是锁定结果。

声明允许的 SemVer 范围与实际解析出的依赖树不同。教学依赖在 lockfile 中锁为 1.4.2；缺少 lockfile 或不按它安装时，允许范围可能在另一次安装解析到 1.5.0。lockfile 应与清单一起提交，并由项目约定的包管理器严格消费；它同时锁住直接依赖和传递依赖的具体解析结果。

# 教学结果（不是安装命令）
lockfile: package-a@1.4.2
未锁定范围可能解析为: package-a@1.5.0

示例代码：examples/ch06/install-policy.txt

lock 开或关切换分段
观察要点：① 打开 lock 后，本次安装解析为 1.4.2。② 关闭 lock 后，允许范围可解析到 1.5.0，不再是可复现输入。③ lockfile 固定的是依赖树结果，不只是一个顶层版本号。④ 构建机不执行未锁定的安装结果。

6.8 审计与构建机

最后把这些边界变成可重复检查。审计不是安装以后才补的一步，构建机也不是开发机的放大版。

审计输入

记录清单、lockfile、解析出的依赖树与已知风险信息；风险结论要有版本、时间和处理决定。

构建机规则

只从受控来源取得已锁定的依赖树；校验失败、lockfile 缺失或解析漂移时停止，而不是继续产出包。

产物复核

检查浏览器产物和日志不含秘密；抽查订单备注仍走文本呈现；部署 CSP 与重定向规则与文档一致。

让失败可见

构建机不执行未锁定的安装结果。把“缺 lock”“依赖解析变动”“秘密扫描命中”设为可追踪的失败，而不是由人工记忆补救。

本章避坑清单

  1. 把订单备注用 innerHTML 插入，等于把不可信字符串交给 HTML 解释器。
  2. 把 sid 当作安全属性；它只是 cookieName。HttpOnly 的 Cookie 脚本读不到，但携带 Cookie 的请求仍要防 CSRF。
  3. 把密钥值写进 REACT_APP_、公共构建变量、前端包、仓库或日志。
  4. 用 userId 10001 当密钥或权限证明；业务 id 不具备秘密性。
  5. 没交 lockfile 就安装，结果可能从 1.4.2 漂移到 1.5.0。
  6. 让构建机执行未锁定的安装结果，导致不能复现也不能可靠审计。

订单备注是不可信字符串，默认当文本呈现；CSP 是纵深防御，开放重定向须按允许规则验证目标。HttpOnly 的 Cookie 不可被脚本读取，内存 token 刷新就消失；Cookie 自动带凭据时仍须设计 CSRF 防护。ORDER_API_SECRET 不能进前端包或仓库。用 lockfile 把依赖树锁在 1.4.2，构建机拒绝未锁定的安装结果。
