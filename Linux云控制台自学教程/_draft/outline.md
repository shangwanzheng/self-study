# Linux 云控制台自学教程 · 大纲

## 范围

- 新课。输出目录：`Linux云控制台自学教程/`（当前工作区下）。
- 作者：未指定。不写 `meta author`，不放作者 chip。
- 主题：Linux 基础。只保留操作主流云控制台时用得上的那一层。
- 学习目标：学完能在教学控制台里指认基准实例，用密钥登录，在正确目录里查看文件，用 sudo 装上并启动 nginx，让安全组和系统防火墙都放行 80，在云盘扩容后让 `df` 变成 100 GiB，并用日志解释「运行中但网页打不开」。
- 读者基础：会用浏览器和图形界面，没有系统学过 shell。不假定读者已有某家云的账号。

厂商按钮名称会变。正文用本大纲的教学控制台用词，并写明以该厂商现行文档为准。不要把某一家控制台的当前菜单写成普遍事实。

## 必学 / 可查 / 暂缓

- 必学：实例与镜像、登录三要素、当前目录、密钥文件权限、sudo、服务是否在听、安全组与 ufw、数据盘文件系统、用日志对照现象。
- 可查：vim 的进阶操作、shell 脚本、cron、用户组细节、SELinux、手写 systemd unit、LVM。
- 暂缓：内核编译、容器编排、性能调优、自建云平台。这些不影响「把一台 Linux 云主机在控制台里操作到网页能打开」。

## 技能树

只用来查漏，不决定章序。

1. 认出控制台对象
   - 区分镜像和实例
   - 用区域、实例名、实例 ID 锁定一台
   - 区分公网地址和私网地址
   - 先修：会用浏览器
2. 登录
   - 用户名、密钥、安全组 TCP 22 同时成立
   - 先修：模块 1
3. 在系统里定位
   - 当前目录与绝对路径
   - 先修：模块 2
   - `.ssh` 与 `authorized_keys` 的属主和写权限
   - 先修：当前目录
   - `ubuntu` 与 `sudo`
   - 先修：已经登录
4. 让 80 端口有进程
   - 安装 nginx
   - active，并且听在 `0.0.0.0:80`
   - 先修：sudo
5. 让控制台变更在系统里生效
   - 安全组与 ufw 两道门
   - 先修：已经知道有没有进程在听
   - 块设备容量与文件系统容量
   - 先修：会看绝对路径 `/data`
6. 用证据闭环
   - 一种现象对应一处日志或一条命令
   - 先修：模块 1–5

#### ch04 · 密钥绑定了，权限仍会拒绝

- id：`ch04`，文件：`ch04_mode.html`，阶段：2
- 主概念：控制台已经绑定密钥，sshd 仍会因为属主不对，或 `.ssh` / `authorized_keys` 对组或其他人可写而拒绝。
- 前置：第 3 章。前置检查 2–3 题。
- 目标：
  1. 能指出要看的两个路径：`/home/ubuntu/.ssh` 和 `/home/ubuntu/.ssh/authorized_keys`。
  2. 能用 `Course.linux.sshAccepts` 的规则判断接受还是拒绝。
  3. 能说明建议值是目录 `700`、文件 `600`，而 `755` 配 `644` 仍然接受。
- 演示：分段选择目录模式 `700` / `755` / `775`，文件模式 `600` / `644` / `664`，再加一个「属主是 ubuntu」开关。调用 `Course.linux.sshAccepts`。
- 规则（必须与函数一致，不要改写成「644 一律失败」）：
  - 属主不是 ubuntu：拒绝。
  - 目录或文件对组或其他人可写（如 `775`、`664`）：拒绝。
  - `755` 与 `644`：接受。
  - 建议值仍是 `700` 与 `600`。
- 节：前置检查；为什么学；核心概念；逐步讲解；示范例题；常见错误；四类练习；迁移。
- 易错：`chmod 777`；把操作者电脑上私钥的权限，说成服务器上 `authorized_keys` 的权限；文件属主是 root。
- 避坑：改权限前先看清是目录还是文件。私钥权限不在这台实例上。
- 迁移：属主改成 root，模式仍是 `700` 和 `600`，判断 sshd 是否接受。

#### ch07 · 两道门都要放行

- id：`ch07`，文件：`ch07_doors.html`，阶段：3
- 主概念：公网访问 80 要过安全组和系统防火墙；两道门都开了但没人听，表现是连接被拒绝，不是一直转。
- 前置：第 6 章。前置检查 2–3 题。
- 目标：

  2. 能区分「连不上」和「连接被拒绝」。

- 演示：开关：安全组放行 80、ufw 已启用、ufw 放行 80、有进程监听。绑定地址固定为 `0.0.0.0`（绑定地址已在第 6 章讲完）。调用 `Course.linux.reach80`。读出 `label` 和 `reason`。
- 基准成功态：安全组已放行 TCP 80，来源 `0.0.0.0/0`；ufw 未启用；nginx 听在 `0.0.0.0:80`。结果是打得开。
- 节：前置检查；为什么学；核心概念；逐步讲解两种失败；示范例题；常见错误；四类练习；迁移。

- 易错：只改安全组；只关 ufw 但安全组没放行；把「连接被拒绝」当成安全组丢包。
- 避坑：有的镜像默认不开 ufw。不要把某一家云的默认安全组写成普遍事实。基准实例的 ufw 是未启用。
- 迁移：两道门都放行，但 `listening` 为假。结果必须是「连接被拒绝」。

### 第 4 篇 · 对上证据

#### ch08 · 扩容的是块设备

- id：`ch08`，文件：`ch08_disk.html`，阶段：4
- 主概念：控制台扩容改变的是块设备大小，`df` 显示的是文件系统大小。
- 前置：第 7 章。前置检查 2–3 题。
- 目标：
  1. 能说出数据盘设备是 `/dev/vdb`，挂载点是 `/data`。
  2. 能说明控制台已是 100 GiB 时，`df` 仍可能是 20 GiB。
  3. 能写出 `sudo resize2fs /dev/vdb`，并说明它为什么适用于这块没有分区的整盘 ext4。
- 演示：一个开关「文件系统已经 resize2fs」。调用 `Course.linux.dfDataGiB`。块设备一侧始终显示 `baseline.dataBlockGiB`（100）。未 resize 时 df 为 20，resize 后为 100。不要出现第三种容量。
- 节：前置检查；为什么学；核心概念；逐步讲解；示范例题；常见错误；四类练习；迁移。
- 命令：`commands.df`、`commands.resize`。
- 易错：扩容后只看控制台；对 `/dev/vda` 做 resize 却去看 `/data`；把内存 4 GiB 当成磁盘。
- 避坑：有分区表时要先处理分区。本课数据盘是整盘 ext4、没有分区，所以只做 `resize2fs`。系统盘 `/dev/vda` 不在本章扩容。具体命令以镜像文档为准。
- 迁移：块设备已经是 100 GiB，文件系统还没 resize，问 `df -h /data` 应看到 20 GiB 还是 100 GiB。
