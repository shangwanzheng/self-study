控制台里的这台 Linux

你点的是云控制台，改的是云里那一台实例。先用区域、实例名、镜像把它认出来。

预计学习 40 分钟 前置：会用浏览器，无前置章节 演示 1 个
  • 能用区域、实例名、镜像三项，判断眼前这一行是不是基准实例。
  • 能说明「运行中」只表示虚拟机开着。
  • 能说出公网地址给你的电脑用，私网地址给云里的其他资源用。

1.1 为什么学

你会用浏览器，这一章就够用。前面没有要先学完的章节。

先看本课这一台。它在区域 cn-demo-1，名字叫 web-demo，由镜像 Ubuntu 22.04 LTS 启动。你在控制台里点到的，就是这一台。你的电脑做的事，是把控制台页面显示出来。

后面你要登录、看文件、让服务起来。那些动作都得点在同一台上。台子认错，动作就落到别的地方，你还会对着自己的电脑找原因。

先停一下。你把浏览器关掉，区域 cn-demo-1 里的 web-demo 还在不在？想一句再往下看。

还在。浏览器是你这边的窗口。实例由镜像启动之后，留在它的区域里。你的电脑关机，那一台不会跟着从区域里消失。

所以这一章只做一件事：用区域、实例名、镜像，确认你看到的是这台基准实例。登录要满足的条件，下一章再拆。

1.2 核心概念

上一节把你的电脑和控制台里的那一台分开了。这一节给三个词下定义，再用基准实例做正例，用一项对不齐的情况做反例。

镜像是启动时用的系统模板。本课这份叫 Ubuntu 22.04 LTS。模板说明系统从哪一份复制出来。模板自己不在实例列表里占「一台正在开着的机器」。

实例是用那份镜像启动出来的那一台。本课这台的名字是 web-demo，实例 ID 是 i-demo0001。你在控制台里点击、查看、改设置，点的是实例这一行。

区域是控制台把实例列表分开的范围。这台在 cn-demo-1。你打开的区域名和 cn-demo-1 不一致时，眼前这份列表里没有本课的 web-demo。本课不在别的区域再放一台，也不另写一套地址。可用区 cn-demo-1a 是这台在 cn-demo-1 里面的位置：先进入这个区域，才能看到这个位置上的这一行。

词基准实例上的值它回答的问题
区域cn-demo-1你打开的是哪一份列表
实例web-demo，ID i-demo0001你点的是哪一台
镜像Ubuntu 22.04 LTS这一台从哪份模板启动
可用区cn-demo-1a在这个区域里的哪个位置

核对「是不是这台」先用前三行：区域、实例名、镜像。可用区放在区域对上之后再看。

三项同时成立

区域 cn-demo-1、实例名 web-demo、镜像 Ubuntu 22.04 LTS，三格一起对上，才是基准实例。对上两格、错一格，就还不是这台。

正例。区域 cn-demo-1，实例名 web-demo，镜像 Ubuntu 22.04 LTS。这就是基准实例。可用区 cn-demo-1a，实例 ID i-demo0001，规格 2 vCPU、4 GiB。这份镜像上的登录名是 ubuntu，这里先记住名字。

反例。镜像仍是 Ubuntu 22.04 LTS，名字也写成 web-demo，但你打开的区域和 cn-demo-1 不一致。缺了区域这一格。列表里找不到 web-demo 时，先回到区域，公网和私网都先不要改。

先停一下。三项里，哪一项决定你眼前这份列表？

区域。列表跟着区域走。实例名和镜像，是你进入 cn-demo-1 之后继续核对的两列。

1.3 逐步讲解

三个词已经能用了。这一节按你在控制台上的顺序走：先锁定这一行，再读状态，再把两个地址的用途分开。

按钮名会变

你实际打开的控制台，按钮叫什么，以该厂商现行文档为准。本课固定用这些教学词：区域、实例、镜像、运行中、公网地址、私网地址。文档上的名字和这里不一样时，先按文档点到实例列表，再把那一页上的名字对应回区域、实例名、镜像这三项。

  1. 看区域名。与 cn-demo-1 一致，才继续。不一致，这份列表里没有本课的 web-demo。
  2. 在这份列表里找实例名 web-demo。
  3. 看这一行的镜像是不是 Ubuntu 22.04 LTS。
  4. 看实例 ID 是不是 i-demo0001，把这一行锁住。名字对上、ID 不是 i-demo0001，就还不是这台教学实例。
  5. 看状态。本课用「运行中」讨论这台开着的虚拟机。
  6. 读公网和私网，并记下谁用哪一个。
运行中只表示开着

「运行中」只表示虚拟机开着。它不回答网页打不打得开，也不回答你有没有登录进去。看到运行中，这句话就停在这里：这台虚拟机是开的。

公网地址是 203.0.113.15。它给你的电脑用。你人在自己电脑前，要访问这台实例，看的是这个地址。203.0.113.15 是文档用地址，用来教学，不是某台真实服务器，也不是个人信息。

私网地址是 10.0.1.15/24。它给云里的其他资源用。斜线后面的 24 是前缀长度，本课不做计算。你把整段 10.0.1.15/24 当成这台的私网来记。

你坐在自己的电脑前。两个地址里，该抄哪一个？先答，再看下一段。

抄 203.0.113.15。私网 10.0.1.15/24 留给云里的其他资源。两个地址都记在这台实例上，用途不同，要一起写在笔记里，不能互相代替。

规格是 2 vCPU、4 GiB。它告诉你这台的计算和内存有多大。同样大小的实例可以有很多台，所以规格不代替区域、实例名和镜像。你读到别的 vCPU 或别的内存大小，就知道那不是本课写下的这台规格。

1.4 示范例题

状态和两个地址已经分开。这一节用基准实例把三项判断走完，并说明为什么选这三项。

基准实例这一行

区域 cn-demo-1，可用区 cn-demo-1a，实例名 web-demo，实例 ID i-demo0001，镜像 Ubuntu 22.04 LTS，规格 2 vCPU、4 GiB，状态运行中，公网 203.0.113.15，私网 10.0.1.15/24，登录名 ubuntu。

把三项写成一句：区域是 cn-demo-1，实例名是 web-demo，镜像是 Ubuntu 22.04 LTS。三格都对，判断为「是这台」。然后读 ID i-demo0001，确认锁的是这一行。状态是运行中，只记虚拟机开着。你的电脑用 203.0.113.15，云里的其他资源用 10.0.1.15/24。

这三项各自对应一个格子。区域回答「你打开的是哪一份列表」。实例名回答「这份列表里你指的是哪一行」。镜像回答「这一行从哪份模板启动」。只对上名字时，区域仍可能是另一份列表；本课不在那份列表里放第二台，所以区域仍要对上。只对上镜像时，从 Ubuntu 22.04 LTS 启动的实例可以不止一行，名字不同就不是 web-demo。规格 2 vCPU、4 GiB 表示大小，两个地址表示给谁用，都在你认出这台之后再读。

实例 ID 放在三项之后，用来锁住这一行。镜像告诉你模板，i-demo0001 告诉你是哪一行。

下面的演示把区域、实例名、镜像各自做成「一致 / 不一致」。显示出来的名字和地址从基准记录读取。某一项不一致时，读出写明是哪一项。公网和私网不跟着开关改，避免你顺手写下第二套地址。

核对是不是这台基准实例切换分段，看判断结果
观察要点：① 三项都一致，判断读出「是这台」。② 有项不一致，判断写明是区域、实例名还是镜像。③ 公网仍是 203.0.113.15，私网仍是 10.0.1.15/24；区域不一致时，变的是你打开的列表。

1.5 常见错误

例题里三项是对上的。这一节放在你最容易走岔的三步旁边。每处都先写误区，再写改法。

镜像不是正在运行的机器

Ubuntu 22.04 LTS 正在运行，所以它就是 web-demo。Ubuntu 22.04 LTS 是镜像，是启动用的模板。正在列表里占一行的是实例 web-demo，ID 是 i-demo0001。

别的区域里没有这台

列表里找不到 web-demo，这台已经被删掉了，地址也要换一套。你打开的区域和 cn-demo-1 不一致时，这份列表里本来就没有 web-demo。把区域改回 cn-demo-1，再对名字和镜像。公网仍是 203.0.113.15，私网仍是 10.0.1.15/24。

家里的电脑不用私网

人在自己电脑前，用 10.0.1.15 去连这台。10.0.1.15 属于私网 10.0.1.15/24，给云里的其他资源用。你的电脑使用公网 203.0.113.15。怎样登录，下一章再写。

1.6 四类练习

三种走岔的方式你已经见过。这一节换你来做，由易到难：先回忆，再辨析，再放回基准实例，最后把区域换掉。每题先自己写答案，再打开解析。解析给出正确结果、关键步骤、错因，以及该回看的节。

回忆练习一

合上页面，回答两句。控制台操作的是什么？核对基准实例的三项，基准值各是什么？

看解析

正确结果：控制台操作的是某个区域里、由某份镜像启动的那一台实例。三项是区域 cn-demo-1、实例名 web-demo、镜像 Ubuntu 22.04 LTS。

关键步骤：先说清操作对象是云里的实例，再列出三项和三个值。

错因：把对象说成自己的电脑，是把显示页面的窗口当成了被改的机器。只记得 web-demo、说不出区域和镜像，三项就缺了格，还不能判断是这台。

回看：1.1 为什么学、1.2 核心概念。

辨析练习二

下面两句，哪一句成立？

甲：Ubuntu 22.04 LTS 正在运行，所以它就是 web-demo。

乙：web-demo 是实例，Ubuntu 22.04 LTS 是启动它的镜像。这一行的实例 ID 是 i-demo0001。

看解析

正确结果：乙成立。

关键步骤：先把镜像认成模板，再把实例认成那一台，最后用 i-demo0001 锁住这一行。

错因：甲把镜像名当成了正在运行的机器。模板可以用来启动实例，模板本身不是列表里的 web-demo。

回看：1.2 核心概念、1.5 常见错误。

应用练习三

你读到这一行：区域 cn-demo-1，可用区 cn-demo-1a，实例名 web-demo，实例 ID i-demo0001，镜像 Ubuntu 22.04 LTS，规格 2 vCPU、4 GiB，状态运行中，公网 203.0.113.15，私网 10.0.1.15/24。

回答三句：这是不是基准实例？「运行中」还多保证了什么？你的电脑该用哪个地址？

看解析

正确结果：是这台。运行中只保证虚拟机开着。你的电脑用 203.0.113.15。私网 10.0.1.15/24 给云里的其他资源。

关键步骤：先对区域、实例名、镜像，再用 i-demo0001 锁行，然后把状态收成「虚拟机开着」，最后按「谁在用」选地址。

错因：看到运行中就认为网页已经打得开，是把状态词用过了头。把 10.0.1.15 抄给自己的电脑，是把私网的用途换成了公网的用途。

回看：1.3 逐步讲解、1.4 示范例题。

迁移练习四

对照方式不变，仍是区域、实例名、镜像。你当前打开的区域名与 cn-demo-1 不一致，列表里没有 web-demo。不要新写一个区域名，也不要新写 IP。

回答两句：基准实例的公网和私网要不要换成另一套？你下一步改哪一项？

看解析

正确结果：不换。公网仍是 203.0.113.15，私网仍是 10.0.1.15/24。下一步把区域改回 cn-demo-1，再对实例名 web-demo 和镜像 Ubuntu 22.04 LTS。对上之后，这一行的 ID 应是 i-demo0001。

关键步骤：先承认变的是列表，地址没变；下一步只改区域这一项。

错因：以为实例没了，于是编一套新地址。或者改用私网，从自己的电脑去找。两处都把「找错列表」做成了「换掉这台的记录」。

回看：1.5 常见错误、1.7 迁移。

1.7 迁移

练习四把你放在与 cn-demo-1 不一致的区域里。这一节把那次更换的步骤固定下来。换的是你打开的区域名，对照方式仍是基准三项。不新造第二套地址。

只改指定的那一项

这一次指定要换的是区域名。实例名 web-demo、镜像 Ubuntu 22.04 LTS、公网 203.0.113.15、私网 10.0.1.15/24 都保持基准记录。

  1. 写下基准区域 cn-demo-1。这台实例的列表在这里。
  2. 看屏幕上的区域名。与 cn-demo-1 不一致，就停。此时先不要下结论说机器没了。
  3. 这份列表里没有 web-demo，是因为列表换了。公网仍是 203.0.113.15，私网仍是 10.0.1.15/24。
  4. 把区域改回 cn-demo-1。
  5. 对实例名 web-demo，对镜像 Ubuntu 22.04 LTS。
  6. 再看实例 ID 是不是 i-demo0001，可用区是不是 cn-demo-1a。规格仍是 2 vCPU、4 GiB。
  7. 状态若是运行中，只记「虚拟机开着」。

区域名换了，认台子的方法不换。你仍用同一份基准记录对照。登录名 ubuntu 已经记在这台镜像上；三条怎样同时成立，下一章再讲。
