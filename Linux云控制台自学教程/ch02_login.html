2.1 前置检查

下面三题只问第 1 章：哪一台实例，以及公网和私网各给谁用。答完再学登录。这次作答单独计分，不计入章末 8 题。

2.2 为什么学

第 1 章你已经能对上基准实例：区域 cn-demo-1，实例名 web-demo，实例 ID i-demo0001，镜像 Ubuntu 22.04 LTS。公网地址 203.0.113.15 给你的电脑用，私网地址 10.0.1.15 给云里的其他资源用。「运行中」只说明这台虚拟机开着。

机器开着，你仍可能登不进去。登录要三条同时成立：用户名是 ubuntu，密钥 demo-key 已经绑定到这台实例，安全组 sg-web-demo 的入方向放行 TCP 22，并且来源是 198.51.100.20/32。三条里缺一条，Course.linux.loginOk 就返回失败的 reason。

登录打到的是 cn-demo-1 里的 web-demo。换一个区域，列表里没有这台，后面的用户名和密钥都没有对象。

2.3 核心概念

主概念就一句：用户名、密钥、安全组入方向 TCP 22 必须同时成立。函数按这个顺序检查，碰到第一条不成立就返回，后面的不再看。

条件基准演示开关不成立时的 reason
用户名ubuntu用户名是 ubuntu用户名不是 ubuntu
密钥demo-key 已绑定密钥已绑定密钥 demo-key 未绑定到这台实例
安全组sg-web-demo 入方向 TCP 22，来源 198.51.100.20/32安全组放行 22安全组未放行 TCP 22

调用时还有第四个字段 permOk。本章把它固定传成 true。文件权限留到第 4 章，这里不判断。

来源写在基准规则里

loginOk 只接收 user、keyBound、sg22、permOk。勾上「安全组放行 22」表示 sg-web-demo 已按来源 198.51.100.20/32 放行入方向 TCP 22，函数收到的 sg22 为 true。来源换成别的地址时，函数没有另一句 reason；对你这台电脑来说，22 上的包到不了实例。这个情况放在迁移一节判断。

2.4 逐步讲解

下面四步对着基准实例做。数字只来自 Course.linux.baseline 和 Course.linux.commands.ssh。控制台上的按钮名称会变，以该厂商现行文档为准。本课用教学控制台的词：密钥、安全组、入方向。

用户名

这份 Ubuntu 22.04 LTS 的登录名是 ubuntu。演示里勾上「用户名是 ubuntu」时，user 传入 baseline.user，也就是 ubuntu。不勾时传入 root。传入 root，reason 是「用户名不是 ubuntu」。

密钥

密钥名称是 demo-key。绑定指控制台把这把密钥配到 web-demo 上。教学命令里的私钥文件名是 demo-key.pem，它留在你自己的电脑上，由 -i 指给 ssh。

私钥不离开你的电脑

不要把 demo-key.pem 的内容贴进网页，也不要贴进工单。控制台「远程连接」和这条 ssh 是不是同一条路径，以厂商现行文档为准。本课的基准路径是 ssh 到公网地址。

安全组入方向

安全组是 sg-web-demo。入方向 TCP 22 的来源是 198.51.100.20/32。只把密钥绑上、不放行 22，数据包到不了这台实例上的 ssh 服务。用户名已经是 ubuntu 时，reason 是「安全组未放行 TCP 22」。

调用，再写命令

演示调用 Course.linux.loginOk({user, keyBound, sg22, permOk: true})。三条都成立时，ok 为 true，reason 为「可以登录」。这时你在自己的电脑上输入的是下面这一行。它使用公网地址 203.0.113.15。私网 10.0.1.15 仍然留给云里的其他资源。

ssh -i demo-key.pem ubuntu@203.0.113.15

2.6 常见错误

用 root 登录这份 Ubuntu 镜像
把登录名写成 root。 这份 Ubuntu 22.04 LTS 的登录名是 ubuntu。不勾「用户名是 ubuntu」时，传入的 user 是 root，reason 是「用户名不是 ubuntu」。
只绑密钥，不放行 22
demo-key 已经绑到 web-demo，就认为一定进得去。 用户名已经是 ubuntu 时，安全组还要放行入方向 TCP 22。缺这一条，reason 是「安全组未放行 TCP 22」。
安全组来源不是 198.51.100.20/32
入方向写了 TCP 22，来源却不是 198.51.100.20/32。 基准规则的来源就是 198.51.100.20/32。来源换成别的地址，你的电脑仍从 198.51.100.20 出去时，这条规则对不上，ssh 进不去。

2.7 四类练习

回忆

合上页面，写出登录 web-demo 的三条：用户名、密钥名称、安全组要放行的端口。再补上安全组名和来源。

核对

用户名 ubuntu，密钥 demo-key，入方向 TCP 22。安全组是 sg-web-demo，来源是 198.51.100.20/32。命令打到公网 203.0.113.15。

辨析

密钥绑定和安全组放行，各管一件事。绑定回答「这台实例认不认 demo-key」。放行回答「入方向 TCP 22 让不让包进来」。用户名 ubuntu 和传入的 root 也是两件事：只有前者等于 baseline.user。

核对

只绑定 demo-key、不放行 22，用户名又已经是 ubuntu 时，reason 是「安全组未放行 TCP 22」。传入 root 时，函数先返回「用户名不是 ubuntu」，还轮不到密钥和安全组。

应用

勾了「用户名是 ubuntu」和「安全组放行 22」，没有勾「密钥已绑定」。写出 loginOk 的 reason。

核对

user 是 ubuntu，keyBound 是 false，sg22 是 true，permOk 是 true。reason 是「密钥 demo-key 未绑定到这台实例」。用户名已经通过，函数下一步看密钥。

迁移

你的出口地址不是 198.51.100.20。安全组 sg-web-demo 的入方向 TCP 22 来源仍是 198.51.100.20/32。用户名仍是 ubuntu，密钥 demo-key 仍绑定在 web-demo 上。ssh 进得去吗？先自己判断，再读下一节。

2.8 迁移

你换了一个出口，这个出口不是 198.51.100.20。实例仍是区域 cn-demo-1 里的 web-demo。用户名仍是 ubuntu，密钥 demo-key 仍绑定着。安全组仍是 sg-web-demo，入方向 TCP 22 的来源仍写着 198.51.100.20/32。

你在自己的电脑上仍输入 2.4 那一行，目标仍是公网 203.0.113.15。判断：ssh 进不去。规则只接收来源 198.51.100.20/32，你现在的出口不在这一个地址里，入方向不收你的包。用户名和密钥这两条仍然成立，补不上来源这一条。

私网地址接不住这次迁移

私网 10.0.1.15 给云里的其他资源用。你人在云外，改去连私网，仍然到不了这台实例。基准命令保持打在公网 203.0.113.15 上；进不去的原因在安全组来源。

本章避坑清单

  1. 私钥 demo-key.pem 只放在你自己的电脑上。不要把它的内容贴进网页，也不要贴进工单。
  2. 控制台「远程连接」和这条 ssh 是不是同一条路径，以该厂商现行文档为准。本课基准路径是 ssh 到公网 203.0.113.15。
  3. 这份镜像的登录名是 ubuntu。传入 root 时，reason 是「用户名不是 ubuntu」。
  4. 只绑定 demo-key 不够。安全组 sg-web-demo 还要放行入方向 TCP 22。
  5. 这条 22 的来源是 198.51.100.20/32。你的出口不是 198.51.100.20 时，规则照旧，ssh 进不去。
  6. 本章 permOk 固定为 true。不在这里判断服务器上的密钥文件权限。
