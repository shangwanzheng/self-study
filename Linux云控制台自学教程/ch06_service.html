第 6 章 · 跑起来

运行中不等于有人在听

控制台可以告诉你虚拟机开着。TCP 80 上有没有进程在听，要在同一次判断里看完三步：装了没有、active 没有、听在哪。

预计学习 40 分钟 前置：第 5 章 分步演示 1 个
  • 你能按「装了没有、active 没有、听在哪」排出失败原因。
  • 你能写出安装、启动、查看监听的三条基准命令。
  • 你能说明只听 127.0.0.1 时，公网网页仍然打不开。

6.1 前置检查

本章要用 第 5 章 的登录用户 ubuntu，把 sudo 放在需要改系统的命令最前面。下面三题确认这件事。答错就回第 5 章，过了再往下。

6.2 为什么学

前置过了：你已经能用 ubuntu 登录基准实例 web-demo，并在命令最前面加上 sudo。控制台此时往往写着「运行中」。网页打不开时，缺的是另一项证据。

基准实例在区域 cn-demo-1，实例 ID 是 i-demo0001，镜像是 Ubuntu 22.04 LTS。公网地址 203.0.113.15 是文档用地址，用来在教程里指这台机器，它不是你的电脑，也不是某台真实服务器。你在浏览器里打开 http://203.0.113.15/ 时，控制台上的「运行中」只说明这台虚拟机开着。

先想一想

控制台写着运行中，网页却打不开。你手头有没有「TCP 80 上有进程在听」的证据？

还没有。运行中记录的是虚拟机开着。有没有进程在 80 上听，要进系统看。厂商控制台上的状态名称会变，本章用教学词「运行中」；到你自己的云上，按钮名以该厂商现行文档为准。

这一章只回答有没有进程在听、听在哪个地址。下一章是「两道门都要放行」。

6.3 核心概念

上一节的缺口收成一句话：实例「运行中」不能回答「TCP 80 有没有进程在听」。安装、active、监听地址是同一次判断的三步。

先看正例。三步都成立，并且绑定地址是 0.0.0.0 时，调用 Course.linux.httpListen 得到 step「在听」、detail「0.0.0.0:80」。这里的 0.0.0.0 就是 Course.linux.baseline.bind。端口 80 是 baseline.httpPort。成功态的 bind 必须是 baseline.bind。

步骤你在问成立时不成立时函数停在
1装了没有包 nginx 已经在系统里未安装
2active 没有单元 nginx 是 active未运行
3听在哪有套接字听在 0.0.0.0:80未监听，或只听本机

套接字是进程用来占用端口、等待连接的端点。绑定地址是这个套接字接受连接的地址。0.0.0.0 表示在本机各个 IPv4 地址上听 80。127.0.0.1 是 baseline.loopback，只接受本机自己发来的连接。

再看反例。下面任一情况，函数都不会返回「在听」：

  • 控制台是运行中，系统里没有做这三步。
  • 包在，单元却不是 active。
  • 单元是 active，但没有套接字听 80。
  • 有套接字，但绑定是 127.0.0.1。公网网页打不开。
一次判断

函数按安装、active、监听、绑定地址的顺序停下。前面一步不成立时，后面的开关不改变这次的 step。四项同时成立，才是成功态。

6.4 逐步讲解这三步

概念已经有了。这一节按同一次判断的顺序，写出每一步用的基准命令，以及函数在哪一句停下来。本章只有下面四条命令，页面上的写法与示例文件逐字相同。

第一步：装了没有

镜像刚启动时，里面可以没有 nginx。控制台已经是运行中。你用第 5 章的 ubuntu 登录后，在 shell 里安装。这条命令最前面是 sudo，因为安装要改系统。

sudo apt-get install -y nginx

examples/ch06/install.sh

装完，installed 为真。若这一步不成立，httpListen 返回 step「未安装」，detail「镜像里没有 nginx」。后面的 active 和监听地址这次还没轮到。

包名和单元名

包名和单元名以镜像文档为准。本课教学镜像是 Ubuntu 22.04，包名和单元名都是 nginx。换一份镜像时，先查那份文档，再更换命令里的名字。不要把本课的名字写成所有系统的事实。

第二步：active 没有

包在磁盘上，进程可以还没起来。单元是 systemd 用来启动的那个名字，本课与包名相同，都是 nginx。下面这条把单元启动到 active：

sudo systemctl start nginx

examples/ch06/start.sh

启动之后用状态命令看它是不是 active。这条前面没有 sudo，按基准命令逐字写：

systemctl status nginx

examples/ch06/status.sh

先想一想

包已经装上，状态里却不是 active。你的下一步是再装一次，还是执行 start？

执行 start。安装只完成第一步。第二步不成立时，函数返回 step「未运行」，detail「包在，但 nginx 不是 active」。这时即使你把「正在监听」拨开，step 仍停在「未运行」。

第三步：听在哪

active 表示 systemd 认为这个单元在跑。套接字可以仍不在，也可以只绑在 127.0.0.1。用下面这条列出正在监听的 TCP 端口，地址和端口用数字显示：

ss -ltn

examples/ch06/ss.sh

-l 只看监听，-t 只看 TCP，-n 让地址和端口以数字出现。本课只关心 TCP 80 那一行。成功时你要看到地址 0.0.0.0、端口 80，也就是 detail「0.0.0.0:80」。

没有 80 这一行时，listening 为假，函数返回 step「未监听」，detail「服务是 active，但没有套接字听 80」。绑定地址这次还不参与。

有 80、地址却是 127.0.0.1 时，进程在听，听的是本机。step 是「只听本机」，detail 是「听在 127.0.0.1，公网访问会被拒绝」。公网网页打不开。配置文件在 /etc/nginx/nginx.conf，页面文件在 /var/www/html/index.html。本章不另给改配置的命令，绑定地址放在下面的演示里切换。

判断在哪一步停下

把四项一起交给 Course.linux.httpListen({installed, active, listening, bind})。返回里读 step 和 detail：

  1. 未安装：镜像里没有 nginx。
  2. 未运行：包在，但 nginx 不是 active。
  3. 未监听：服务是 active，但没有套接字听 80。
  4. 只听本机：听在 127.0.0.1，公网访问会被拒绝。
  5. 在听：0.0.0.0:80。这一行只有 bind 等于 baseline.bind 时出现。
三步一次看完拨动开关 · 切换绑定地址
观察要点：① 上面一行始终是运行中，开关改变的是下面三步。② 前一步停下时，后面的开关不改变 step。③ 三步都过、绑定为 0.0.0.0 时，step 为「在听」，detail 为 0.0.0.0:80。改成 127.0.0.1 后，step 为「只听本机」。

6.5 示范例题

三步和演示都有了。这一节只用基准实例的这一套数，走一遍成功态，并列出函数会停住的另外四行。

为什么选这些数：全课只有这一套。实例 web-demo（i-demo0001）在 cn-demo-1，镜像 Ubuntu 22.04 LTS，登录用户 ubuntu。包名和单元名都是 nginx。成功时绑定必须是 baseline.bind，本课是 0.0.0.0，端口是 80。公网 203.0.113.15 仍是文档用地址。控制台状态保持运行中，它不进入函数的参数。

基准成功态

已安装、active、正在监听，bind 取 baseline.bind。返回 ok 为真，step 是「在听」，detail 是「0.0.0.0:80」。

你在机器上的顺序就是上一节的四条命令：先安装，再 start，用 status 确认 active，用 ss -ltn 确认地址是 0.0.0.0、端口是 80。演示里把三个开关打开，绑定留在 0.0.0.0，读数应与这一行一致。

同一组输入进入 httpListen 的返回。前面一步已经失败时，后面的格子不再改变 step。
已安装active正在监听绑定stepdetail
否———未安装镜像里没有 nginx
是否——未运行包在，但 nginx 不是 active
是是否—未监听服务是 active，但没有套接字听 80
是是是127.0.0.1只听本机听在 127.0.0.1，公网访问会被拒绝
是是是0.0.0.0在听0.0.0.0:80

0.0.0.0 来自 baseline.bind，127.0.0.1 来自 baseline.loopback。表里的「—」表示这一格无论填什么，step 都已经由更前面的一步决定。

先想一想

三步里的前两步都过了，ss -ltn 里 80 的地址是 127.0.0.1。公网浏览器打得开吗？

打不开。函数给出「只听本机」。你把这个结果留到 6.8，那里只改绑定地址，再判断一次。

6.6 常见错误

例题里的成功态要四项同时成立。你容易在下面三处把「运行中」或前一步，当成已经有人在听。

只看运行中
控制台写着运行中，你就刷新网页。 运行中只说明虚拟机开着。进系统按三步看：装了没有、active 没有、听在哪。
装了但没启动
安装命令成功之后，你认为单元已经是 active。 包在，nginx 仍可以不是 active。接着执行 start，再用 status 看 active。函数这时的 step 是「未运行」。
只听本机
status 里已经是 active，你认为公网网页一定打得开。 active 过的是第二步。再用 ss 看地址。只看到 127.0.0.1:80 时，step 是「只听本机」，公网网页打不开。

这三处和包名、单元名那条，都收在章末避坑清单里。判断顺序也别跳：没装成就去解释监听地址，读到的 step 仍是「未安装」。

6.7 四类练习

用刚才的同一次判断做题。回忆、辨析、应用在这一节，解析紧跟在题后。迁移只改绑定地址，放在 6.8。

回忆

合上页面。按顺序说出这三步，并说出成功时的 step 和 detail。

解析

正确答案：装了没有、active 没有、听在哪。成功时 step 是「在听」，detail 是「0.0.0.0:80」。

关键步骤：先安装，再确认 active，再看监听地址。成功态的绑定等于 baseline.bind，本课是 0.0.0.0。

常见错误答案：只回答「运行中」。错因：运行中只说明虚拟机开着，函数的参数里没有这一项。

做错回看：6.3 核心概念。

辨析

下面两句，哪句是正例，哪句是反例？

  1. 已安装、active、正在监听，绑定 0.0.0.0。
  2. 控制台是运行中，于是直接刷新 http://203.0.113.15/。

解析

正确答案：第 1 句是正例，step 为「在听」，detail 为「0.0.0.0:80」。第 2 句是反例，三步都还没有证据。

关键步骤：正例要四项同时成立，绑定取 baseline.bind。反例停在控制台的「运行中」。

常见错误答案：把第 2 句当成正例。错因：把虚拟机开着当成 TCP 80 上有进程在听。

做错回看：6.3 核心概念、6.6 常见错误。

应用

基准实例上：已安装为真，active 为假，正在监听为真，绑定为 0.0.0.0。step 是什么？detail 是什么？你下一步执行哪一条基准命令？

解析

正确答案：step「未运行」，detail「包在，但 nginx 不是 active」。下一步执行 sudo systemctl start nginx，再用 systemctl status nginx 看是不是 active。

关键步骤：函数按安装、active、监听、绑定的顺序停。第二步已经失败，后面的「正在监听」和 0.0.0.0 不改变这次的 step。

常见错误答案：「在听」，理由是绑定已经是 0.0.0.0。错因：跳过了 active。另一错法是回答「未监听」。错因：未监听要等 active 已经成立、并且没有套接字时才出现。

做错回看：6.4 逐步讲解这三步，尤其是第二步。

迁移题在下一节：保持已安装且 active，只把绑定从 0.0.0.0 改成 127.0.0.1。

6.8 迁移

应用题停在「未运行」。这一节换一个已经走过前两步的场景，只动监听地址。

条件：包已经安装，单元 nginx 是 active，正在监听为真。绑定从 0.0.0.0 改成 127.0.0.1。公网网页打得开吗？

到演示里把三个开关都打开，绑定选 127.0.0.1，读出 step 和 detail。这一改只动绑定，安装和 active 保持成立。

解析

正确答案：公网网页打不开。ok 为假，step 是「只听本机」，detail 是「听在 127.0.0.1，公网访问会被拒绝」。

关键步骤：已安装且 active，所以不会停在「未安装」或「未运行」。正在监听为真，判断进入绑定地址。这个地址是 baseline.loopback，不是 baseline.bind，因此不是「在听」。

常见错误答案：打得开，因为已经 active。错因：active 只过了第二步。地址是 127.0.0.1 时，听的是本机，公网网页打不开。

做错回看：6.3 核心概念、6.4 第三步。

本章避坑清单

  1. 只看控制台「运行中」就刷新网页。运行中只说明虚拟机开着。TCP 80 有没有进程在听，要看安装、active、监听地址。
  2. 装了包但没 start。包在，nginx 仍可以不是 active。接着执行启动命令，再用 status 确认。此时 step 是「未运行」。
  3. active 但只听 127.0.0.1。公网网页打不开。成功态要听在 0.0.0.0:80，绑定必须是 baseline.bind。
  4. 包名和单元名以镜像文档为准。本课是 Ubuntu 22.04，包名和单元名都是 nginx。换镜像先查文档，再换命令里的名字。
  5. 判断跳步。没装成时，step 停在「未安装」。active 还没成立时，不会先给出「未监听」或「只听本机」。

本章小结与延伸阅读

实例在运行，只说明虚拟机开着；TCP 80 有没有进程在听，要一次看完安装、active 和监听地址。

  • 没装，step 是「未安装」。
  • 装了但不是 active，step 是「未运行」。
  • active 但没有套接字，step 是「未监听」；套接字在 127.0.0.1，step 是「只听本机」，公网网页打不开。
  • 成功态的 bind 是 baseline.bind，即 0.0.0.0。step 是「在听」，detail 是 0.0.0.0:80。
