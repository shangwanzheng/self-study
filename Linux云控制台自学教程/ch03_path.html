命令落在当前目录

你登录之后，shell 站在一个目录里。相对路径从这里往下接；以 / 开头的绝对路径自己说完整个位置。

预计学习 45 分钟 前置：第 2 章 分段演示 1 个
  • 能把一条相对路径解析成绝对路径。
  • 能说明从 /home/ubuntu 输入 nginx.conf 到不了 /etc/nginx/nginx.conf。
  • 能说明 /data 和 data 不是同一个位置。

3.1 前置检查

第 2 章结束时，用户名、密钥、安全组入方向 TCP 22 这三条同时成立，你才能进到基准实例的 shell。下面 3 题确认这件事还在。这 3 题不计入章末自测。

还没把握的话，先回到 第 2 章 登录要三条同时成立，再做这 3 题。

3.2 为什么学

前置检查过了，说明你知道怎样登录 web-demo。登录成功之后，第一条命令会改哪一个目录，第 2 章没有回答。本章只回答这一件事。

基准实例的登录用户是 ubuntu。刚登录、还没有成功执行过 cd 时，当前目录是 /home/ubuntu。这是全课基准里的家目录。你随后输入的文件名，默认就接在这个目录后面。

后面几章要看 nginx 的配置，也要看数据盘挂载点。配置文件在 /etc/nginx/nginx.conf，数据盘出现在 /data。你若站在家目录里只敲文件名，命令碰到的是家目录里的另一个名字，配置文件和数据盘都还在原地。

先停一下。你刚登录，还没有 cd。这时输入 nginx.conf，你以为自己在看哪一个文件？先写下绝对路径，再往下读。

这一节先记住起点：登录后的当前目录是 /home/ubuntu。下一节给这个起点起两个名字，相对路径和绝对路径。

3.3 核心概念

上一节把问题收成「先知道自己站在哪」。站的那个位置叫当前目录。有的手册把它写作工作目录，本章统一叫当前目录。

相对路径取决于当前目录。本章用来练习的相对路径是 nginx.conf、data 和 error.log，它们都不以 / 开头。shell 把它们接在当前目录后面，得到一条绝对路径。

绝对路径不取决于当前目录。本章用来练习的绝对路径是 /etc/nginx/nginx.conf 和 /data，它们以 / 开头。/ 是根目录，路径从根自己说完，换当前目录不会把它改接到别处。

正例

当前目录无论是 /home/ubuntu、/、/etc/nginx 还是 /data，输入 /etc/nginx/nginx.conf，解析结果都是这条路径本身。它等于基准里的 nginx 配置。输入 /data，解析结果都是基准里的数据盘挂载点。

反例

同一个名字 nginx.conf，当前目录是 /etc/nginx 时，落到 /etc/nginx/nginx.conf。当前目录是 /home/ubuntu 时，落到 /home/ubuntu/nginx.conf。文件名相同，位置不同。

一句定义

相对路径取决于当前目录。绝对路径不取决于当前目录。动手之前先确认当前目录，再决定要写哪一种路径。

定义到这里就够用。下一节按 Course.linux.resolve 的规则，把一条输入算成绝对路径。

3.4 逐步讲解

上一节的定义要变成你能亲手算的步骤。本章演示调用的就是 Course.linux.resolve(当前目录, 输入)。你在纸上也可以按同样的规则来算。本章这几条输入里没有 .、.. 和重复斜杠，所以结果就是下面接出来的绝对路径。

  1. 看输入的第一个字符。
  2. 第一个字符是 /：结果就是这条路径。当前目录不参与。
  3. 第一个字符不是 /：把当前目录和这条输入用 / 接起来。当前目录本身是 / 时，先去掉它末尾的斜杠再接，于是 data 变成 /data。

所以你要先看见当前目录。登录后打印它的命令是：

pwd

examples/ch03/pwd.sh 与上面这一行逐字相同，文件末尾另有一个换行。刚登录、还没有执行成功的 cd 时，这条命令打印 /home/ubuntu。

3.5 示范例题

步骤有了。这一节固定用基准实例里后面还会反复出现的位置：家目录 /home/ubuntu、配置 /etc/nginx/nginx.conf、挂载点 /data。选这组，是因为登录后你就站在家目录，而配置和数据盘都不在家目录里面。

当前目录固定为 /home/ubuntu

四条输入都调用 Course.linux.resolve('/home/ubuntu', 输入)。

家目录上的四次解析，外加两个对照行。等于一列只对照基准配置和基准挂载点。

/home/ubuntunginx.conf/home/ubuntu/nginx.conf否否

前四行是例题本身。第五行说明：相对路径 nginx.conf 要到达配置文件，当前目录得先是 /etc/nginx。第六行说明：当前目录是根时，相对路径 data 会落到挂载点；这和家目录那一行不同。

例题的用法就这两句。要看配置，写 /etc/nginx/nginx.conf，或先让当前目录变成 /etc/nginx 再写 nginx.conf。要看数据盘，写 /data。下一节把最容易看反的两行单独拿出来。

3.6 常见错误

例题里的第一行和第三行，就是最容易看反的两种结果。你人还在 /home/ubuntu，相对路径却被当成已经到了 /etc 或 /data。

家目录里的 nginx.conf

你在 /home/ubuntu 输入 nginx.conf，命令落到 /home/ubuntu/nginx.conf。配置文件在 /etc/nginx/nginx.conf。两条路径不同，这条相对路径没有碰到配置文件。

把 /data 写成 data

数据盘挂载点是 /data。你在家目录输入 data，命令落到 /home/ubuntu/data。挂载点要写成以 / 开头的 /data。

先停一下。cd 报错之后，下一条相对路径从哪一个目录出发？
cd 失败时当前目录不变

你想进入 /etc/nginx，命令却报错了。当前目录仍是报错前 pwd 打印的那个目录。接着输入的 nginx.conf 还是从原目录起算。若你当时站在 /home/ubuntu，它仍然落到 /home/ubuntu/nginx.conf。本课按常见 shell 记这条：cd 没有成功，当前目录保持原样。你的镜像若不是 bash，以该 shell 的手册为准。

3.7 四类练习

常见错误看过了。下面四题由易到难：回忆、辨析、应用、迁移。每题后面就是解析，含错答和该回看的节。

回忆

合上页面，用两句话分别说出相对路径和绝对路径各取决于什么。

正确答案。相对路径取决于当前目录。绝对路径不取决于当前目录。

关键步骤。看第一个字符。不以 / 开头的接到当前目录后面；以 / 开头的自己说完位置。

常见错答。两种路径都取决于当前目录，或两种都不取决于。错因是把「路径」当成一种东西，没有先看它开不开头的 /。

回看。3.3 核心概念。

辨析

判断这句：「我在家目录，输入 nginx.conf，改的就是 /etc/nginx/nginx.conf。」

正确答案。这句不成立。当前目录 /home/ubuntu 加上 nginx.conf，落到 /home/ubuntu/nginx.conf。

关键步骤。nginx.conf 不以 / 开头，所以 resolve 把它接在家目录后面。配置文件那条绝对路径没有出现在结果里。

常见错答。因为文件名一样，就认为全机只有这一份。错因是用名字代替了路径。

回看。3.6 常见错误。

应用

当前目录是 /home/ubuntu。分别写出 data 和 /data 的绝对路径，并指出哪一个等于基准挂载点。

正确答案。data 落到 /home/ubuntu/data。/data 落到 /data。后者等于 baseline.dataMount。

关键步骤。第一条是相对路径，接在家目录后面。第二条以 / 开头，当前目录不参与。

常见错答。两条都写成 /data，或两条都写成 /home/ubuntu/data。错因是漏看开头有没有 /。

回看。3.5 示范例题。

迁移

你一直在家目录里试 data。现在把当前目录换成 /，输入仍然是 data。绝对路径是什么？它等于挂载点吗？

正确答案。/data。它等于基准挂载点。

关键步骤。当前目录是根。相对路径 data 接在根后面，resolve 去掉根目录末尾的斜杠再拼接，得到 /data。

常见错答。仍然写成 /home/ubuntu/data。错因是把家目录那一题的结果搬过来，没有改当前目录再算一次。

回看。3.4 逐步讲解。

根目录这一次说明：同一条相对路径，换了当前目录就要重算。下一节换到日志目录，用基准里的错误日志再做一次。

3.8 迁移

上一节把当前目录换成了根，相对路径 data 落到了挂载点。这一节换成 nginx 错误日志所在的目录。日志路径用基准里的 errorLog 对照，文件名仍是 error.log。

当前目录是 /var/log/nginx。输入相对路径 error.log。它落到哪里？

正确答案。/var/log/nginx/error.log。这就是 baseline.errorLog。

关键步骤。error.log 不以 / 开头，接在当前目录 /var/log/nginx 后面。拼出来的绝对路径与基准错误日志逐字相同。

常见错答。写成 /home/ubuntu/error.log，因为登录后的目录还留在脑子里；或写成配置文件 /etc/nginx/nginx.conf，把配置路径当成了日志路径。错因都是没有用这一节给出的当前目录重算。

回看。3.3 核心概念、3.4 逐步讲解。

若你这时仍站在 /home/ubuntu，同一条 error.log 会落到 /home/ubuntu/error.log，那不是基准错误日志。要碰到 baseline.errorLog，要么当前目录已经是 /var/log/nginx 再写相对路径，要么直接写绝对路径 /var/log/nginx/error.log。

这条日志的位置你已经能指认。下一章不改这条规则，它要处理的是：密钥已经绑定，服务器上的目录权限仍可能拒绝登录。

本章避坑清单

  1. 先 pwd，再写相对路径。刚登录时当前目录是 /home/ubuntu。你已经 cd 过，就以最新一次成功的 pwd 为准。
  2. 家目录里的 nginx.conf 到不了配置文件。从 /home/ubuntu 输入 nginx.conf，落到 /home/ubuntu/nginx.conf，碰不到 /etc/nginx/nginx.conf。
  3. 家目录里的 data 不是数据盘。把挂载点写成 data，会落到 /home/ubuntu/data。挂载点是 /data。
  4. 根目录下的 data 要单独重算。当前目录是 / 时，相对路径 data 落到 /data。不要把家目录那一题的结果照搬过来。
  5. cd 失败时当前目录不变。报错之后，下一条相对路径仍从原来的目录起算。
  6. 本章只认落点。编辑器留到后面需要改文件时再学。

本章小结与延伸阅读

相对路径取决于当前目录，绝对路径不取决于当前目录；写相对路径之前，先用 pwd 确认自己站在哪。

  • 刚登录时当前目录是 /home/ubuntu。
  • 从家目录输入 nginx.conf，落到 /home/ubuntu/nginx.conf，到不了 /etc/nginx/nginx.conf。
  • 从家目录输入 data，落到 /home/ubuntu/data；挂载点要写 /data。
  • 当前目录是 /var/log/nginx 时，相对路径 error.log 落到 /var/log/nginx/error.log。
  • cd 失败时当前目录不变。本章不学编辑器。

下一章是「密钥绑定了，权限仍会拒绝」。密钥已经绑在实例上之后，sshd 仍会看 /home/ubuntu/.ssh 和 /home/ubuntu/.ssh/authorized_keys 的属主与写权限。那两条是绝对路径；权限是另一件事，到 第 4 章 再判断接受还是拒绝。
