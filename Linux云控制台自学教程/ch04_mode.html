第 4 章 · 进得去

密钥绑定了，权限仍会拒绝

控制台已经绑定密钥 demo-key。sshd 仍会检查 /home/ubuntu/.ssh 和 authorized_keys：属主必须是 ubuntu，而且目录和文件都不能对组或其他人可写。

预计学习 40 分钟 前置：第 3 章 分段演示 1 个
  • 指出要看的两个路径：/home/ubuntu/.ssh 和 /home/ubuntu/.ssh/authorized_keys。
  • 用 Course.linux.sshAccepts 的规则判断接受还是拒绝。
  • 说明建议值是目录 700、文件 600，而 755 配 644 仍然接受。

4.1 前置检查

上一章你已经能分清相对路径和绝对路径。这一章的两个路径都是绝对路径。先用 3 题确认第 3 章还在，再进入权限。这 3 题单独计分，不计入章末自测。

路径以基准算例为准：家目录 /home/ubuntu，配置文件 /etc/nginx/nginx.conf，数据盘挂载点 /data。需要时回到 第 3 章 命令落在当前目录。

4.2 为什么学

第 2 章登录时，文件权限被固定成通过。用户名、密钥绑定、安全组 TCP 22 三条齐了，就可以讨论「进得去」。真实登录还会再过一关：公钥已经写在服务器上，sshd 仍可能因为属主或写权限拒绝这把钥匙。

控制台里「绑定密钥」是本课的教学说法。各家按钮名称会变，以该厂商现行文档为准。绑定成功只说明公钥进了 authorized_keys。它不代替你检查属主，也不代替你检查目录和文件是否对组或其他人可写。

所以这一章只做一件事：给定属主、目录模式、文件模式，判断 sshAccepts 返回的 ok 和 reason。实例仍是基准里的 web-demo，登录用户仍是 ubuntu，密钥名仍是 demo-key。

先想一下

控制台已经显示密钥绑定成功，ssh 仍被拒绝。你下一步要打开的是服务器上的哪两个路径？想完再看下一节。

4.3 核心概念

本课用 Course.linux.sshAccepts(dirMode, keyMode, ownerIsUser) 表示 sshd 在这台教学实例上的判断。它对应 OpenSSH 里常见的 StrictModes 行为：属主必须是登录用户，.ssh 和 authorized_keys 都不能对组或其他人可写。教学实例就按这个函数判，不另加一套规则。镜像若改过 sshd_config，以该镜像文档为准。

两个路径只从基准算例来：

  • 目录：baseline.sshDir，值是 /home/ubuntu/.ssh。
  • 文件：baseline.authKeys，值是 /home/ubuntu/.ssh/authorized_keys。

模式写成 chmod 那种八进制。每三位依次是属主、组、其他人。r 是读，w 是写，x 是执行；对目录来说，x 表示能进入这个目录。组或其他人那一位上出现 w，函数就拒绝。

先看正例

建议值

属主是 ubuntu，目录 700（rwx------），文件 600（rw-------）。ok 为 true，reason 为「sshd 接受这把密钥」。基准里的建议值 suggestDir、suggestKey 就是这一对。

较宽，仍然接受

属主是 ubuntu，目录 755（rwxr-xr-x），文件 644（rw-r--r--）。组和其他人可以读、可以进入目录，不能写。ok 仍为 true。建议值仍是目录 700、文件 600。

再看反例

目录对组可写

目录 775（rwxrwxr-x）时，组有写权限。reason 为「.ssh 对组或其他人可写」。文件即使已经是 600，也过不了这一关。

属主不是 ubuntu

模式仍是 700 和 600，属主换成别人（迁移一节里是 root）。reason 为「属主不是 ubuntu」。建议模式不会把这一条救回来。

文件 664（rw-rw-r--）是另一条反例：组可以改 authorized_keys。reason 为「authorized_keys 对组或其他人可写」。目录 700 也救不了这个文件。

这一节要记住的三句

属主必须是 ubuntu。目录和文件只要对组或其他人可写，就拒绝。755 配 644 可以接受，建议值仍是目录 700、文件 600。

4.4 逐步讲解

上一节给了正例和反例。这一节按函数的返回顺序往下走。它遇到第一条失败就停，所以 reason 只报最先那一条。

  1. 属主不是 ubuntu：拒绝，reason 是「属主不是 ubuntu」。
  2. 目录缺少属主的读和执行，属主进不去：拒绝，reason 是「属主进不了 .ssh」。演示里的 700、755、775 都有属主的 rwx，这一关都过。
  3. 目录对组或其他人可写：拒绝，reason 是「.ssh 对组或其他人可写」。775 在这里失败。
  4. 文件缺少属主的读：拒绝，reason 是「属主读不了 authorized_keys」。演示里的 600、644、664 都有属主的读，这一关都过。
  5. 文件对组或其他人可写：拒绝，reason 是「authorized_keys 对组或其他人可写」。664 在这里失败。

五关都过，ok 为 true，reason 是「sshd 接受这把密钥」。

因此目录 775、文件 664、属主仍是 ubuntu 时，先报目录，不报文件。属主已经不是 ubuntu 时，后面的 775 或 664 都不会改写这句 reason。

755 配 644 为什么仍然接受

先自己判一次

属主是 ubuntu，目录 755，文件 644。你判断接受还是拒绝？看完再对照下表。

755 的组和其他人是 r-x，没有 w。644 的组和其他人是 r--，也没有 w。函数拒绝的是写，不是「别人能不能读」。所以这一对接受。700 和 600 更紧：组和其他人连读都没有。能被接受，和建议值是两件事。下面这张表和函数一致，你可以在演示里逐行点出来。

4.5 示范例题

上一节的表可以逐行点。这一节用基准实例走一遍：先看到拒绝，再改到建议值。

教学控制台上，实例名 web-demo，镜像 Ubuntu 22.04 LTS，密钥 demo-key 已经绑定，登录用户是 ubuntu。你在服务器上看到：目录 /home/ubuntu/.ssh 的模式是 775，文件 /home/ubuntu/.ssh/authorized_keys 的模式是 644，两个路径的属主都是 ubuntu。

调用 sshAccepts(0o775, 0o644, true)。ok 为 false，reason 是「.ssh 对组或其他人可写」。文件 644 本身可以被接受，可是函数先看目录，775 已经失败，所以不会报成文件的问题。

改之前先看清对象

目录和文件各有一条命令。先看你要改的是目录 /home/ubuntu/.ssh，还是文件 authorized_keys。把文件的 600 用到目录上，属主没有执行位，进不了 .ssh，reason 是「属主进不了 .ssh」。把目录的 700 用到文件上，函数仍然接受，因为属主能读，组和其他人也不能写；建议的文件模式仍是 600。

目录用这一条：

chmod 700 /home/ubuntu/.ssh

examples/ch04/chmod-ssh-dir.sh

文件用这一条：

chmod 600 /home/ubuntu/.ssh/authorized_keys

examples/ch04/chmod-authorized-keys.sh

两条都做完，属主仍是 ubuntu。再调用 sshAccepts(0o700, 0o600, true)，ok 为 true，reason 是「sshd 接受这把密钥」。这一对就是建议值。只改文件、把目录留在 775，结果仍是拒绝。

4.6 常见错误

上一节的两条命令是收紧到建议值。下面三句是把同一套规则说反时最常见的样子。

chmod 777
「先 777，登录成功再收紧。」 777 是 rwxrwxrwx，组和其他人都有写位。用在目录上，reason 是「.ssh 对组或其他人可写」。用在文件上，reason 是「authorized_keys 对组或其他人可写」。目录和文件都是 777 时，先报目录。上一节问的那种改法，ok 是 false。
两把钥匙看混了
「我把电脑上 demo-key.pem 的权限改好了，服务器上的 authorized_keys 就不用看。」 demo-key.pem 在操作者电脑上，第 2 章的命令用 ssh -i demo-key.pem ubuntu@203.0.113.15 带上它。服务器上 sshd 读的是 authorized_keys。电脑上那把私钥的权限，代替不了服务器上这两个路径的属主和写权限。
私钥不在这台实例上

不要到 web-demo 里去找 demo-key.pem 的权限。这台实例上和密钥登录有关、并且本课要检查的，只有 /home/ubuntu/.ssh 和 /home/ubuntu/.ssh/authorized_keys。

属主变成 root
「模式已经是 700 和 600，谁当属主都能登录。」 属主是 root 时，ownerIsUser 为 false。函数第一关就返回 ok false，reason 是「属主不是 ubuntu」。下一节的迁移就是这个情形。
和「644 一律失败」分开

644 的组和其他人只读，写位是关的。属主是 ubuntu、目录是 755 或 700 时，文件 644 会被接受。要拒绝的是 775、664、777 这种把写位开给组或其他人的模式。

4.7 四类练习

四题由易到难。做完立刻看解析：正确答案、关键步骤、常见错答和错因，以及该回看的节。

回忆

合上页面。这台实例上要检查的两个路径是什么？建议的目录模式和文件模式是什么？属主是 ubuntu 时，755 配 644，接受还是拒绝？

解析

正确答案：目录 /home/ubuntu/.ssh，文件 /home/ubuntu/.ssh/authorized_keys。建议值是目录 700、文件 600。755 配 644，属主是 ubuntu 时接受，reason 是「sshd 接受这把密钥」。

关键步骤：路径只取基准的 sshDir 和 authKeys。接受看的是属主加上写位，建议值是更紧的那一对。

常见错答：「644 一律失败」，或只说出私钥文件名 demo-key.pem。错因：644 没有把写位开给组或其他人；demo-key.pem 在操作者电脑上。

回看：4.3 核心概念、4.4 逐步讲解。

辨析

下面哪一句和 sshAccepts 一致？

  1. 控制台绑定成功之后，sshd 不再看属主和写权限。
  2. 属主不是 ubuntu，或者目录或文件对组或其他人可写，sshd 就拒绝。属主是 ubuntu 时，755 配 644 可以接受。建议值仍是 700 和 600。
  3. 文件模式只要出现 644，结果一定是拒绝。

解析

正确答案：第 2 句。

关键步骤：用函数的三条出口对照：属主、目录写位、文件写位。755 和 644 的写位是关的，所以第 2 句里的「可以接受」成立。

常见错答：选第 1 句或第 3 句。错因：绑定只说明公钥进了文件。第 3 句把「写位打开才拒绝」记成了「出现 644 就拒绝」。

回看：4.3 核心概念、4.6 常见错误。

应用

实例 web-demo，用户 ubuntu，密钥 demo-key 已绑定。目录 /home/ubuntu/.ssh 是 700，文件 authorized_keys 是 664，属主都是 ubuntu。写出 ok 和 reason。

解析

正确答案：ok 为 false，reason 是「authorized_keys 对组或其他人可写」。

关键步骤：属主通过。目录 700 能进入，组和其他人也不能写。文件 664 是 rw-rw-r--，组有写位，在第五关拒绝。

常见错答：接受，因为目录已经是建议的 700。错因：目录通过之后还要单独看文件。只改目录、把文件留在 664，登录仍会被拒绝。

回看：4.4 逐步讲解。

迁移

模式仍是目录 700、文件 600，属主改成了 root。写出 ok 和 reason。完整情景在下一节。

解析

正确答案：ok 为 false，reason 是「属主不是 ubuntu」。

关键步骤：ownerIsUser 为 false。函数在第一关返回，700 和 600 不会把结果改成接受。

常见错答：接受，因为模式已经是建议值。错因：建议值只在属主是 ubuntu 时同时成立。root 当属主，建议模式也过不了第一关。

回看：4.4 逐步讲解、4.8 迁移。

4.8 迁移

上一题把属主换成了 root。这里把场景补全，数字仍是基准里的那一对建议模式。

你为了修改权限使用了提权，做完之后 /home/ubuntu/.ssh 和 authorized_keys 的属主都变成了 root。你再核对模式：目录仍是 700，文件仍是 600。控制台上的密钥绑定没有取消，安全组也没有改。

回到演示：目录选 700，文件选 600，取消「属主是 ubuntu」。读数是 ok false，reason「属主不是 ubuntu」。sshd 拒绝这把密钥。

把属主改回 ubuntu，模式仍保持 700 和 600，同一调用变成 sshAccepts(0o700, 0o600, true)，ok 为 true。权限这一关过了之后，下一章才谈得上「登录用户不是 root」：人是 ubuntu，写系统配置时还要另加 sudo。提权本身会在后面用到；这一章要你先看见提权留下的属主，会让 sshd 在进门时就拒绝。

迁移结论

属主是 root，目录 700，文件 600：拒绝。原因句是「属主不是 ubuntu」，不是目录或文件的写权限。

本章避坑清单

  1. 改权限前先看清是目录还是文件。目录用 chmod 700 /home/ubuntu/.ssh，文件用 chmod 600 /home/ubuntu/.ssh/authorized_keys。把 600 用在目录上，属主进不了 .ssh。
  2. chmod 777 会把写位开给组和其他人。用在目录或文件上，sshd 都拒绝。
  3. 操作者电脑上 demo-key.pem 的权限，不能代替服务器上 authorized_keys 的权限。私钥不在这台实例上。
  4. 属主是 root 时，模式仍是 700 和 600，sshd 仍拒绝，reason 是「属主不是 ubuntu」。
  5. 755 配 644、属主是 ubuntu 时，函数接受。建议值仍是目录 700、文件 600。不要把 644 记成一律失败。
