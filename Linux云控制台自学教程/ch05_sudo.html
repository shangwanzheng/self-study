5.1 前置检查

第 4 章确认过：密钥已经绑上，sshd 仍会看服务器上的属主和写权限。下面三题只检查这件事。答完再进入 sudo。这三题不计入章末自测。

5.2 为什么学

你已经能登录。第 2 章把用户名固定成 ubuntu，第 4 章让 sshd 收下这把密钥。登录成功之后，提示符左边仍是 ubuntu，家目录是 /home/ubuntu。接下来你要看的文件不在家目录里，而在 /etc/nginx/nginx.conf。

很多人这时会去改登录名。这份教学镜像的登录用户写在基准里，就是 ubuntu。系统配置目录不跟着家目录一起放开。你人已经进来了，写 /etc 仍要单独取得一次提权。

先想一下。提示符上是 ubuntu。直接去写 /etc/nginx/nginx.conf，和在命令最前面加上 sudo，会是同一种结果吗？先有个判断，再看后面的定义。

这一章只解决「谁有权写这个路径」。nginx 装没装、有没有进程在听，留到下一章。这里不出现安装命令。

5.3 核心概念

先把三个词定死，再看正例和反例。后面的演示只使用 ubuntu 和 root 这两个名字。

登录用户

登录用户是你 ssh 进去之后的那个账户。基准实例 web-demo 的镜像是 Ubuntu 22.04 LTS，登录用户是 ubuntu，家目录是 /home/ubuntu，主机名是 web-demo。控制台把你放进系统，不会把你变成 root。

root

root 是可以直接写 /etc/nginx/nginx.conf 的超级用户。它能写，是因为它就是 root。本课的登录路径仍使用 ubuntu。你在演示里可以把身份拨到 root，用来看函数的另一支；真正登录时保持 ubuntu。

sudo

sudo 放在整条命令的最前面，让后面这一条命令以更高权限执行。教学实例假定 ubuntu 在 sudo 组里，所以 ubuntu 可以使用 sudo。提权只覆盖这一条命令。下一条若不再把 sudo 放在最前面，权限又回到 ubuntu 自己的范围。

正例

用户是 ubuntu，并且使用 sudo。可以写。原因是「ubuntu 通过 sudo 可以写」。

反例

用户仍是 ubuntu，但没有 sudo。不能写。原因是「ubuntu 没有 sudo 时写不了 /etc」。家目录里能新建文件，改变不了这句原因。

还有一支要单独记住：用户是 root 时，可以直接写，原因是「root 可以直接写 /etc/nginx/nginx.conf」。这一支不读取「有没有 sudo」。它用来对照，不是让你把登录名改掉。

与 Course.linux.canWriteEtc 的返回一致。原因一句不改写。
用户使用 sudo能否写入原因
ubuntu否不能ubuntu 没有 sudo 时写不了 /etc
ubuntu是能ubuntu 通过 sudo 可以写
root否或是能root 可以直接写 /etc/nginx/nginx.conf

收束：能写 /etc/nginx/nginx.conf 的教学路径是「ubuntu + sudo」。root 那一行只说明超级用户本身可以写。

5.4 逐步讲解

上一节给出了三行结果。这一节按你登录之后的顺序，说明这三行从哪来。判断函数是 Course.linux.canWriteEtc(user, useSudo)。

登录之后你仍是 ubuntu

密钥被 sshd 接受之后，会话属于 ubuntu。当前目录若还停在家目录，你能在 /home/ubuntu 里放自己的文件。这份权利停在家目录。/etc/nginx/nginx.conf 是绝对路径，人在哪个目录都能指到它，指到不等于写得进。

函数先看用户，再看 sudo

把用户和开关交进去，函数按下面的顺序给原因。

  1. 用户是 root：返回可以写，原因固定为「root 可以直接写 /etc/nginx/nginx.conf」。后面的开关不再参与。
  2. 用户是 ubuntu，并且使用 sudo：返回可以写，原因是「ubuntu 通过 sudo 可以写」。
  3. 用户是 ubuntu，并且没有 sudo：返回不能写，原因是「ubuntu 没有 sudo 时写不了 /etc」。

你要带走的是第 2 步。第 1 步用来认识 root 能写什么。把 ssh 的登录名改成 root，动的是第 2 章的登录条件，不是本章的写法。

sudo 必须是命令的第一个词

shell 把第一个词当成要执行的程序。sudo 在最前面时，它去执行后面的 ls 和路径，ls 因此带着提权去碰 /etc/nginx/nginx.conf。把 sudo 挪到中间或末尾，第一个词不再是 sudo，提权不会发生。

本章用来碰到这个路径的命令只有一行，sudo 在最前面：sudo ls /etc/nginx/nginx.conf。它只列出这个路径。文件还没出现时，你会看到找不到文件，那是下一章要处理的安装问题。身份不对时，不带 sudo 的写入会被拒绝，文件内容保持原样。

口令不在本课里

教学实例假定 ubuntu 在 sudo 组。sudo 若向你要口令，以这份镜像的文档为准。本课不写出口令，也不猜测一个。

动手前先猜。把用户停在 ubuntu，先不要勾选。你预期读出的原因是「ubuntu 没有 sudo 时写不了 /etc」。勾上之后再看它有没有换成另一句。

观察要点：① ubuntu 不勾选时，原因是「ubuntu 没有 sudo 时写不了 /etc」。② 勾上之后，原因变成「ubuntu 通过 sudo 可以写」。③ 拨到 root 后，勾不勾选，原因都是「root 可以直接写 /etc/nginx/nginx.conf」。

左栏和右栏的原因来自同一次调用。你读到的句子应当与上一节的表一致。演示里没有第三个用户名。

5.5 示范例题

规则已经能判三种输入。这一节把基准实例收成一条可以照着敲的命令，并说明为什么是这一条。

基准实例 web-demo

镜像 Ubuntu 22.04 LTS，登录用户 ubuntu，配置路径 /etc/nginx/nginx.conf。目标是不改登录名，把 sudo 放在最前面去碰到这个路径。用这对输入判断写入，落在「ubuntu 通过 sudo 可以写」那一支。

选择 ubuntu，是因为它就是基准里的登录用户。把 sudo 放在最前面，是因为 useSudo 要为真，函数才会给出「ubuntu 通过 sudo 可以写」。命令用 ls 这个路径，是因为本章只把 sudo 和 /etc/nginx/nginx.conf 放在同一行里。安装 nginx 是第 6 章的事，这里不写安装命令。

sudo ls /etc/nginx/nginx.conf

同一份命令：examples/ch05/sudo-ls-nginx-conf.sh

这行命令对应的输入是 user 为 ubuntu、useSudo 为真。用这对输入判断能不能写，返回可以写，原因是「ubuntu 通过 sudo 可以写」。ls 本身不修改文件。同一次写入若拿掉最前面的 sudo，输入变成 useSudo 为假，原因换成「ubuntu 没有 sudo 时写不了 /etc」，文件不会被改掉。

文件尚未安装出来时，这行 ls 会告诉你路径不存在。那一句说的是「还没有这个文件」，不是「ubuntu 写不了 /etc」。两种话要分开听。身份问题用本节的函数判断，安装问题留到下一章。

5.6 常见错误

示范命令已经摆正。下面三处是最容易在这一步走偏的地方，每处都先给正解。

把登录名改成 root

登录名保持 ubuntu。要写 /etc/nginx/nginx.conf 时，在命令最前面加 sudo。

把登录名改成 root。登录条件里的用户名就不再是 ubuntu。写配置要走的是 sudo 这一支，不是更换登录名。

sudo 写在命令中间

sudo 是第一个词，例如 sudo ls /etc/nginx/nginx.conf。

写成 ls sudo /etc/nginx/nginx.conf，或把 sudo 放在路径后面。shell 执行的是 ls，sudo 只是参数，提权没有发生。

家目录可写就当成 /etc 可写

/home/ubuntu 能写，只说明家目录属于 ubuntu。写 /etc/nginx/nginx.conf 仍要 sudo。

在家目录新建成功，就断定系统配置也能直接改。两个路径的权限分开算。函数在没有 sudo 时给出的是「ubuntu 没有 sudo 时写不了 /etc」。

组与口令

教学实例假定 ubuntu 在 sudo 组，所以上面的正例走得通。口令提示以镜像文档为准。不要把别处见过的口令抄过来，也不要现编一个填进去。

这三处误解和这条避坑，都会收进章末清单。

迁移

同一条写配置的操作，只把操作者从「已经 sudo」换成「忘记 sudo」。文件还会被改掉吗？先写判断，再打开 5.8 对解析。

5.8 迁移

5.7 的应用题里，你已经能让 ubuntu 通过 sudo 写到配置路径。现在保持那一条写配置的操作不变：路径仍是 /etc/nginx/nginx.conf，登录用户仍是 ubuntu，命令的其余部分也不改。唯一的变化是，这一次忘记把 sudo 放在最前面。

先判断。文件会被改掉，还是保持原样？用用户和开关去对函数，不要用「刚才已经 sudo 过」来推。

判断文件会不会被改掉

第一次的输入是 ubuntu，并且使用 sudo。canWriteEtc 返回可以写，原因是「ubuntu 通过 sudo 可以写」。这次写入可以改掉文件。

第二次的输入仍是 ubuntu，useSudo 为假。返回不能写，原因是「ubuntu 没有 sudo 时写不了 /etc」。权限在写入之前就拒绝了，所以文件不会被改掉。

上一条命令用过 sudo，不会自动留给下一条。每一条要写 /etc 的命令，都要自己把 sudo 放在最前面。家目录此刻仍然可写，那份可写覆盖不到这个配置路径。

看解析

正确答案。忘记 sudo 时，文件不会被改掉。

关键步骤。锁定用户仍是 ubuntu；把 useSudo 从真改成假；读 ok 和 reason；reason 应为「ubuntu 没有 sudo 时写不了 /etc」。

常见错误。认为登录过就一直能写；认为上一次 sudo 会残留；认为家目录可写就等于这次也能改配置。错因是把「人已经在系统里」当成了「对 /etc 的写权限」。

本章避坑清单

  1. 登录名保持 ubuntu。不要把登录名改成 root 来写 /etc/nginx/nginx.conf。
  2. sudo 放在命令最前面。写在中间或末尾时，shell 不会用它提权。
  3. 家目录 /home/ubuntu 可写，不等于 /etc/nginx/nginx.conf 可写。
  4. 教学实例假定 ubuntu 在 sudo 组。口令以镜像文档为准，不要编造口令。
  5. 同一条写配置的命令，忘记 sudo 时文件不会被改掉。上一条的 sudo 不会自动留给下一条。
