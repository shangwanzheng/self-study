# 章节子任务书

父任务在大纲和 `CHAPTERS` 已写入后，每章发一个子任务。把下面整段交给子任务，替换花括号。不要让子任务自行决定章号、文件名、运行时名或基准算例。

```text
你负责一门离线交互式自学教程中的单独一章。只写这一个文件：
{课程目录}/{file}

先读这些文件再动笔，写的时候对标它们，不要发明第二套页面：
- {课程目录}/{样章文件}（若本章就是样章，则对标用户指定的样式样章）
- {课程目录}/assets/css/course.css
- {课程目录}/assets/js/course.js（只用已有运行时 API）
- {课程目录}/assets/js/{计算文件}
- 课程合同：{技能目录}/course-contract.md
- 领域包（没有则删掉这一行）：{技能目录}/domains/{领域文件}

本章身份（不得改）：
- id：{id}
- 章号：{no}
- 篇：{stageName}
- 标题：{title}
- 运行时全局名：{runtime}（全文只用这一个；initChapter、ui、errors 都挂在它上面）
- 作者：{author}（若为「不署名」：不要写 meta author，不要放作者 chip；否则可见 chip 只放一枚，meta author 只写一条）
- 前置：{prereq}
- 学习目标：{objectives}
- 小节大纲：{sections}
- 基准算例（只许引用，不许改数）：{baseline}
- 必须写进正文的易错点：{mistakes}
- 必须写进正文的避坑点：{pitfalls}
- 演示清单：{demos}（空间关系用 3D，曲线用 Plot 或 canvas2d，步骤用分步控件）

写作要求：
- 一章只讲一个主概念。小节大纲里的每一节都是这个概念的一步，开头写明承接上一节的结果。不要另起一个主概念。
- 章首 hero 写学习目标。大纲若单列了前置检查，用单独一次 ui.quiz，不计入章末题量。
- 练习覆盖大纲列出的题型（回忆、辨析、应用、迁移）。解析写出正确结果、关键步骤、错因，以及做错应回看哪一节。
- 有公式时只用 \( \) 与 \[ \]。没有公式就不要编。
- 章末四块，顺序固定：本章避坑清单、自测题（不少于 8 题，含多选，用 ui.quiz，覆盖复述、举例、应用、辨错）、术语表、本章小结与延伸阅读。小结用一句话收束，并预告下一章。
- 本章专用 CSS 类名以 c{no}- 为前缀，写在本文件 style 里。
- 每个演示独立 IIFE + try/catch，错误推入 {runtime}.errors。没有演示清单就不要做空转动画。
- 文末调用 {runtime}.initChapter('{id}')。
- 资源只用相对路径，禁止 CDN、禁止 type="module"。
- 正文里的代码块必须在 `{课程目录}/examples/` 下有同一份示例文件，并在代码块后用相对链接指过去。不要把示例用 script src 嵌进页面。
- 软件菜单与标准限值不作定论，写明以文档或标准原文为准。
- 示例参数是教学用，不写成未标明的真实产品或个人数据。

禁止：
- 不要修改 course.js、course.css、计算文件、index.html 和其他章节。
- 不要重复插入作者标签，不要编造作者。
- 不要新增未在基准算例中的同名参数。
```

父任务收回各章后：用技能第 3 节的 10 条看过一遍，核对注册表与冻结大纲一致（不改已有 `id`、章号和文件名）、首页作者、跨章链接、共用计算是否仍被需要它的章调用，然后运行 `scripts/validate_course.py`。
