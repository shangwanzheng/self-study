# 离线交互式自学教程

把一个主题做成**断网用浏览器直接打开**的分章教程。页面框架、章节骨架和运行时接口见 [course-contract.md](course-contract.md)。并行章节任务书见 [subagent-brief.md](subagent-brief.md)。

主题有领域包时，大纲定稿前先读对应文件。车辆多体动力学、悬架、操稳、平顺性读 [domains/vehicle-mbd.md](domains/vehicle-mbd.md)。没有领域包就按本技能现写，不要把别的学科的例子套进来。

## 何时使用 / 何时不用

**使用：** 用户要一门可自学的课、要补章节、要交互演示把概念讲透、要离线 HTML。

**不用：** 只问一个概念且不要成套资料；编写业务功能、跑测试、做缺陷分析。这些不走本技能。

## 产出放哪里

- 课程正文只写入用户指定目录。
- 未指定时：当前工作区就是在备这门课，则放到工作区下的 `<课程名>/`。当前工作区是别的软件项目时，先问输出目录，不要写进该项目。
- 大纲草稿、校验日志放 `<课程目录>/_draft/`。
- 续写已有课程时，在原目录改，不复制出第二套 `assets/`。

## 作者署名

用户指定作者时照用。未指定则**不要编造人名**，不写 `meta author`，不放作者 chip。

指定了作者时，每个 HTML **只保留一处可见署名**和**一条**作者元信息，位置见课程合同。正文里的「作者」（文献作者、库作者）不要改。发现重复时删到各剩一个，不要再追加。

## 工作流

复制清单并逐项做完。先冻结合同，再并行写章节。

```text
任务进度：
- [ ] 1. 确认是新课还是续写，以及输出目录、作者、主题、读者基础
- [ ] 2. 写出分篇大纲（阶段、章号、文件名、运行时名、基准算例、每章演示）
- [ ] 3. 备好 assets 与注册表；续写时只追加章节，不重写已有章
- [ ] 4. 按 subagent-brief 并行生成各章（每章一个子任务）
- [ ] 5. 父任务只做合并：注册表、首页、跨章引用、共用计算
- [ ] 6. 运行 scripts/validate_course.py，失败则改到通过
- [ ] 7. 抽查首页、第 1 章或本次新章：署名规则、演示能算、自测能提交
```

### 1. 确认范围

请求里已经给出主题和目录时，直接开工，不要再追问风格。缺主题时只问三件事：主题、读者基础、输出目录。

续写时先读现有 `CHAPTERS`、`STAGES` 和目标章前后各一章，沿用章号、文件名、难度徽章和 callout，不改已完成章的结构。运行时全局名沿用该课已有的名字。

### 2. 大纲

一门课默认按五篇展开。篇名随主题改，顺序表示依赖，不要打乱：

1. 共同语言（术语、符号、约定、本课数字从哪来）
2. 对象与结构（要操作的东西、怎么组成、参数是什么）
3. 方法（步骤怎么做、量怎么取、结果从哪读）
4. 现象与判断（现象和前面参数的对应、怎样算做对）
5. 实战（完整流程、核对、调试、全课避坑）

用户明确要短课：可以把第 4 篇并进第 3 篇，仍保留共同语言、对象与结构、实战。

用户点名的主题各成一章或一章中的主节，并主动补上理解该主题所必需的前置章。已有章不要重复生成。

每章在大纲里写死：`id`（`ch01`）、文件名、篇号、学习目标、8–12 个小节及难度（入门/进阶/深入）、至少 4 个具体易错点和 4 个避坑、至少 2 个交互演示、与前后章共用的符号。整门课只定一套基准算例（名称、数字、单位），各章引用它，不另起一套数。

演示形态按内容选，不要为了凑种类做空转场景：

- 空间关系、结构、姿态用 3D
- 曲线、扫参、对比用 2D
- 步骤、分类、状态变化用分步控件或分段高亮
- 主题没有公式就不要编公式；运行时里的 KaTeX 仍然留着，用到再写

大纲同时写死运行时全局名：新课用 `Course`；续写已有课沿用原名（车辆标杆课是 `VMD`）。

### 3. 共用合同先落盘

运行时模板在本技能目录的 `template/`。那里是整门车辆标杆课（章节、首页、`assets/`），随技能存放。不要到别的目录另找一份。

新课只复制 `template/assets/`（含 three.js、OrbitControls、KaTeX），再改课程名、`CHAPTERS`、`STAGES`。页面骨架对标 `template/index.html` 和 `template/ch01_mbd_basics.html`，只对标结构。不借用车辆正文，也不借用 `refCar`。不要把新课写进 `template/`。`template/assets/js/course.js` 缺失时停下来说明模板不完整，不要另写一套滑块、曲线或 3D 查看器。

用户要续写某一门已经生成的课：在那门课自己的目录里改。续写车辆标杆课本身时，改 `template/` 里的章节，规则见 [domains/vehicle-mbd.md](domains/vehicle-mbd.md)。

新课复制后，父任务把全局对象 `VMD` 改成大纲里的运行时名（新课为 `Course`）。只改这个全局标识，不要改 three、KaTeX 内部名字。改完搜索确认章节只会用到一个全局名。续写禁止重命名。

本课纯计算放 `assets/js/models.js`，无 DOM。模板里的其他学科计算（例如车辆的 `refCar`、轮胎、整车模型）不要带进无关课程；确认无引用后再从副本里去掉。

`course.js` 与 `models.js`（或该课已有的计算文件）只由父任务修改。子任务只写自己的那一个 HTML。

### 4. 并行写章

大纲和注册表冻结后，每一章启动一个子任务，提示词用 [subagent-brief.md](subagent-brief.md)。新课还没有自己的样章时，结构对标 `template/ch01_mbd_basics.html`，正文不要抄车辆内容。子任务不得改 `course.css`、`course.js`、计算文件、其他章节和首页，也不得改 `template/`。章节专用样式写在该章 `<style>` 里，类名以章号为前缀（`c07-`）。

### 5. 内容必须讲透

每节按这个顺序写，不要只给定义：

1. 这一节解决什么问题。
2. 符号、方向或约定、单位。
3. 用本课基准算例走一遍数量级，或做一个完整的小例子。
4. 紧挨着概念写「易错」和「避坑」：错在哪、会看到什么、正确做法是什么。
5. 落到可操作的对象：代码里的类型或函数、公式里的量、图上的读数、实验步骤、模型里的部件。软件菜单名和标准限值不作定论，写明以文档或标准原文为准。

易错点要具体到对象和差多少。不要写「注意单位」这类没有上下文的套话；单位问题要指出哪两个单位会混、差多少、用哪个量校核。

有公式时用 `\(...\)` 与 `\[...\]`。推导里的假设写在公式旁边。

演示必须能被滑块或按钮改变结果。每个演示的 `demo-caption` 以「观察要点」开头，并编号写出该看什么。装饰性空转不算演示。

章末固定四块：本章避坑清单、自测题（含多选，提交后给解析）、术语表（中文 / 英文 / 符号 / 含义）、本章小结与延伸阅读。自测解析要解释误区，不要只写「选 B」。符号列可以是代码名、记号或「—」。

### 6. 校验

在本技能目录执行（`python` 不可用时改用 `py -3`）：

```bash
python scripts/validate_course.py "<课程目录>" --author "<作者>"
```

未指定作者时去掉 `--author`。退出码非 0 就按报告改，再跑，直到通过。校验项包括：章节注册表与文件一致、无远程脚本和样式、无 ES Module、作者规则、`initChapter` 的 id 与注册表一致、相对资源存在、章末四块齐全、页内 id 不重复。

### 7. 抽查

IDE 浏览器不能打开 `file://`。需要看页面时，在课程目录临时启动静态服务，看完即关。课程本身仍必须能在 `file://` 下离线打开，所以资源保持相对路径，脚本保持经典脚本。

抽查首页、一个会随控件变化的演示、一道自测题提交。有 3D 时确认看到的是场景而不是 WebGL 失败提示。续写时再打开相邻旧章，确认顶栏上一章/下一章和侧栏章名正确。指定了作者时，确认作者标签只出现一次。

## 领域包

`domains/` 里每个文件只管一门学科：必须覆盖的主题、基准算例、坐标或约定、易错表、这门课特有的禁止项。新主题不要套用其他领域包。

用户要求把某学科的覆盖和易错冻成可复用规则时，才新增 `domains/<slug>.md`，并在本文件的开头加上触发句。不要为单独一门课预建领域包。

## 不要做的事

- 不要从 CDN 引用 three、KaTeX 或字体。
- 不要把教程脚本写成 `type="module"`。
- 不要为了单章去改全局 `course.css`。
- 不要在一页上重复作者标签，也不要编造作者。
- 不要让各章使用互相矛盾的基准数字。
- 不要把教学示例写成未标明的真实产品数据或真实个人信息。
- 不要在子任务之间同时改 `course.js`。
- 不要用空转动画充当演示。
