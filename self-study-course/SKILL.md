# 离线交互式自学教程

把一个主题做成**断网用浏览器直接打开**的分章教程。页面框架、章节骨架和运行时接口见 [course-contract.md](course-contract.md)。并行章节任务书见 [subagent-brief.md](subagent-brief.md)。

主题有领域包时，大纲定稿前先读对应文件。车辆多体动力学、悬架、操稳、平顺性读 [domains/vehicle-mbd.md](domains/vehicle-mbd.md)。没有领域包时，把坐标或约定、基准算例、易错写进该课大纲。不要新建 `domains/`，也不要把别的学科的例子套进来。领域包只在用户要求把某学科冻成可复用规则时新增，见文末。

## 何时使用 / 何时不用

**使用：** 用户要一门理论类的可自学课、要补章节、要交互演示把概念讲透、要离线 HTML。

**不用：** 只问一个概念且不要成套资料；编写业务功能、跑测试、做缺陷分析；编程语言入门、边学边练、项目驱动练手。编程课走同级 [code-practice-course](../code-practice-course/SKILL.md)。

## 产出放哪里

- 课程正文只写入用户指定目录。
- 未指定时：当前工作区就是在备这门课，则放到工作区下的 `<课程名>/`。当前工作区是别的软件项目时，先问输出目录，不要写进该项目。
- 大纲写到 `<课程目录>/_draft/outline.md`。校验日志放 `<课程目录>/_draft/`。
- 续写已有课程时，在原目录改，不复制出第二套 `assets/`。

## 作者署名

用户指定作者时照用。未指定则**不要编造人名**，不写 `meta author`，不放作者 chip。

指定了作者时，每个 HTML **只保留一处可见署名**和**一条**作者元信息，位置见课程合同。正文里的「作者」（文献作者、库作者）不要改。发现重复时删到各剩一个，不要再追加。

## 工作流

复制清单并逐项做完。先定稿大纲并冻结合同，再并行写章节。

章和单元是同一个交付单位：

- **技能树**只记录先修，不决定章序。
- **学习路径**决定阶段和章序。
- **阶段**就是注册表里的一篇（`STAGES` 的一条）。
- **一章等于一个单元**：一个主概念、一个 HTML。
- **节**是这一章里的 `h2`，只推进这一个主概念。

```text
任务进度：
- [ ] 1. 确认新课或续写，以及输出目录、作者、主题、学习目标、读者基础
- [ ] 2. 把大纲写到 _draft/outline.md：技能树、学习路径、全课的运行时名和基准算例，以及每章的阶段、章号、文件名、演示、节列表
- [ ] 3. 按编写原则检查大纲：一章一个主概念，四类练习和章末四块已排进各章
- [ ] 4. 备好 assets，把 CHAPTERS 和 STAGES 写入并冻结；续写只追加
- [ ] 5. 按 subagent-brief 并行生成各章（每章一个子任务）
- [ ] 6. 用 10 条检查各章，核对注册表、首页、跨章引用和共用计算，再跑 validate_course.py 直到通过
- [ ] 7. 抽查首页、第 1 章或本次新章：署名、演示能算、自测能提交
```

### 1. 确认范围

主题、学习目标和输出目录都有了就开工，不要再追问风格。读者基础没写时问一句。作者没指定就不要问人名。缺了别的，只补问缺的那一项。

学习目标要能观察。例如「学完能用牛顿第二定律列出质点的运动方程，并说明初始条件怎样改变轨迹」。编程语言入门、个人主页、项目练手不在本技能里做。

续写时先读现有 `CHAPTERS`、`STAGES` 和目标章前后各一章，沿用章号、文件名、难度徽章和 callout，不改已完成章的结构。运行时全局名沿用该课已有的名字。

### 2. 大纲

大纲从学习目标倒推，写到 `_draft/outline.md`。先把内容分成必学（不学做不下去）、可查（用到再查）、暂缓（暂时不影响产出）。

同一份大纲里分两节，不要并成一张图：

1. **技能树**：终点能力拆成 3—7 个模块，每个模块拆成可练习的小技能，并标出先修。用来查漏。
2. **学习路径**：章序按学习者学会的顺序排。阶段和章以这一节为准。

每个小技能收成一章。几项小技能同属一个主概念时，并进同一章的不同节，不另开 HTML。

每章写死这些字段：`id`、章号、阶段（篇名）、文件名、标题、前置章、演示、节列表。全课再写死两件共用的：

- 运行时全局名。新课用 `Course`；续写沿用原名（车辆标杆课是 `VMD`）。
- 一套基准算例。章节只引用这套数，并写清单位。

演示按内容选，可以写「无」。不要为了凑种类做空转场景：

- 空间关系、结构、姿态用 3D
- 曲线、扫参、对比用 2D
- 步骤、分类、状态变化用分步控件或分段高亮
- 主题没有公式就不要编公式；运行时里的 KaTeX 仍然留着，用到再写

节列表按下面的顺序选，用不到的不写进去。这些项默认要有；删掉某一项时，在该章下面写明理由：为什么学、核心概念、示范例题、常见错误、四类练习、迁移、章末四块。

| 顺序 | 内容 | 页面位置 |
| --- | --- | --- |
| 1 | 单元目标，3 条以内，写能做到什么 | 章首 hero |
| 2 | 前置检查：开始前应会什么，2—3 题 | 单独一次 `ui.quiz`，不计入章末 8 题。大纲没列就不做 |
| 3 | 为什么学 | 一节 |
| 4 | 核心概念：先定义，再正例，再反例 | 一节 |
| 5 | 逐步讲解：写出推理，不只给结论 | 一节或多节 |
| 6 | 示范例题：用基准算例，写明为什么这样选 | 一节 |
| 7 | 常见错误：2—3 个误解和纠正 | 正文 callout，并汇总进章末避坑 |
| 8 | 四类练习与答案解析 | 一节 |
| 9 | 迁移：换一个场景用一次 | 一节。迁移题就放这里 |
| 10 | 章末四块 | 避坑清单、自测、术语表、小结与下一章。不占节号 |

自测只有章末这一处正式题：`ui.quiz`，不少于 8 题，含多选，覆盖能复述、能举例、能应用、能辨错。不要再写一张与这次 quiz 重复的自测清单。

### 3. 编写原则

这一步只检查 `_draft/outline.md`，不另停下来问用户。写完章节后，用文末 10 条再查一遍，放在第 6 步。

- 一章一个主概念。术语先定义，长内容分节，每节有一句收束。
- 先例子后抽象，先正例后反例，再给规则。
- 大约每讲 5—10 分钟在正文里插一个问题，让读者先想再往下看。这种提问不是第三次 `ui.quiz`。正式提交的题只有前置检查和章末自测。
- 练习做完紧跟解析。解析要写出为什么错。
- 常见错误写在读者容易想错的那一步旁边。
- 章首链到前置章，章末保留术语表，侧栏能跳到各节。
- 用第二人称，像教练在旁边提问。
- 有代码块时，同一份文件放在 `examples/`，代码块后面给相对链接。

练习只分四类，由易到难：回忆、辨析、应用、迁移。

1. 回忆：合上教材能否说出核心概念。
2. 辨析：正例和反例，纠正常见误解。
3. 应用：在基准算例或标准场景里使用。
4. 迁移：换一个场景用一次。

答案写明：正确答案、关键步骤、常见错误答案及错因、做错应回看哪一节。回看的节名就是诊断标签。

写完一章，用这 10 条检查：

- [ ] 目标可观察、可评估
- [ ] 前置知识明确；若有前置检查，那 2—3 题不计入章末自测
- [ ] 这一章只有一个主概念
- [ ] 有正例、反例和逐步推理
- [ ] 常见错误进了章末避坑清单
- [ ] 练习覆盖回忆、辨析、应用、迁移
- [ ] 答案有解析、错因，以及回看哪一节
- [ ] 章末自测不少于 8 题、含多选，覆盖复述、举例、应用、辨错
- [ ] 有上一章的承接和下一章的预告
- [ ] 目标读者能独立做完

### 4. 共用合同先落盘

运行时模板在本技能目录的 `template/`。那里是整门车辆标杆课（章节、首页、`assets/`），随技能存放。不要到别的目录另找一份。

新课只复制 `template/assets/`（含 three.js、OrbitControls、KaTeX），再改课程名、`CHAPTERS`、`STAGES`。页面骨架对标 `template/index.html` 和 `template/ch01_mbd_basics.html`，只对标结构。不借用车辆正文，也不借用 `refCar`。不要把新课写进 `template/`。`template/assets/js/course.js` 缺失时停下来说明模板不完整，不要另写一套滑块、曲线或 3D 查看器。

这一步把大纲里的阶段和章节写入 `STAGES`、`CHAPTERS`。写入后即冻结 `id`、章号、文件名、运行时全局名和基准数字。续写只追加条目，不改已有章的 `id` 与文件名。

用户要续写某一门已经生成的课：在那门课自己的目录里改。续写车辆标杆课本身时，改 `template/` 里的章节，规则见 [domains/vehicle-mbd.md](domains/vehicle-mbd.md)。

新课复制后，父任务把全局对象 `VMD` 改成大纲里的运行时名（新课为 `Course`）。只改这个全局标识，不要改 three、KaTeX 内部名字。改完搜索确认全课只会用到一个全局名。续写禁止重命名。

本课纯计算放 `assets/js/models.js`，无 DOM。模板里的其他学科计算（例如车辆的 `refCar`、轮胎、整车模型）不要带进无关课程；确认无引用后再从副本里去掉。

`course.js` 与 `models.js`（或该课已有的计算文件）只由父任务修改。子任务只写自己的那一个 HTML。

### 5. 并行写章

大纲和注册表冻结后，每一章启动一个子任务，提示词用 [subagent-brief.md](subagent-brief.md)。子任务书里的小节大纲照 `_draft/outline.md` 该章的节列表填。

新课还没有自己的样章时，结构对标 `template/ch01_mbd_basics.html`，正文不要抄车辆内容。子任务不得改 `course.css`、`course.js`、计算文件、其他章节和首页，也不得改 `template/`。章节专用样式写在该章 `<style>` 里，类名以章号为前缀（`c07-`）。

### 6. 核对并校验

收回各章后，先用第 3 节的 10 条看每章。然后只做这些核对：注册表与冻结的大纲一致、首页、跨章链接、共用计算是否仍被需要它的章调用。标题笔误和首页可以改。`id`、章号、文件名、运行时全局名和基准数字保持冻结。共用公式可以补进 `models.js`。

在本技能目录执行（`python` 不可用时改用 `py -3`）：

```bash
python scripts/validate_course.py "<课程目录>" --author "<作者>"
```

未指定作者时去掉 `--author`。退出码非 0 就按报告改，再跑，直到通过。校验项包括：章节注册表与文件一致、无远程脚本和样式、无 ES Module、作者规则、`initChapter` 的 id 与注册表一致、相对资源存在、章末四块齐全、页内 id 不重复、每个代码块后面链到 `examples/` 且文件存在。

### 7. 抽查

IDE 浏览器不能打开 `file://`。需要看页面时，在课程目录临时启动静态服务，看完即关。课程本身仍必须能在 `file://` 下离线打开，所以资源保持相对路径，脚本保持经典脚本。

抽查首页、一个会随控件变化的演示、一道自测题提交。有 3D 时确认看到的是场景而不是 WebGL 失败提示。续写时再打开相邻旧章，确认顶栏上一章/下一章和侧栏章名正确。指定了作者时，确认作者标签只出现一次。

## 领域包

`domains/` 里每个文件只管一门学科：必须覆盖的主题、基准算例、坐标或约定、易错表、这门课特有的禁止项。新主题不要套用其他领域包。没有领域包的课，这些约定写在 `_draft/outline.md`，不预建领域包。

用户要求把某学科的覆盖和易错冻成可复用规则时，才新增 `domains/<slug>.md`，并在本文件的开头加上触发句。不要为单独一门课预建领域包。

## 不要做的事

- 不要从 CDN 引用 three、KaTeX 或字体。
- 不要把教程脚本写成 `type="module"`。
- 不要为了单章去改全局 `course.css`。
- 不要在一页上重复作者标签，也不要编造作者。
- 不要让各章使用互相矛盾的基准数字。
- 不要把教学示例写成未标明的真实产品数据或真实个人信息。
- 不要在子任务之间同时改 `course.js`。
- 不要用空转动画充当演示。
- 不要只在 HTML 里嵌一段代码，而不在 `examples/` 下给出同一份示例文件。
