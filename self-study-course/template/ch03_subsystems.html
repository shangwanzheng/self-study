整车模型架构：模板、子系统与装配

整车多体模型不是一个“大文件”，而是一套分层的数据体系。本章讲清模板、子系统、装配、试验台、属性文件各存什么，子系统之间怎样靠通讯器自动连接，硬点怎样驱动参数化几何，以及怎样检查一个装配是否真的“装对了”。

3.1 为什么要分层建模

一辆轿车的整车多体模型，通常有一两百个部件、几百个运动副和衬套、上千个参数和几十条特性曲线。把它当成“一个大模型”从头搭当然也能跑起来，但只要遇到“换一套后悬硬点”“把前悬单独拿去做 K&C”“三个人同时改不同的系统”这类日常需求，就会陷入复制粘贴、版本混乱和查不出的连接错误。车辆专用多体软件（以 Adams/Car 为代表）因此把模型拆成 模板（template）—子系统（subsystem）—装配（assembly） 三层，再把弹簧、减振器、衬套、轮胎等特性数据放进独立的属性文件（property file）。

一个类比：图纸、订单与总装线

把整车模型想象成一家汽车厂的数据，就很容易理解这几个层次：

  • 模板像一张“参数化图纸”：它规定麦弗逊悬架由哪些零件组成、零件之间用什么铰接、弹簧装在哪两个点之间、零件形状怎样随关键点变化，但不规定具体尺寸和特性。
  • 子系统像一份“按图纸下的订单”：选定这张图纸，再填上本车的硬点坐标、弹簧特性文件、零件质量，就得到“A 车型前悬架”。同一张图纸可以下很多份订单：A 车前悬、B 车前悬、A 车运动版前悬。
  • 装配像“总装线 + 工装夹具”：把车身、前悬、后悬、转向、稳定杆、车轮等订单拿到一起，再放上一个试验台（test rig，相当于夹具和驾驶机器人），才得到一个可以求解的模型。
  • 属性文件像“外购件规格书”：弹簧厂给的力—变形曲线、减振器厂给的力—速度曲线、轮胎厂给的轮胎参数，独立存放、被多份订单引用。

这个类比里最关键的一点是：图纸（模板）是共享的，订单（子系统）是各自的。改图纸会影响所有按它下的订单，改订单只影响自己——后面很多避坑点都从这里来。

分层带来的六个好处

模块化（modularity）

每个子系统只关心自己内部的拓扑和数据，通过标准化接口（通讯器）与其他子系统连接；替换一个子系统时，其余子系统一个字都不用改。

复用（reuse）

一个验证过的模板可以被几十个车型的子系统引用；同一个前悬子系统既能装进悬架 K&C 装配，也能装进整车装配，保证“台架上的悬架”和“整车里的悬架”是同一份数据。

参数化（parameterization）

几何、连接位置和方向都由硬点、构造框和参数驱动。改一个硬点，连杆形状、衬套位置、弹簧安装线会自动更新——这是做硬点灵敏度分析和试验设计（DOE）的前提。

多人协作（collaboration）

悬架工程师维护悬架子系统，转向工程师维护转向子系统，模板由少数专家维护。分工清楚、权限可控，可以并行工作而不互相覆盖。

数据管理（data management）

所有文件放在数据库目录中、按类型分表存放，可纳入版本管理；子系统只“引用”属性文件，避免同一条曲线被复制成十几份、改了一份忘了另外几份。

可追溯（traceability）

每个结果都能追溯到“哪个装配 → 哪些子系统 → 哪些模板和属性文件的哪个版本”。这是仿真结果能被评审、能被复现的基础（见 3.9 节）。

分层建模的“代价”正是本章的重点

分层以后，子系统之间的连接不再是画在眼前的铰链，而是装配时按规则自动配对的通讯器；数据也不再集中在一个文件里，而是分散在模板、子系统、属性文件和数据库中。绝大多数“装配成功、结果离谱”的问题，都出在这些看不见的地方。本章后面每一节都在回答三个问题：这一层存了什么？它和别人怎么连？哪里最容易出错？

子系统不等于一个物理总成
把“子系统”理解成一个物理总成：认为“四个车轮就是一个子系统”，或者“制动系统应该拆到四个车轮里”。 子系统是一份数据实例，划分依据是“谁维护、谁复用、谁替换”。前、后车轮通常是两个子系统（次要角色分别为 front、rear），却引用同一个车轮模板；制动系统常作为一个子系统同时作用在四个车轮上；副车架可以放在悬架子系统里，也可以单独成为子系统，取决于它是否需要单独替换。

3.2 模板—子系统—装配三层结构

三层结构的核心是一条“引用链”：装配引用子系统，子系统引用模板和属性文件。每一层只保存自己负责的那部分信息，打开装配时软件沿着这条链把所有文件加载进来，再按通讯器规则把子系统连成一个整体。

模板：拓扑 + 参数化规则 + 接口

模板（常见扩展名约定为 .tpl）描述的是一类机构，而不是某一辆车。一个麦弗逊悬架模板通常包含：

  • 拓扑：有哪些部件（下摆臂、转向节、减振器上下体、副车架……），部件之间用什么运动副或衬套连接，弹簧、减振器、缓冲块装在哪里；
  • 参数化规则：部件的几何、连接的位置和方向如何由硬点、构造框和参数变量决定（3.3 节）；
  • 接口：需要从别的子系统得到什么（输入通讯器），能向别人提供什么（输出通讯器）（3.4 节）；
  • 默认数据：默认硬点坐标、默认属性文件、默认质量与惯量。这些默认值只是“占位”，在子系统中必须改成本车数据；
  • 主要角色（major role）：创建模板时就确定，说明“它是什么”，例如 suspension（悬架）或 steering（转向）。

在 Adams/Car 中，模板在模板编辑器（Template Builder）里建立和修改，通常只有“专家用户”有权限；普通用户在标准界面（Standard Interface）中使用模板创建、修改子系统和装配（具体模式名称与权限设置以所用版本的软件文档为准）。这种权限划分本身就是一种质量控制：拓扑由少数人维护，数据由多数人填写。

子系统：引用模板 + 本车数据

子系统（常见扩展名约定为 .sub）= “引用哪个模板” + “本车的具体数据”，包括：硬点坐标、参数变量值（如静态前束、外倾设定）、属性文件引用、部件质量与惯量（可覆盖模板默认值），以及主要角色和次要角色（minor role）。子系统文件通常是分段的文本格式，可以用文本比较工具直接查看两个版本的差异。

  • 主要角色回答“它是什么”：suspension、steering、antirollbar（稳定杆）、body（车身）、powertrain（动力总成）、driveline（传动系）、brake_system（制动）、wheel（车轮/轮胎）等，由模板决定；
  • 次要角色回答“它装在哪”：front、rear、trailer、any 等，在创建子系统时指定。它是通讯器匹配的关键条件：同一个麦弗逊模板，次要角色选 front 就是前悬，选 rear 就是后悬。

装配：子系统清单 + 试验台

装配（常见扩展名约定为 .asy）本身几乎不存力学数据，它只记录两件事：用了哪些子系统、用哪个试验台。打开装配时，软件依次加载子系统以及它们引用的模板和属性文件，再按通讯器规则把子系统连接起来。

  • 悬架装配（suspension assembly）= 一个悬架子系统（需要转向工况时再加转向子系统）+ 悬架试验台，用于同向/反向轮跳、侧倾、转向、侧向力与纵向力柔度等分析，详见 第 9 章；
  • 整车装配（full-vehicle assembly）= 前/后悬架 + 转向 + 前/后稳定杆 + 车身 + 动力总成 + 制动 + 前/后车轮 + 整车试验台，用于操稳、平顺、耐久等整车分析，详见 第 14 章。

数据库：按类型分表的目录

数据库（Adams/Car 中常见约定为 .cdb 目录）是存放上述所有文件的“仓库”。它就是一个普通目录，内部按文件类型分成若干“表”（.tbl 子目录）：

vehicle_A.cdb/              ← 一个数据库 = 一个目录（常见约定，示意）
├─ templates.tbl/      *.tpl   模板
├─ subsystems.tbl/     *.sub   子系统
├─ assemblies.tbl/     *.asy   装配
├─ springs.tbl/        *.spr   弹簧
├─ dampers.tbl/        *.dpr   减振器
├─ bushings.tbl/       *.bus   衬套
├─ bumpstops.tbl/      *.bum   缓冲块
├─ reboundstops.tbl/   *.reb   限位块
├─ tires.tbl/          *.tir   轮胎
└─ roads.tbl/          *.rdf   路面

子系统引用属性文件时，通常不写绝对路径，而写成“数据库别名 + 表 + 文件名”的形式（例如 mdids://vehicle_A/springs.tbl/coil_F_28N.spr 这类写法，具体语法以软件文档为准）。软件通过配置把别名映射到真实目录，于是整个数据库可以整体搬家而不必改引用——但也埋下了“别名指向了另一个同名数据库”的隐患（3.9 节）。软件一般自带只读的共享示例数据库，用户应在自己的私有库或项目库中工作。

改模板会影响所有引用它的子系统
“我只是给自己用的前悬模板加了一个衬套、改了一个默认质量，别的车型不受影响。” 模板是共享的“图纸”。所有引用该模板的子系统在下次打开时都会使用新的拓扑和新的默认值，其中可能包括同事正在对标的车型。正确做法：修改前先查清引用范围；需要改拓扑时复制成新名字、新版本的模板，让需要的子系统改为引用新模板；共享模板的改动走评审，并在变更记录中写明影响范围。
子系统重名会互相覆盖
“另存子系统时沿用原名就行，反正存在我自己的目录里。” 同一个数据库表中同名文件会直接被覆盖；不同数据库中的同名文件，则可能因为别名或搜索顺序而被装配“错拿”。命名时带上车型、方案和版本（如 A01_fsusp_sport_v3.sub），保存前确认目标数据库；打开装配后核对每个子系统的实际来源路径。

为什么要把“主要角色”和“次要角色”分开

主要角色回答“它是什么”，决定这个子系统在装配中的身份，试验台和其他子系统靠它识别“谁是悬架、谁是转向”；次要角色回答“它在哪儿”，决定通讯器和谁配对。把两者分开以后，“一个模板、多个子系统”才成立：一个双横臂模板可以同时生成前悬（front）和后悬（rear）两个子系统，一个车轮模板可以同时生成前轮和后轮两个子系统，而模板本身一行都不用改。反过来，如果次要角色填错，模板再正确也会装错（3.4 节）。

3.3 模板里有什么

打开一个悬架模板，可以看到硬点、构造框、参数变量、部件、几何、连接、力元和通讯器这几类“积木”。它们之间有明确的依赖顺序：硬点 → 构造框 → 部件与几何 → 连接与力元 → 通讯器。理解了这条依赖链，就理解了为什么改一个硬点，整套悬架会自动跟着变；也就知道哪些东西不会自动跟着变。

硬点与构造框

硬点（hardpoint）是只有位置、没有方向的几何点，是模板中最基本的参数。常见命名前缀为 hpl_（左）、hpr_（右）、hps_（单个，位于车辆中面或不分左右）。左右成对的硬点在模板中一起创建，默认关于车辆中面（\(y=0\)）对称：只需输入左侧坐标，右侧自动镜像。

构造框（construction frame）是带“位置 + 方向”的坐标系，常见前缀为 cfl_/cfr_/cfs_。它的位置通常放在某个硬点上，方向可以用“指向另一个硬点”“三点确定一个平面”“相对某个坐标系的欧拉角”等方式定义（可选方式以软件文档为准）。衬套的轴向、旋转副的轴线、车轮的旋转轴、减振器的轴线，都要靠构造框来定方向。最常见的“两点定轴”写成：

\[ \mathbf{r}_{\mathrm{cf}}=\mathbf{r}_A,\qquad \mathbf{e}_z=\frac{\mathbf{r}_B-\mathbf{r}_A}{\lVert\mathbf{r}_B-\mathbf{r}_A\rVert} \](3-1)
  • \(\mathbf{r}_A,\ \mathbf{r}_B\)：两个硬点的位置，例如 \(A=\) hpl_lca_front、\(B=\) hpl_lca_rear（下摆臂前、后内点）；
  • \(\mathbf{r}_{\mathrm{cf}},\ \mathbf{e}_z\)：构造框原点与 z 轴方向。下摆臂的旋转副轴线就沿 \(\mathbf{e}_z\)；改动任一硬点，轴线方向自动更新。

参数变量

参数变量（parameter variable）是模板中的标量参数，常见前缀 pvl_/pvr_/pvs_，例如静态前束和外倾的设定值（示意名 pvl_toe_angle、pvl_camber_angle）、转向比、齿条行程限位、“是否启用某个功能”的开关量。在常见的悬架模板中，前束、外倾设定值是通过让车轮主轴相对转向节转过一个小角度来实现的，而不是去改硬点——所以“调前束”通常改参数变量，“改运动学”才改硬点。参数变量在子系统中赋值，与硬点一起保存在子系统文件里。

这样硬点一动，质心随之移动；而如果质心是按绝对坐标输入的，改硬点后它会“留在原地”，部件的质量分布就和几何对不上了。

几何

几何（geometry）——连杆圆柱、摆臂外形、导入的外形文件——只负责显示，以及（可选的）按体积估算质量，不参与力学计算（接触问题除外）。几何同样是参数化的：圆柱两端绑定在硬点上，改硬点后形状自动跟随。正因为“看起来对”只说明几何对，不说明质量、惯量和连接对，模型检查不能只靠看图。

连接与力元

连接把部件彼此（或与安装部件）联系起来，分两大类：

  • 运动副（joint）：旋转副（revolute）、球铰（spherical）、万向节（hooke/universal）、移动副（translational）、圆柱副（cylindrical）、固定副（fixed）等，按理想几何关系去除自由度（每种运动副去掉几个自由度见 第 1 章）；
  • 衬套（bushing）：不去除自由度，而是在两个部件之间施加六向（三个平动、三个转动）的弹性力和阻尼力，刚度可以是线性的，也可以是非线性曲线（第 6 章）。

力元（force element）包括弹簧（引用 .spr，涉及自由长度、安装长度与预载）、减振器（.dpr）、缓冲块（.bum，压缩方向的限位）、限位块（.reb，伸张方向的限位）以及稳定杆的扭转刚度等。模板只决定力元装在哪两个点之间、沿什么方向，力元有多硬由属性文件决定。

运动学模式与柔性模式

同一个连接位置，模板里常常同时定义“运动副 + 衬套”两种实现，并标明哪一个在运动学模式（kinematic mode）下激活、哪一个在柔性模式（compliant mode）下激活。例如下摆臂内侧：柔性模式下是前、后两个衬套；运动学模式下两个衬套停用，换成一个沿两点连线（式 3-1）的旋转副。分析时切换模式，软件就自动启停对应的连接。

为什么还需要运动学模式

运动学模式把衬套的影响“关掉”，只剩硬点决定的几何运动学，这有两个用处：一是硬点设计初期快速筛选方案，不必等衬套数据；二是把总的 K&C 特性拆成“几何运动学 + 弹性运动学（elasto-kinematics）”两部分，分别找责任——前束变化大，究竟是硬点布置的问题，还是衬套太软的问题？五连杆这类依靠衬套设计柔度转向的悬架尤其需要这种拆分（第 5 章、第 9 章）。

左右对称机制

成对的实体（hpl_/hpr_、cfl_/cfr_、gel_/ger_……）在模板中一起创建，默认对称：右侧硬点由左侧硬点关于车辆中面镜像得到。在子系统中修改硬点时，可以选择“对称修改”（左右同步）或关闭对称、只改一侧。非对称修改的正当用途包括：左右不同的转向横拉杆布置、非对称的副车架安装点、制造公差与装配偏差研究。但关闭对称以后，左右两侧就成了两套独立数据，之后每一次修改都要想清楚“改的是哪一侧”（3.7 节的演示 C 可以亲手体验）。

模板中的部件质量用默认值，没有改成本车数据
“子系统已经装上、静平衡也收敛了，部件质量应该是对的。” 模板作者给部件的质量和惯量，往往来自示例车数据或几何体积估算，只是“占位”。不逐一核对，就会出现簧下质量偏小三成、副车架只有几千克、动力总成惯量差一个数量级之类的问题，直接影响偏频、轮胎动载荷、整车质量与质心。正确做法：建立部件质量核对表，与 BOM 或称重数据逐项对比（3.8 节演示 E）；在子系统中修改质量后确认已保存进子系统文件，而不是只改了当前打开的模型。

3.4 通讯器机制

模板里不写死“减振器上支座连到哪一个车身”，只声明“我需要一个车身安装部件”。这种声明就是通讯器（communicator）。装配时，软件把所有子系统（以及试验台）的输入通讯器与输出通讯器按规则两两配对——配上了，才算真正“装上”；配不上，后果可能很严重，而且往往不会报错。

输入通讯器与输出通讯器

  • 输入通讯器（input communicator），常见前缀 ci[lrs]_，意思是“我需要别人提供……”。例如前悬模板中的 ci[lr]_strut_to_body（减振器上支座要连到车身）、ci[lr]_tierod_to_steering（横拉杆内点要连到转向齿条）。
  • 输出通讯器（output communicator），常见前缀 co[lrs]_，意思是“我能提供……”。例如转向模板输出齿条部件，悬架模板输出轮毂部件、轮心位置和前束/外倾设定值，车身模板输出车身部件。

本节出现的通讯器名称均为按常见命名约定构造的示意名，具体名称以所用模板为准。

匹配规则

一个输入通讯器 \(i\) 与一个输出通讯器 \(o\) 配对，需要同时满足三个条件：

\[ \mathrm{match}(i,o)=\big[\,n_i=n_o\,\big]\ \wedge\ \big[\,t_i=t_o\,\big]\ \wedge\ \big(\,r_i=r_o\ \vee\ r_i=\texttt{any}\ \vee\ r_o=\texttt{any}\,\big) \](3-3)
  • \(n\)：匹配名（matching name），逐字比较，例如 strut_to_body；
  • \(t\)：实体类型，如 mount（安装部件）、location（位置）、parameter（参数）、marker（标记）；
  • \(r\)：次要角色。模板中通讯器的次要角色常设为 inherit（继承），创建子系统时自动取该子系统的次要角色——这正是同一个模板既能做前悬又能做后悬的原因（具体选项以软件文档为准）。

注意式 (3-3) 里没有“主要角色”：通讯器不关心对方是悬架还是车身，只认名字、类型和次要角色。所以名字拼错一个字母、次要角色填错一个选项，都会让本该连上的两个子系统“擦肩而过”。

未匹配的安装部件会被连到地面

mount 类通讯器最需要警惕。模板中每个 mount 输入都对应一个无质量的安装部件；装配时如果找到匹配的输出，安装部件就被替换为对方的真实部件（例如车身）；如果找不到，安装部件就被固定到地面（ground）。模型照样能装配、能求解，只是某个本应随车身运动的连接点被钉死在了大地上。

通讯器未匹配，部件被连到 ground
“装配成功、没有报错，说明所有子系统都连对了。” mount 未匹配通常只在装配信息窗口里列出，不会中止装配。典型后果：副车架安装点接地，整车多出一个“对地支撑”，侧倾和俯仰被大地托住，静平衡“特别容易收敛”，操稳结果却完全失真；横拉杆内点接地，方向盘转了车轮不转；稳定杆连接杆接地，稳定杆变成连到大地的扭簧。每次装配后都要逐条阅读未匹配列表，对每一条回答“这是故意的吗？”
次要角色设错：前悬子系统用成了 rear
“次要角色只是个标签，选错了也无所谓，反正模板是麦弗逊。” 次要角色直接参与匹配（式 3-3）。前悬设成 rear 后：它的横拉杆输入找不到 front 的转向输出 → 横拉杆接地；它的轮毂、轮心、前束输出变成 rear → 前车轮找不到安装对象 → 前轮接地，而后车轮可能同时匹配到两个“后悬”；前稳定杆的连接杆也找不到对象。演示 B 可以复现这一连串后果。
any 不是万能钥匙
“把次要角色都设成 any，就不会有匹配不上的问题了。” any 能和任何次要角色匹配，因此很容易产生多重匹配：例如前稳定杆设成 any，它的连接杆输入会同时匹配前悬和后悬的输出，最终连到哪一个取决于软件规则，可能连到非预期的部件。any 只适合确实“不分前后”的子系统，比如车身、制动系统。
软件为什么不把“未匹配”直接当错误

因为很多未匹配是故意的。同一个前悬子系统装进悬架装配时，没有车身子系统，它的车身安装输入全部未匹配、全部接地——这恰好就是悬架试验台要的“车身固定”边界条件。同一个机制，在悬架装配里是特性，在整车装配里就是事故。所以软件只能列出来，由工程师判断。好的做法是为每个装配维护一份“允许的未匹配清单”，每次装配后与之比对，多出来的每一条都要追查。

试验台通讯器

试验台本身也是一个模板，同样通过通讯器与子系统交换信息。悬架试验台需要从悬架子系统得到车轮安装部件、轮心位置、前束/外倾设定值等信息，才能在正确的位置施加轮跳和力、计算前束外倾；整车试验台需要从转向子系统找到方向盘或齿条的驱动对象，从车轮子系统得到轮胎信息（以上为概念描述，所需通讯器清单以试验台文档为准）。自建模板如果缺少试验台约定的输出通讯器，子系统照样能创建、装配也可能“成功”，但装进试验台后无法驱动或无法测量——能装配不等于能分析。复制软件自带模板再修改时，不要删掉或改名这些试验台用的通讯器。

怎样检查通讯器

  1. 装配前做通讯器测试：对“候选子系统 + 试验台”运行软件提供的通讯器检查功能（具体入口以软件文档为准），列出已匹配、未匹配和多重匹配的通讯器。
  2. 装配后读信息：逐条阅读装配信息中的未匹配列表，与该装配的“允许未匹配清单”比对。整车装配中，mount 类未匹配原则上应为零。
  3. 核对名称：输出与输入的匹配名逐字一致，包括大小写、下划线和单复数（tierod 与 tie_rod 是两个名字）。
  4. 核对角色：每个子系统的次要角色与实际安装位置一致；稳定杆、车轮的次要角色与对应悬架一致；慎用 any。
  5. 物理验证：静平衡后检查各安装部件的位置和受力；对可疑部件施加一个小载荷或做一次小幅激励，“纹丝不动”的部件多半被接了地。

文本格式与单位段

Adams 系的属性文件多采用带分段标题的文本格式（常称 TeimOrbit 格式）：用方括号标记数据块，[UNITS] 段声明本文件中数值所用的单位；软件读取时按单位段把数值换算成模型单位。下面是一个结构示意（字段名与真实文件可能不同，以软件文档为准）：

$------------------------------------------------ MDI_HEADER   （示意）
[MDI_HEADER]
 FILE_TYPE    = 'spr'
 FILE_VERSION = 4.0
 FILE_FORMAT  = 'ASCII'
(COMMENTS)
{comment_string}
'前螺旋弹簧 28.4 N/mm，供应商样件实测，2026-09，v2'
$------------------------------------------------ UNITS
[UNITS]
 LENGTH = 'mm'
 FORCE  = 'newton'
 ANGLE  = 'degrees'
 MASS   = 'kg'
 TIME   = 'second'
$------------------------------------------------ SPRING_DATA
[SPRING_DATA]
 FREE_LENGTH = 352.0
$------------------------------------------------ CURVE
[CURVE]
{ disp      force }
 -100.0   -2840.0
    0.0       0.0
  100.0    2840.0

关键在于：单位段说了算。软件不会去“猜”数据是不是像毫米，它只按单位段换算。数值与单位段一旦不一致，误差往往是 1000 倍（mm 与 m）或 57.3 倍（deg 与 rad），而且不会报错。几个常用换算：

\[ k\,[\mathrm{N/m}]=1000\,k\,[\mathrm{N/mm}],\qquad c\,[\mathrm{N\cdot s/m}]=1000\,c\,[\mathrm{N\cdot s/mm}],\qquad 1\ \mathrm{N\cdot m/rad}\approx 17.45\ \mathrm{N\cdot mm/deg} \](3-4)
属性文件的单位段与数据不一致
“从别的文件复制了表头，再把供应商的数据贴进去，数值没错就行。” 复制来的单位段可能写着 meter，而贴进去的是毫米数据；减振器曲线的速度可能是 m/s，单位段却写 mm/s。正确做法：每次新建或修改属性文件，先核对 [UNITS] 段，再用一个“手算点”验证——例如刚度 28.4 N/mm 的弹簧，100 mm 处力应为 2840 N；导入后在软件里画出曲线，读一个点与手算值对比。
单位段写错时，悬架会怎样

课程示例车前轴单侧簧上载荷约为 \(F=\tfrac12 m_s g\,\tfrac{b}{L}=\tfrac12\times1420\times9.81\times\tfrac{1.6}{2.8}\approx 3980\ \mathrm{N}\)（单侧簧上质量约 406 kg）。设弹簧刚度 \(k_s=28.4\ \mathrm{N/mm}\)，杠杆比 \(i=0.9\)（第 4 章）：

\[ k_w=k_s\,i^2=28.4\times0.81\approx 23.0\ \mathrm{N/mm},\qquad \delta_{st}=\frac{F}{k_w}\approx 173\ \mathrm{mm},\qquad f=\frac{1}{2\pi}\sqrt{\frac{k_w}{m_s'}}\approx 1.20\ \mathrm{Hz} \](3-5)
  • 正确：轮心刚度 23.0 N/mm（与示例车 refCar 的 23000 N/m 一致），静挠度 173 mm，偏频 1.20 Hz。
  • 数据是毫米、单位段写成 meter：位移被放大 1000 倍理解，刚度变成 0.0284 N/mm。要托住 3980 N 需要 173 m 的变形——车身会一路下沉，直到压在缓冲块上；静平衡要么失败，要么“收敛”在缓冲块上，K&C 和操稳结果全错。
  • 数据是米、单位段写成 mm：刚度被放大 1000 倍，静挠度只有 0.17 mm，偏频变成 \(1.20\times\sqrt{1000}\approx 38\ \mathrm{Hz}\)——悬架几乎是刚性的，平顺性结果毫无意义。

两种错误都不会触发任何报错，只能靠“手算点 + 静平衡姿态 + 偏频”这类量级检查发现。

曲线的单调性、插值与外推

  • 单调性：弹簧、缓冲块、衬套的力—变形曲线应单调递增（切线刚度为正）；减振器的力—速度曲线应过原点并单调。局部负刚度会让静平衡出现多解或发散，在动态分析中产生非物理的能量。
  • 插值：曲线在数据点之间用样条（如 Akima 样条）或线性插值。数据点稀疏时，样条在拐点附近可能“过冲”，造成局部负刚度——在拐点附近加密数据点，或改用线性插值。
  • 外推：超出数据范围后，软件按某种规则外推（例如沿端部斜率延伸，或保持端部值，取决于元件类型和设置，以软件文档为准）。缓冲块曲线只给到 30 mm 压缩、而工况压到 40 mm 时，最后 10 mm 的力完全取决于外推方式。数据必须覆盖工况可能达到的范围，并留出余量。
曲线范围不够，结果落在外推区
“供应商只测到 ±0.5 m/s，减振器曲线就给到 ±0.5 m/s，过坑工况超出一点也没关系。” 过坑、路沿冲击等工况的减振器速度可以超过 1 m/s，此时阻尼力由外推规则决定，可能偏大一倍，也可能偏小一半，载荷分解与耐久结果随之失真。正确做法：查看每个力元在工况中实际达到的变形/速度范围（后处理中输出即可），与曲线范围对比；不够时补测或按物理趋势合理延伸，并在头注释中写明“外推部分为估算”。

共享引用与文件管理

一份属性文件常被多个子系统引用：同一款轮胎用于前后轴，同一个衬套用于基础版和运动版前悬（演示 D 中的 bush_lcaF.bus）。修改它，就等于修改所有引用它的子系统。推荐的管理原则：

  • 修改前先查“谁在引用它”，评估影响范围（演示 D 的“只看影响”就是这个思路）；
  • 用“另存为新版本 + 更新需要的引用”代替“原地覆盖”；
  • 文件名带关键参数和版本（如 coil_F_28N_v2.spr），头注释写清来源、日期、试验条件和单位；
  • 已发布（对标通过）的属性文件设为只读，只允许新增版本，不允许修改。
原地修改共享属性文件
“我把公共库里的轮胎文件按最新试验数据改了一下，大家用的都是最新的，挺好。” 同事上周提交的对标结果引用的是旧数据，今天重新打开装配，结果就变了，而且没人知道为什么。共享文件只能新增版本；是否切换到新版本，由各子系统的维护人决定并记录在变更记录中（3.9 节）。

3.6 主要子系统与建模要点

一个典型的前驱轿车整车模型由十个左右的子系统组成。下面按子系统给出典型部件、连接方式、与谁交换什么通讯器，以及最常见的错误。先用卡片建立整体印象，再用汇总表横向对比，最后在 3D 爆炸图中把它们“拆开”来看。具体的结构与参数分别在后续各章展开，这里只讲“建模时要注意什么”。

前悬架suspension / front

部件：下摆臂、转向节、减振器上/下体、副车架、轮毂（轮毂常放在悬架子系统中）。

连接：摆臂衬套、下球铰、减振器上支座衬套、轮毂轴承旋转副。

通讯器：输入——上支座、副车架 → 车身；横拉杆内点 → 齿条。输出——轮毂、轮心位置、前束/外倾设定、稳定杆连接点。

常见错误：次要角色设成 rear；弹簧安装长度与预载不匹配，设计姿态偏离。

后悬架suspension / rear

部件：多连杆（或扭力梁、拖曳臂）、转向节、副车架、轮毂、弹簧座。

连接：连杆两端衬套；弹簧、减振器安装点。

通讯器：输入——副车架、弹簧上座、减振器上点 → 车身。输出——轮毂、轮心、稳定杆连接点。

常见错误：扭力梁用刚体代替柔性体，侧倾刚度与侧倾转向失真（第 6 章）；后稳定杆次要角色不一致。

转向系统steering / front

部件：方向盘、转向管柱、中间轴（万向节）、小齿轮、齿条、齿条壳体，以及 EPS 助力。

连接：管柱旋转副、万向节、齿轮齿条耦合、齿条移动副、壳体衬套。

通讯器：输入——管柱 → 车身，壳体 → 副车架。输出——齿条（供横拉杆内点），以及驾驶机器驱动方向盘所需的对象。

常见错误：壳体安装未匹配而接地，转向系统柔度被低估；方向盘转角正负号与试验台约定相反（第 8 章）。

稳定杆antirollbar / front、rear

部件：左右两段半杆（中间用扭转约束或扭簧连接）、连接杆。

连接：杆身衬套；连接杆两端球铰。

通讯器：输入——连接杆下端 → 悬架（减振器或摆臂），杆身衬套 → 副车架或车身。

常见错误：次要角色与对应悬架不一致，连接杆接地，稳定杆变成“对地扭簧”；扭转刚度单位用错（N·m/rad 与 N·mm/deg 差约 17.45 倍）。

车身body / any

部件：车身（刚体，或用模态柔性体描述车身弹性），可选的乘员、配载质量点。

连接：自身不含连接，其他子系统的安装部件都连到它上面。

通讯器：输出——大量车身安装部件（悬架上支座、副车架、管柱、动力总成悬置）及测量标记点。

常见错误：车身质量已含动力总成或乘员，又在其他子系统重复计入；柔性车身的接口点与硬点不一致。

动力总成与悬置powertrain / front、any

部件：动力总成质量体（发动机 + 变速器，含转动惯量）、发动机转矩特性。

连接：3～4 个悬置衬套（或液压悬置）、扭力杆。

通讯器：输入——悬置 → 车身/副车架。输出——驱动转矩、发动机转速等信号（给传动系）。

常见错误：悬置衬套坐标系方向错，刚度主轴错位；动力总成惯量用默认值。

传动系driveline

部件：半轴、传动轴、差速器（常用简化的转矩分配）。

连接：等速万向节（常用恒速副或“球铰 + 约束”近似）。

通讯器：输入——差速器 ← 动力总成，半轴外端 → 轮毂。

常见错误：部分模板把传动系并入动力总成，再加一个传动系子系统就重复了；遗漏半轴、车轮转动惯量对加速工况的影响。

制动系统brake_system / any

部件：以力元（制动力矩）为主，少量无质量部件；制动盘、卡钳的质量一般计入轮毂或转向节。

通讯器：输入——各轮轮毂与转向节（制动力矩及其反作用）、制动踏板信号。

常见错误：制动盘质量在制动子系统与轮毂中重复计入；前后制动力分配与实车不符。

车轮与轮胎wheel / front、rear

部件：车轮（轮辋 + 轮胎的质量与转动惯量），轮胎力元引用 .tir。

通讯器：输入——轮毂安装、轮心位置、前束/外倾设定。输出——车轮部件、轮速等。

常见错误：前后轮引用了不同版本的 .tir；车轮质量在轮毂部件里又计一次；轮胎半径与悬架设计时假设的半径不一致，设计姿态偏移（第 7 章）。

空气动力（可选）并入车身或单独子系统

内容：风阻、升力和俯仰力矩，作用在车身的参考标记点上。示例车 \(C_dA=0.68\ \mathrm{m^2}\)，120 km/h 时风阻 \(F_d=\tfrac12\rho C_dA\,u^2\approx 453\ \mathrm{N}\)。

常见错误：系数的参考面积、参考点定义与风洞报告不一致；高速工况漏加升力，轴荷与高速操稳失真。

车身质量重复计入或遗漏
“车身质量直接填整备质量减去四个车轮就行。” 整车质量 = 所有子系统中所有部件质量之和。如果车身质量取自“整备质量减车轮”，它已经包含了动力总成、悬架簧上部件和燃油，再加上这些子系统自己的部件质量，就会重复计入；反过来，如果车身只填了白车身质量，内饰、电器、乘员又会被遗漏。必须先定义车身质量的“口径”（含什么、不含什么），再由各子系统补齐其余部分，最后用总质量、轴荷和质心高与称重数据对账（3.8 节演示 E 可直观看到重复计入的后果）。

3.7 硬点与参数化设计

硬点是模板参数化的“总开关”：悬架的运动学特性几乎完全由硬点决定，硬点表也是悬架工程师与 CAD、试验、供应商之间交换得最频繁的数据。本节讨论硬点表怎么写、坐标系怎么对、改硬点时哪些东西会跟着变而哪些不会，以及从 CAD 取硬点时最容易犯的错。

坐标系：ISO 与 Adams/Car 全局

设 Adams/Car 模型全局原点在 ISO 坐标中的位置为 \((x_0,\,0,\,z_0)\)，则同一点的两种坐标满足：

\[ \begin{bmatrix}x_A\\ y_A\\ z_A\end{bmatrix}=\begin{bmatrix}-1&0&0\\ 0&-1&0\\ 0&0&1\end{bmatrix}\begin{bmatrix}x-x_0\\ y\\ z-z_0\end{bmatrix} \](3-6)

这个矩阵的行列式为 \(+1\)，是一个真正的旋转（绕 Z 轴 180°），连杆长度、角度大小都不变，只是正负号和原点变了。与之对照，左右对称是关于车辆中面的镜像，行列式为 \(-1\)：

\[ \mathbf{r}_{\text{右}}=\mathrm{diag}(1,\,-1,\,1)\,\mathbf{r}_{\text{左}} \](3-7)

原点的取法各企业并不统一：前轴中心、车头前方某参考点、地面或轮心高度都有人用（以企业建模规范为准），所以硬点表的表头必须写清“哪个坐标系、原点在哪、单位是什么”。

硬点坐标系的原点、方向、单位没对齐
“CAD 里量出来的坐标直接填进子系统就行。” CAD 整车坐标常与 ISO 或企业约定一致（X 前或 X 后因企业而异），而 Adams/Car 模型全局常为 X 向后、Y 向右、Z 向上，左侧硬点的 y 为负；原点可能不同，单位可能是 mm 也可能是 m。正确做法：先写出两套坐标之间的变换（式 3-6），用两三个“标志点”（如左前轮心、主销上下点）验证，再整表转换；转换后用连杆长度、主销内倾角做不变量校核。
把一个硬点从 CAD 搬进模型

CAD 给出（ISO，原点为前轴中心地面点，mm）：hpl_lca_front = (200, 380, 200)，hpl_lca_outer = (0, 730, 160)。企业的 Adams/Car 模型约定：X 向后、Y 向右、Z 向上，原点在前轴前方 1000 mm 的地面上，即 \(x_0=1000,\ z_0=0\)。按式 (3-6)：

  • hpl_lca_front：\(x_A=-(200-1000)=800\)，\(y_A=-380\)，\(z_A=200\)，即 (800, −380, 200)；
  • hpl_lca_outer：(1000, −730, 160)；
  • 校核：两点距离 \(\sqrt{200^2+350^2+40^2}\approx 405.1\ \mathrm{mm}\)，变换前后一致；左侧 y 为负；前轴前方的点 \(x_A<1000\)。

三种典型错误及后果：① X 忘了反号（整表一致地错）——悬架前后颠倒，后倾角由 +2.4° 变成 −2.4°，转向节臂从轴后跑到轴前，转向几何全部反了；② Y 忘了反号——左侧数据落到右侧，模型变成左右互换的镜像车，“左轮”结果实际是右轮，与试验对比时左右对调；③ 单位用了 m 而模型是 mm——硬点挤在原点附近 1/1000 的范围内，模型看起来“消失”了，这类错误反而最容易被发现。

参数化依赖：什么会跟着变，什么不会

改一个硬点后，会自动更新的

以它为端点的几何（连杆圆柱、摆臂外形）；以它定位、定向的构造框（式 3-1）；挂在这些构造框上的运动副、衬套、弹簧和减振器安装点；按相对位置定义的部件质心（式 3-2）；以及由此产生的全部运动学特性。

不会自动更新的

按绝对坐标输入的质心和惯量；属性文件中的数据（弹簧自由长度、缓冲块间隙）——硬点一动，安装长度和预载就变了；其他子系统中的对应点（例如稳定杆子系统里的连接杆位置）；以及任何手工记在表格里的“设计值”。

改了弹簧硬点，忘了安装长度和预载
“只是把弹簧下座往外挪了 10 mm，运动学变化很小，不用管别的。” 弹簧上下座硬点决定安装长度，安装长度与自由长度之差决定预载。挪了硬点，预载随之改变，静平衡后的车身高度就偏离设计姿态，而所有 K&C 特性都是在“错误的工作点”上评估的。改硬点后要重新核对设计载荷下的弹簧预载与车身高度（第 10 章）。
硬点参数化模板：双横臂前悬选择硬点、编辑坐标 · 拖动旋转 · 点击后滚轮缩放
硬点编辑
观察要点：① 选 hpl_tierod_inner，把 z 从 280 拖到 250 或 310：横拉杆、转向节、车轮自动重新“装配”，下方曲线里前束随轮跳的斜率（轮跳转向，bump steer）明显变化——这就是参数化：只改一个数，整套几何和运动学都跟着变（几何原理见 第 4 章）。② 取消“左右对称”后再改同一个硬点：只有左侧变化，左右前束曲线分开，“左右最大差异”变红——直线行驶遇到路面起伏时，左右轮转向不同会让车跑偏。③ 切换“柔性模式”：摆臂内侧、减振器两端由蓝色运动副变成橙色衬套；运动学模式下柔度读数恒为 0。④ 读数里的 Adams/Car 坐标：同一个左侧硬点，x 和 y 都变了号。
关闭左右对称后只改了一侧
“为了试一下效果，先关掉对称改左侧，回头再改右侧。”——结果“回头”被忘了。 关闭对称以后，左右两侧就是两套独立数据，之后的每次修改都只作用于选中的那一侧。左右不对称的硬点会造成左右轮跳转向、侧倾转向不同，直线行驶跑偏，左右 K&C 结果不一致。正确做法：非对称修改只用于确实不对称的结构，并在变更记录中写明；每次发布前做一次“左右差异检查”（对称件左右硬点之差应为 0）。

从 CAD 取硬点的注意事项

  1. 确认坐标系：CAD 整车坐标的原点、轴向（X 向前还是向后、Y 向左还是向右）和单位，写出与模型全局坐标的变换（式 3-6），用标志点验证。
  2. 确认设计状态：硬点对应哪个载荷状态（整备、设计载荷、满载）和车身姿态。模型的“设计位置”必须与之一致，否则静平衡后的姿态与 CAD 不符（第 10 章）。
  3. 确认点的物理意义：衬套取弹性中心（不一定是螺栓孔中心），球铰取球心，减振器取上下铰点，弹簧取作用线与上下座的交点。
  4. 处理左右与对称：CAD 常只给一侧或给全车；对称件用左侧数据 + 对称开关，非对称件（转向机、副车架偏置安装点等）单独处理。
  5. 精度与校核：保留到 0.1 mm；用连杆长度、主销内倾角、轮距与轴距做交叉校核；与上一版硬点表逐项做差异对比，差异要能解释。

设计变量与 DOE

把关键硬点（或硬点偏移量）定义为设计变量，就可以做灵敏度分析和试验设计（DOE）：例如横拉杆内点 z 在 ±10 mm 内变化对轮跳转向的影响，上摆臂内点高度对外倾增益的影响。分层架构的好处在这里体现得很充分：变体只改子系统数据而不动模板，可以批量生成；同一个子系统变体同时用于 K&C 装配和整车装配，“部件指标—系统指标—整车指标”的链条不会断。DOE 的方法与目标分解见 第 15 章，五连杆硬点灵敏度见 第 5 章。

硬点变量的取值范围要“装得上”

硬点变化太大时，机构可能在轮跳范围内出现死点、无解，或连杆与车身干涉。设定 DOE 范围前，先在运动学模式下把极端组合跑一遍全行程（演示 C 中把硬点拖到很远时，读数会提示“部分行程无解”）；再把通过的范围交给柔性模式和整车分析。

3.8 装配与试验台

子系统准备好以后，装配把它们和一个试验台放到一起。试验台决定“怎么约束、怎么激励、测什么”；装配检查决定“这个模型能不能用”。一个没有经过检查的装配，求解成功只说明方程有解，不说明模型正确。

悬架试验台

悬架试验台（suspension test rig）把车身侧的安装部件固定（接地），在轮胎接地点或轮心处施加垂向位移（同向轮跳、反向轮跳），施加转向输入，以及侧向力、纵向力、回正力矩，测量前束、外倾、轮心位移、侧倾中心、柔度等 K&C 指标。悬架装配 = 一个悬架子系统（需要转向工况时再加转向子系统）+ 悬架试验台。工况定义与指标提取见 第 9 章。

整车试验台

整车试验台（full-vehicle test rig）不固定车身，而是提供驾驶机器（控制方向盘、油门、制动、挡位）、路面、初始条件和事件序列。整车装配 = 全部整车子系统 + 整车试验台。驾驶员模型、事件设置与求解流程见 第 14 章，操稳工况见 第 12 章。

自由度检查

装配后检查模型自由度，是发现“多了约束”（如部件被接地）或“少了约束”（如漏了一个运动副）的快速方法。空间机构的自由度可按 Grübler–Kutzbach 公式估算（第 1 章）：

\[ F=6\,n-\sum_j c_j \](3-10)
  • \(n\)：运动部件数（不含地面）；\(c_j\)：第 \(j\) 个运动副去掉的自由度数（旋转副 5、球铰 3、万向节 4、圆柱副 4、移动副 5、固定副 6）。衬套不去除自由度。
数一数双横臂悬架角的自由度

运动学模式、齿条固定（悬架装配中没有转向子系统时，横拉杆内点的安装部件接地）。运动部件：下摆臂、上摆臂、转向节、横拉杆、轮毂，\(n=5\)；运动副：两个摆臂内侧旋转副 \(2\times5\)，上下球铰 \(2\times3\)，横拉杆两端球铰 \(2\times3\)，轮毂旋转副 5，合计 \(\sum c_j=27\)：

\[ F=6\times5-27=3 \]

这 3 个自由度是：轮跳 1 个、车轮自转 1 个，以及横拉杆绕自身轴线的“空转”1 个。最后一个是局部自由度，不影响运动学，但在动力学中是一个没有刚度的模态；模板中常把横拉杆一端改为万向节（去掉 4 个），使 \(F=2\)。如果你数出来的结果比软件统计的多或少，就说明某处连接与预想不同——例如某个部件被意外接地，会让自由度凭空少 6 个。

静平衡收敛不等于模型正确
“静平衡一次就收敛了，模型状态很好。” 被意外接地的部件、过硬的单位错误、重复的约束，反而会让静平衡“更容易”收敛。静平衡之后要核对的是结果是否合理：车身高度与设计值、各弹簧力与预期载荷、各轮垂向力之和等于整车重力、左右对称车的左右轮荷相等。

3.9 模型数据管理与协作

当一个整车模型由五六个人共同维护、被几十次评审引用时，“模型怎么管”比“模型怎么建”更决定结果的可信度。分层架构把数据拆散了，管理就必须跟上。本节给出企业中常见的一套做法（示意，具体以所在单位的规范为准）。

版本管理

  • 整个数据库纳入版本管理（Git、SVN 或 PDM 系统）。子系统、装配、属性文件多为文本格式，适合逐行比较差异；模板若以二进制形式保存，则只能做整体版本记录。
  • 打标签：每次对标、评审、发布时打一个标签，记录“装配 + 全部被引用文件 + 求解器版本 + 求解设置”。结果报告中引用这个标签，而不是“最新模型”。
  • 只读与评审：共享模板和已发布数据只读；修改走“副本或分支 → 评审 → 合并或发布”的流程。
  • 结果可再生：体积很大的结果文件可以不入库，但必须能由入库的模型和设置重新生成。

数据库被他人修改，结果无法复现
“结果文件留着就行，需要时把装配再打开重算一遍。” 装配只保存引用。数据库中的模板、子系统、属性文件一旦被他人修改——甚至只是别名指向了另一个同名数据库——同一个装配再次打开就已经是另一个模型。凡是对外发布的结果，都要冻结数据快照：打包装配及全部被引用文件（演示 D 中“只看依赖”高亮的那一组），记录版本标签、求解器版本和求解设置，并把快照与结果一起归档。
“在我电脑上能打开”不代表引用都对
“我这里打开没问题，说明文件引用都是对的。” 数据库别名到真实目录的映射是本机配置。换一个人、换一台机器，同一个别名可能指向另一个同名数据库，打开的是另一套数据。发布前在“干净环境”中打开一次，并让软件或脚本列出全部被引用文件的实际路径，与快照清单核对。
多人协作的几条经验
  • 一人一子系统：每个子系统有明确的负责人，别人修改要经过他；模板由专人维护。
  • 先改副本、后合并：在个人库中验证改动，评审通过后再进入项目库。
  • 结果首页写清模型标签、成熟度等级和关键假设（例如“后悬衬套为估算值”）。
  • 定期做一次“全模型体检”：通讯器未匹配清单、质量对账、左右对称检查、单位段抽查，结果写入模型说明书。

本章避坑清单

  1. 改模板 = 改所有引用者：修改共享模板前先查引用范围；改拓扑时复制成新名字、新版本的模板。
  2. mount 未匹配会接地：装配“成功”不代表连接正确；逐条确认未匹配列表，整车装配中 mount 未匹配应为 0。
  3. 次要角色必须与安装位置一致：前悬设成 rear 会让横拉杆、前车轮、前稳定杆的连接全部错位或接地。
  4. any 不是万能钥匙：any 容易造成多重匹配，只用于确实不分前后的子系统（车身、制动）。
  5. 运动学模式下柔度为 0：K&C 柔度工况和整车分析必须在柔性模式下进行，报告中写明分析模式。
  6. 模板默认质量必须核对：逐个部件与 BOM 或称重数据对比，修改后确认已保存进子系统文件。
  7. 车身质量口径要清楚：明确车身是否含动力总成、乘员、燃油，杜绝重复计入或遗漏；用总质量、轴荷、质心高对账。
  8. 属性文件单位段说了算：mm 与 m、N/mm 与 N/m、deg 与 rad 的错误不会报错，用“手算点”和偏频做量级检查。
  9. 曲线要单调、范围要够：避免负刚度、样条过冲和外推区工作；工况前查看各力元实际达到的范围。
  10. 硬点坐标系写清楚：Adams/Car 全局常为 X 向后、Y 向右、Z 向上，左侧 y 为负；原点与单位写在硬点表表头，转换后做不变量校核。
  11. 左右对称开关要管住：关闭对称只改一侧会造成左右不一致；发布前做左右差异检查。
  12. 改硬点后核对预载与姿态：弹簧硬点改变会改变安装长度和预载，设计姿态随之偏离。
  13. 试验台要选对：K&C 用悬架试验台，操稳、平顺用整车试验台；能装配不等于能分析。
  14. 子系统重名、数据库被改：命名带车型、方案、版本；对外发布的结果必须冻结数据快照并记录版本标签。

本章小结与延伸阅读

  • 整车模型按“模板—子系统—装配”分层：模板管拓扑与参数化，子系统管本车数据，装配管“用哪些子系统 + 哪个试验台”；属性文件管元件特性，数据库管文件存放与引用。
  • 模板内部的依赖链是 硬点 → 构造框 → 部件与几何 → 连接与力元 → 通讯器；改硬点会自动更新几何与连接，但不会更新绝对坐标的质心、属性文件中的数据和其他子系统中的点。
  • 通讯器按“匹配名 + 类型 + 次要角色”配对；未匹配的 mount 把部件接到 ground，而且通常不报错——在悬架装配里这是特性，在整车装配里就是事故。
  • 属性文件的单位段决定数值含义；曲线要单调、范围要覆盖工况；共享文件只新增版本、不原地修改。
  • 硬点表必须写清坐标系、原点和单位；ISO 与 Adams/Car 全局相差绕 Z 轴 180°，左右对称则是镜像。
  • 装配验收看通讯器、质量与质心、自由度、静平衡姿态；结果的可信度取决于版本快照、变更记录和模型成熟度。
